## ブランチとやり取り
- `boki2-quest` から **`jules/ramen-y2-scenes`** を切って作業する。`boki2-quest` へは PR で出す。直接 push しない。
- PR は早めに **ドラフト** で開き、段ごとにコミットを足していく。
- 相談・質問・検査の結果は **PR のコメント** に書く。取りまとめ役（Claude）が PR を見張っていて、PR のコメントで答える。

- 取り込み（マージ）は取りまとめ役が検査を走らせ直し、オーナーが確認してから行う。自分でマージしない。

## 受け入れの基準（確かめられる形）
1. **面白さ**：2年目の札は、どれも「どちらを選んでも損得がある」形にする。札ごとに、`SIM.decide.trial`（または同じ考えの試算）で選択肢の結果を出し、次の2つを PR の本文に表で出す。
   - ほかの選択肢より、どの面でも劣らない選択肢（支配された選択肢）がないこと。
   - 学ぶ論点が、「読むだけ」でなく、遊ぶ人の判断の結果として出てくること。たとえば、増資の株数と価格を自分で選ぶから、資本金と資本準備金の計算が要る。
   - 表には、どういう遊び方が増えそうか（よい面）と、どこが退屈・作業になりそうか（悪い面）の両方を書く（QUALITY 7.1）。
2. `node boki2/tools/coverage.js --ramen --stage 2` が exit 0（累計 38/77）。
3. `node boki2/tools/coverage.js --ramen --stage 1` も exit 0 のまま。
4. AGENTS.md の6つの検査が全部通る。
5. **1年目の数が変わらない**：作業前と作業後で `node boki2/tools/sim-check.js --ramen --runs 300 --info` の1年目の行（倒産・詰み・札・値段の手・店の形の1年目）が同じ数。違ったら原因を書く。
6. 仕訳の正しさ：
   - 書類ごとに、同じ論点の過去問の形（`js/data/exam*.js` の該当する問）と勘定科目・金額の決め方が一致することを、PR の本文に「書類 → 対応する問の id」の表で示す。
   - 2026年度・2027年度で扱いが変わるもの（`s-taiwitsu` は2027年度で3級の範囲へ）は、年度表（`B.kubun.yearly`）に従う。
7. 法令の数字（税率・上限・条番号）を画面の文に出すなら `node boki2/tools/law-check.js` が通ること。通らない数字は出さない（m.1）。
8. `node boki2/tools/ramen-y2-check.js` が exit 0。
