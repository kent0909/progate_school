### 1.2 採る規則（回す前に決める。結果を見て変えない）
1. 仕組みの主の案（K1）は **R1** を使う。理由（正しさ）：K1 の式の3つの項（昼だけ・平日だけ・夜の客がいない）は「住む人がほとんどいず、働く人が昼にいる」に立つ（day と夜間人口の項）。R1 はその量（day）で直接分け、もう1つの条件（従業者1万未満）は都心の事務所街を外す（オフィス街の foot に働き手がすでに入っているので、働き手の項を足すと二重に数える）。
2. R4・R3・R2 は K1 の**変種として同じ組で回し、報告だけ**。規則の選び直しは結果では行わない。変種で合否が変わったら「型の分け方しだい」と書き、司令塔に出す。
3. facts で、各規則の線を ±10% 動かしたときに入れ替わる候補地を出す（頑健さの報告。選び直しには使わない）。

## 3. 物差し（線）。回す前に決める
### 3.1 工場の検査（合否）
| 記号 | 線 | 理由 |
|---|---|---|
| ⑪k 罠でない | 工場の25か所のうち全候補地の利益の上位30%（294か所、通しの利益）に入る数が **3以上**（⑪の「10%以上かつ2か所以上」を25か所に当てた形。そのまま使う） | 面白さ：工場という属性にも選ぶ価値のある所が残る。設計書 6.1 の⑪の定義を変えない |
| H1 穴場でない | 同じ数が **12以下**（25か所の半分以下） | 面白さ：「どこでも勝てるわけではない」＝工場の候補地の半分以上は上位30%の外 |
| H2 単純な規則で勝てない | ⑥ の形で「工場だけ（人通りの倍率の大きい順）」「工場の湾岸・物流の型（R1）だけ（人通り順）」「工場の湾岸・物流の型だけ・昼だけ営業」の3本が、どれも本当の上位10の **85%未満**（⑥ の線） | 面白さ：工場を選ぶ1本の規則で上手な選び方に届かない |
| H3 選ぶだけでは平均の上にならない | 工場の候補地の利益の中央値 ≦ 全候補地の利益の中央値 | 学習効果：工場を選ぶだけでは勝てず、どの工場かを読む判断が要る |
- 型ごと（R1 の湾岸・物流の型7・住工混在の型17・事務所街1）の上位30%の数と利益の中央は**報告だけ**。⑪を型ごとに見る形（型ごとに10%以上かつ2か所以上）は、型を地図に別の属性として出すかの決定（司令塔）に付く物差しなので、報告の列に出し、合否に使わない。
- 報告だけ：⑪k を「営業時間も選ぶ利益（通し・昼だけ・夜だけの最大）」で数えた数。

### 3.2 ほかの検査が壊れていないか
同じ段の比・同じ seed の基準 K0 で通っている検査が、仕組みを足した組で外れたら「壊れた」。見る検査：③・④・⑤（主：世界ごとの数の中央値≦15。報告：最大）・⑥（元の規則の全部）・⑦（オフィス街で昼だけ＞通し 20%以上だけ。オーナーの決定 (c)）・⑧・⑨・⑪（工場を除いた5属性）・⑫a・⑫b・⑬。①・⑭は報告だけ（オーナーの決定 (a)）。基準 K0 で外れている検査は「元から外れ」と書く。
