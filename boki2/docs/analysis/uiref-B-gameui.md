## 0. 要点

1. **見た49の文書・78枚の画像（作品ページ20・作り手の話14本・口コミ254件）から言える芯は、「画面の主役を文字のカードから"世界（店・町・人）"に替え、文字と数は世界の縁に小さく据え置く」こと**。調べた作品のうち、判断や結果の画面で文字のボタンだけを縦に並べるものはほとんどなかった。Coffee Inc 2 は判断の窓の後ろに店の断面か本社のオフィスを常に見せ（E02・E03・E06）、ウマ娘は人物の上に目標と残りの札を固定し（E26）、Stardew は日付とお金を作品の絵と同じ木の枠の小箱に入れて右上へ追い出す（E35）。我々の画面（w26〜w60）は逆で、上部の5段の帯が高さの約4分の1を取り、残りは白いカードの文字だけだった（1章）。
2. **動き（P1・P6）は「量」ではなく「どこで・どれだけ短く・飛ばせるか」で評価が分かれる**。口コミ254件のうち、動き・演出を褒める・求める声は17件、長い・待たされる声は8件（`uiref-B-voices.py`）。褒め言葉の中身は「ヌルヌル動く」「振動が気持ちいい」「1つ1つの動きが凝っていて短い」で、嫌われているのは「毎回の決まった画面での止まる演出」（Pokémon Sleep のランクアップ、Coffee Inc 2 の週の売上の溜める演出）。演出の多い作品ほど、飛ばす・短縮版の切り替えを画面の下に常に置いている（ウマ娘の SKIP OFF・短縮版、E26）。**オーナーの「動きを増やすべき」は、手ごたえの動き（押す・置く・合う）と節目の演出には支持され、繰り返す画面の待たせる演出には反対の事実がある**。
3. **チープさ（P7）を直した作品は、絵を描き込んだのではなく、まず"1つの決まり"を強く押していた**。ペルソナ5 は予算の危機の中で、裏方の UI を作品の主人公に変え、メインカラーを赤1色に絞った [[web:uiref:uB-fami-p5-ui|「主張の強い主人公」]]。Duolingo は描ける人が少ないので、少ない形・丸・白い余白の作風を決めた [[web:uiref:uB-duolingo-shape|「QUICK TO PRODUCE」]]。Balatro は渦の背景と揺れる札とブラウン管の効果を1つにまとめた [[web:uiref:uB-gi-balatro|「CRT filter」]]。我々には既に統一の色（橙・生成り・薄緑）と丸い字があるので、足りないのは「世界の絵」と「1つの強い決まり」（店の素材＝木・湯気・のれん、など）。
4. **何を聞かれているか（P2）と、どこに反映されたか（P3）は、学びのアプリより経営・パズルのゲームの方が手本になる**。Balatro は点を「青の数×赤の数」として左の帯に見せ、札ごとに足される数を札の上に浮かせる（E33）。DragonBox は等式の左右を2つの区画にし、記号の代わりに絵の札を置く（E41）。Brilliant は式を面積の箱にし、間違えたら答えを言わずに図に補助線を1本足す（E40）。Balatro の作者は説明を4行・20語までと自分に課した [[web:uiref:uB-gi-balatro|「four lines and 20 words」]]。
5. **Coffee Inc 2（P9）から抜き出すエッセンスは4つ**：①都市の地図の上に自他の店と空き物件を色と形の違うピンで刺す（E01）②ライバルを「市場シェアのドーナツ＋各社の色とロゴと店舗数」の1枚で見せる（E05）③財務を「大きな2つの数（売上・純利益）＋四半期の棒＋損益・貸借・CF のタブ」で見せる（E04）④どの画面にも担当者の顔と1行の挨拶を上に置く（E02・E06）。**反対の事実**：同じ作品の口コミに、株の売買の UI が悪い、週の売上の数字が出るのが遅い、後半は煩雑、とある（[[web:uiref:uB-applion-coffeeinc2|「週の売上の数字の表示が遅い」]]、[[web:uiref:uB-applion-coffeeinc2|「後半は少し煩雑に感じることがある」]]）。画面の構成をそのまま写すのではなく、4つのエッセンスを我々の店（1軒→町→2号店）の段に合わせて入れる。
6. **会話（紙芝居）は、"紙芝居をやめる"より"1文に1回だけ人が動く"で直る**。ウマ娘は育成中の縦画面の会話を、テンポのため表情と動きの変化を1文に1回までに制限し、話していない人物も反応させる [[web:uiref:uB-gw-umamusume-talk|「1テキストに1回」]]。ブルーアーカイブは紙芝居の形式でも評価されている [[web:uiref:uB-applion-bluearchive-rev|「紙芝居形式でボイス無いこと多い」]]。Florence は会話をジグソーのかけらにし、仲が深まるほどピースが減る [[web:uiref:uB-gw-florence-gdc|「最後は1ピースのパズル」]]。
7. **やっていないことの大きなもの**：Game UI Database・Interface In Game・Mobbin・Dribbble・Behance は規約・robots で取れず、作品の公式の紹介画像（APPLION が載せる App Store の画面写真）と作り手の記事で埋めた。掲載の画面写真は宣伝用に選ばれたもので、結果・月報・順位の実際の画面が載っていない作品がある（逆転裁判・Stardew・Papers, Please の1日の終わり）。口コミは APPLION の1ページ目（ほぼ★5の選ばれた声）だけ。Figma は使っていない（担当A・C と取りまとめ役の範囲として残した）。

## 1. いまの画面（自分で見たこと。取りまとめ役の見立てへの足しと反論）

**取りまとめ役の見立てに足すこと**

**反論・別の見方**
- **見た目の決まりは既にそろっている**：生成りの点の背景・白い角丸のカード・薄緑の縁・橙の主ボタン（下に濃い影）・丸いゴシック、が全画面で揃っている。問題は「ばらばら」ではなく、「世界の絵がない」と「強弱がない」の2つ【推論】。だから大胆な写し方は、色を替えるより、カードの後ろに店と町を置くこと（2章の多くの行）。

- **フォームに見える理由は、カードの形より「縦1列に同じ幅のボタン」**：w39・w40・w52・w54 は、どれも同じ幅の白い枠のボタンが縦に並ぶ。ゲームの判断の画面で、同じ幅のボタンを縦に並べるだけのものは、見た範囲ではブルーアーカイブの会話の選択肢（E29）くらいで、それも場面の絵の上に重ねていた。

- **動きの向き**：褒める・求める 17件、長い・待たされる 8件、両方を書いた件は0。待たされる声8件のうち5件が Pokémon Sleep（毎日決まった時に開く作品）。【推論】待たされる不満は作品の性格（毎日・繰り返し）に偏っていて、我々の月の締め・月報（毎月必ず通る画面）はこの性格に当たる。
- **飛ばせる・待たない・テンポを褒める声 9件**（S+ 5・T+ 4）。演出の多いウマ娘で3件。演出を増やすなら、飛ばす・短くの設定とセット。
- **分かりにくい（C- 12件）の中身**は「表示の意味が分からない」（Duolingo の到達度、ウマ娘の既読選択肢の効果、Pokémon Sleep の睡眠時間の見込み、ねこレストランの大きな数）が多く、「何を聞かれているか」に当たる声は Balatro・学マス・Cultist の「最初のルールが分からない」の4件。
- **偏り**：載っている口コミのほとんどが★5（APPLION の1ページ目は選ばれた声）。不満は★5の中の「ここが惜しい」として出ている。★1〜3 の声の割合は数えていない（やっていないこと）。

## うまくいく理由（因果の鎖）

1. **世界が主役で、数は縁に固定**：店・町・人の絵を画面の大半にする（E01・E02・E25・E35）→ 数と文字を隅の小さな札に据え置く（E26・E35）→ 遊ぶ人は「店を見ている」と感じ、数は見たい時だけ見る → 業務アプリに見えない（P7・P8）。
2. **結果は世界の変化で返る**：判断や記帳の結果が、絵の変化（城が直る E14、客が来る E16、店が満席になる E31）として返る → 数の表を読まなくても良し悪しが分かる → 遊んだ意味が目に残る（P1・P3）。
3. **足し算の途中が見える**：札ごとに足される数が札の上に浮いてから合計に入る（E33）、置いた物が置き場所を埋める（E25）、使った札の跡が残る（E37）→ どこに反映されたかを目で追える → 間違えた札も見つけられる（P3・P4）。
4. **1つの強い決まり**：メインカラー1色（E45）、少ない形と余白（E39）、素材の枠（E35）、手描きの少色（E31）→ 全画面が同じ作品に見える → 絵の量が少なくてもチープに見えない（P7、Behance の行「複数画面の一貫性」）。
5. **手ごたえの動きは短く、大きな時だけ大きく**：普段は静かで短く（Balatro の声「凝っていて短い」）、大きな成果の時だけ光る（E12・E33）→ 光ったことに意味がある → もう1回やりたい（P6）。
6. **人がいる**：担当者の顔と1行（E06）、1文に1回の表情（E27）、聞き手の反応、ライバルの色と顔（E05）→ 画面を開くのが人に会うことになる → 愛着（P1・P9）。
7. **問いは短く、間違いには図で返す**：1行の問い（E37）、4行20語（E34）、補助線1本（E40）→ 読む量が少ない → 何を聞かれているかが分かり、自分で直せる（P2）。

## うまくいかない理由（因果の鎖）

1. **毎回の画面で止まる演出**：決まった画面（朝の結果・週の売上・ランクアップ）で、操作できない演出が毎回入る → 繰り返すほど待ち時間が積もる → ストレスになり、飛ばす方法を探される（反2・反4・反5・反16）。
2. **画面を増やすと操作が崩れる**：事業が広がり画面が増える（株・多都市）→ その画面の UI が作り込まれていない → 後半が煩雑と言われる（反22・反23）。Coffee Inc 2 の不満の芯。
3. **ボタンと情報を詰める**：ホーム画面にボタンが多い → 何が大事か分からない（反20）→ 最も大事な操作（眠る）さえ小さくなる。
4. **教えない・戻れない**：説明がない・失敗すると戻れない（E24）→ 好む人は「手探りの醍醐味」と言う（反8）が、初めての人は困惑する → 対象を選ぶ。
5. **小さな画面で細かく置かせる**：細かい物をドラッグで置く（E25 のスマホ版）→ 指で隠れ、狙いがずれる → タッチペンを勧められる（反10）。色が似た札は捨て間違える（反12）。

## 反証と限界

- **結果・順位・月報の実際の画面を見られなかった作品がある**：逆転裁判（法廷）・Stardew（出荷の集計）・Papers, Please（家計の画面）・ブルーアーカイブ（宣伝の縮小のみ）。結果の画面の根拠は Coffee Inc 2・Pokémon Sleep・学マス・作り手の記事に寄っている。
- **画面写真は宣伝用**：App Store の画面写真は作り手が選んだ最もよい画面で、文字の宣伝帯が付く。実際に遊ぶときの詰まり・待ちは写らない。待ちの不満は声で補ったが、画面では確かめていない。
- **声は★5の1ページ目**：不満の数（W 8件など）は少なめに出ている。不満の割合を作品同士で比べることはしない。
- **動きの評価は文字の声だけ**：実際に動きを見ていない（動画は取っていない）。「ヌルヌル」「まどろっこしい」の長さの数値は分からない。動きの長さは `DESIGN-JOURNAL-UX.md` 5.1 の置き値と担当Cの研究に任せる。
- **作品の規模の差**：ウマ娘・学マス・Coffee Inc 2 の立体の街は、絵と動きの量が我々の何十倍もある【見立て】。エッセンスは量に依らない形で抜き出したが、「店の断面を常設の背景にする」は絵の作り手がいないと作れない（簡略化の台帳 #1）。
- **反対の向きの資料**：Papers, Please の作者は家族の画面をあえて簡素にした（E10）。Florence は評価が高いのに売れ行きは「まあまあ」（反19）。Cultist は教えないことを魅力にしている（E24）。動きや絵を足すほどよい、とは言えない。
- **規約で取れなかった所**：Game UI Database・Interface In Game・Mobbin・Dribbble・Behance・Refero・Figma のサイト、Steam・Reddit。代わりに APPLION の作品ページ（App Store の画像）と作り手の記事で埋めた。
