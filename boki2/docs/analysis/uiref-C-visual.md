# UI・UX の参考の調べ 担当 C：見た目の規則と動き（uiref-C-visual）

2026-10-30、担当 C が書いた。依頼文は `docs/BRIEF-UIREF.md`（9章の担当 C）。決まりは `docs/QUALITY.md` の全章。数は `node boki2/docs/analysis/uiref-C-count.js` で数えた（出力は「資料の内訳」と末尾の「数の出力」に写した）。ゲームのファイルは変えていない。

## 0. 要点（取りまとめ役・オーナー向け）

1. **いまの画面の見た目の規則は「2つの色の体系と30種類以上の文字の大きさと、ほぼ動かない画面」**。style.css は緑（brand #0a8566）と借方の青・貸方の赤、ramen.css は紙の地・朱（自店）・寒色（ライバル）・紅紫（危険）を持ち、題名の画面（w1）は緑の題字と朱のボタンが混ざる。文字の大きさの値は3つの CSS で 53 種類（スクリプトの出力）。上部の帯（w25〜w60）は口座・借入金・手もとのお金・目的・年・進みの棒・タブ6つが同じ強さで並び、手もとのお金が朱（自店・ボタンと同じ色）で出る（w49）。「チープ」の原因は色や角丸の値よりも、**規則がない（どの色・大きさ・動きが何を意味するかが決まっていない）ことと、主役（店・一杯・ピヨ・お金）が絵になっていないこと**の2つだと読む【推論】。
2. **研究の結論は「動きは増やせ」でも「減らせ」でもなく「置く場所と大きさで決まる」**。派手な手ごたえは見た目の評価を上げるが成績は上げない／下げうる（[[web:uiref:uC-juul-juicy-feedback|「a lower 40,340」]]）。効くのは「操作の後」の手ごたえ（[[web:uiref:uC-arx-juicy-vis|「only post-feedback」]]）、強さを上げても効きは増えない、出来事の大事さに合わせる（[[web:uiref:uC-hicks-goodgamefeel|「Feedback Coherence」]]）。数字が変わるときの動きは読み取りを助ける（[[web:uiref:uC-heer-animated-transitions|「around 1 second」]]）が、仕組みを教える動画のような動きは静止図に勝たない（[[web:uiref:uC-tversky-animation|「too complex or too fast」]]）。
3. **見た目の規則の案を3つ出した**（8章）。案A「屋台のあたたかさ」（線なしの平らな絵・紙と木と朱・角は丸く・動きは出来事の大きさの5段）、案B「路線図の帳簿」（色は意味だけ・記号・大きな数字1つ・図が段に分かれて動く）、案C「ドットの屋台と燃える数字」（ドット絵の店・2つの箱の式が燃える）。推しは**店・町・会話は案A、帳簿・月報・町の地図の数字は案B、正解・締め・決算の瞬間だけ案Cのエッセンス（2つの箱の式と数字の強さ）**の組み合わせ。どれも合わない場面を書いた。
4. **オーナーの「選択肢・文字・背景に動き」への具体の形**：選択肢は色＋形の大きな札（Kahoot）、押した札の中だけで色が満ち「＋1万円」が出て紙吹雪は札の外に出ない（Collect UI の正解の札）、文字は見出し・名前の札・数字だけを動かし本文は止める（Muzli の文字の移り変わり、Juicy Text の研究）、背景は時刻と季節の色で変える（Alto・Stardew）。反対の事実：Pokémon Sleep の口コミの「全てのアニメーションや島移動のテンポが悪い」（[[web:uiref:uC-gp-pokemonsleep|「テンポが悪いので」]]）、関係のない飾りを図の隣に置くと学びが下がる（[[web:uiref:uC-wsu-seductive-details|「static joke」]]）。
5. **障害**：Collect UI の元の作品は X（旧 Twitter）の投稿で、X は規約で許可のない自動の収集を禁じるため開いていない（Collect UI の置き場の動画を取り、8コマに切り出して見た）。Collect UI の「順位表」の分類は0件だった。Dribbble・Behance・Refero・Mobbin・design-library は判定済みの禁止で取っていない。AP の配信記事（Robinhood の紙吹雪の廃止）は robots.txt が Anthropic を名指しするので使っていない。Figma は依頼の決まり（外部への通信は research-fetch だけ、figma.com は robots で禁止）と Figma の接続（MCP）の扱いが食い違うので、使わずに相談事項にした（やっていないこと）。

| 飾り（粒・揺れ・背景の動き） | 出来事の大事さに合う大きさで。大きな出来事だけ揺れ。ジュースには「ちょうどよさ」がある（[[web:uiref:uC-arx-gamefeel-survey|「adequacy to juice」]]） | 図の隣にずっとある飾りは学びを下げる。揺れのやりすぎ。成績は下がる向き | [[web:uiref:uC-hicks-goodgamefeel|「Feedback Coherence」]]、[[web:uiref:uC-wsu-seductive-details|「static joke」]]、[[web:uiref:uC-juul-juicy-feedback|「redundant feedback」]] |
| 文字の動き | 短い語（見出し・名前・数字・評価の言葉）。意味のある言葉は進み具合を伝える | 本文、意味のない語（少し遅くなる）。「BAD」の強い否定は有能感を下げる | [[web:uiref:uC-arx-juicy-text|「Progress feedback」]]、[[web:uiref:uC-arx-juicy-text|「Mastery construct」]] |
| 環境の動き（湯気・客・時刻） | 入力なしでも世界が生きていると知らせる | 読む画面の周辺視野で動き続ける | [[web:uiref:uC-hicks-goodgamefeel|「trees swaying」]] |
| 強さ | 中ほどが好まれる。強さを上げても効きは増えない。変えられるように | 強すぎも無しも悪い | [[web:uiref:uC-arx-juicy-or-dry|「Goldilocks effect」]] |

## 6. 数字とグラフの見せ方の規則（実例から抜き出したエッセンス）

1. **大きな数字は1つ、単位は半分、比べは小さく下に**（C16・C17・C18）。上部の帯・月報・決算・検定の結果に。
2. **色は箱の種類（資産・負債・純資産・収益・費用）に結ぶ。増減の良し悪しの信号（緑＝良・赤＝悪）にしない**（C7 の悪い面）。簿記の勘定は良し悪しでないので【推論】。BIZ-FUNVISUAL 3.0 の Tufte の「信号の三色を避ける」と同じ向き。
3. **自分だけ色、比べる相手は灰色**（C19・C24）。ライバルとの比べ・推移に。
4. **変わるときは途中も正しい図のまま約1秒で動き、目盛りは変えない。月をまたいでも同じ目盛り**（Heer）。
5. **式を見せる**：左右の合計を2つの箱で常に並べ、札ごとに増える（C22・C4）。
6. **物の絵の段で積む**（C20・C14）：費用・売上を物の絵の段で。絵は価値の伝言を運ぶので、感情は中立に（Bateman の注意）。
7. **判断のために読む画面は素、覚えてほしい結果の画面は絵入り**（Bateman と Tufte を両立させる読み【推論】）。検定会場は素のまま。

## 7. 合う・合わない（対象の遊ぶ人：中高生〜社会人、日本語、スマホ片手）

- 合う：線なしの平らな絵と丸い形（C25・C31・C34）、色＋形の大きな札（C28）、数字大・単位小（C16）、絵の上の結果（C23）、1色相の光の背景（C29）
- 一部：ドット絵（C26・C27。日本語の本文に合わない）、業務のダッシュボード（C7・C8。数字の階層は使えるが配色は業務）、英字の大きな見出しの作風（C9〜C15）
- 合わない：黒地にネオン・ガラスの冷たい作風（C4・C15）、4原色の学校の早押しの色（C28 の色そのもの）、連続記録の炎（C30）

## 8. 見た目の規則の案（3案）

どの案も「色の差し替え」だけではなく、絵の作風・画面の構成・動きの体系まで決める。値は【推論・置き値】で、資料の数ではない（資料の数は根拠の列に書いた）。

### 案A「屋台のあたたかさ」（店・町・会話・プロローグの主の規則）

| 項目 | 決まり | 参考にした実例 |
|---|---|---|
| 色の組 | 地は紙色1つ（いまの --paper を残す）、文字は濃茶（真っ黒を使わない）、白いカードは「紙の色の明るい段」に替える。主の差し色は朱1つで「押す物」だけ。自店の印は藍、ライバルは灰色の段。お金の数字は色を付けず、箱の種類の色だけ（資産＝藍・負債＝柿・純資産＝若竹・収益＝山吹・費用＝鼠） | C34（真っ白・真っ黒を避け目立たせない所は灰色）、C19（自分だけ色）、C13（差し色1つ） |
| 文字の大小の段 | 6段：12（注）・14（札の小さな字）・16（本文）・20（問い）・28（題）・40（大きな数字）。書体は2つ（丸ゴシックを題と数字、本文は角ゴシック）。ドットの書体は案Cの場面だけ | C16（数字大・単位小）、Muzli の書体の調べ（[[web:uiref:uC-muzli-font-pairings-2026|「used just one」]]、[[web:uiref:uC-muzli-font-pairings-2026|「four times the body」]]） |
| 余白の段 | 4・8・12・16・24・32 の6段。カードの内側は16、カードの間は12、画面の左右は16 | いまの CSS の値のばらつき（1章）を段にまとめる |
| 角丸 | 3段：6（札の中の小さな部品）・14（カード・札）・全丸（人物・印・丸いボタン）。鋭い角は使わない | C34（攻撃的な形を避ける） |
| 影 | 1種類だけ：押せる物の下に3pxのずれた影（押すと0）。押せない物に影を付けない | C35（押せる物だけ質感） |
| 絵の作風 | まず人物の影の形だけで見分けられるかを確かめる（[[web:uiref:uC-duolingo-reshaping-duo|「not appealing」]]）。線なしの平らな形、1つの物の形は15まで、1色相の明暗の3段、頬と弧の目の丸い人物。背景は1色相の段で奥ほど薄く、月の中の時刻で色相が変わる | C25・C29・C31・C32 |
| 動きの長さ | 出来事の大きさの5段：0 押す（80〜120ms）、1 札が入る（250〜400ms）、2 行がそろう（〜700ms、○と小銭）、3 月が締まる（1.2〜2s、暖簾・数字の数え上げ・積み上がり。押せば飛ぶ）、4 決算・検定の合格（2〜3s、題の文字・紙吹雪・炎。押せば飛ぶ）。揺れは段3以上だけ。数字の変化を読ませる動きは約1秒で別枠 | Hicks（大事さに合わせる）、Heer（約1秒）、Liang（操作の後）、Pokémon Sleep の口コミ（飛ばしたい） |
| 合わない場面 | 検定会場（CBT の本番の形は素であるべき）。帳簿・月報の細かい数字を読む所（絵と色が多いと数字が埋もれる）。暗い表示（紙の色の段をそのまま反転すると濁る） | |

### 案B「路線図の帳簿」（帳簿・月報・町の地図・練習室の規則）

| 項目 | 決まり | 参考にした実例 |
|---|---|---|
| 色の組 | 地は白に近い1色（町は都市ごとに地の色を変える）。色は意味だけ：箱の種類5色（案Aと同じ色）、自店の線、ライバルは灰。それ以外は灰色の3段 | C24（色は路線だけ）、C19 |
| 文字の大小 | 大きな数字は1画面に1つ（40）、他は 14・16 の2段。数字は桁がそろう（tabular-nums） | C24（数字は1つ）、Muzli の書体の調べの等幅（[[web:uiref:uC-muzli-font-pairings-2026|「third font is a mono」]]） |
| 記号 | 文字の代わりに記号で種類を分ける（丸・三角・四角＝出来事・箱・書類） | C24、C28（色＋形） |
| 図 | 仕訳を「出来事の駅から箱の駅への線」として描く。帳簿の月は積み上がる背表紙（C14）。推移は面グラフで自店だけ色 | C24・C14・C19 |
| 動き | 図が段に分かれて動く（目盛り→値の順）。約1秒。重なるときは少しずつずらす。途中も正しい図のまま | Heer |
| 合わない場面 | 会話・店の中（人と食べ物の温かさが出ない）。ドパガキの「派手さ」は出ない。中高生の一部には「地味」に見える恐れ【推論】 | |

### 案C「ドットの屋台と燃える数字」（正解・締め・決算の瞬間の規則）

| 項目 | 決まり | 参考にした実例 |
|---|---|---|
| 色の組 | 濃い地（藍の夜）に、2つの箱（左＝藍、右＝柿）と白の大きな数字 | C22 |
| 文字 | 数字と見出しだけドットの書体（いまの DotGothic16 を限定して使う）、日本語の本文はふつうの書体 | C26（ドットは見出しだけ） |
| 絵 | ドット絵の屋台・人物（Stardew の密度は前提にしない） | C27 |
| 動き | 札を置くごとに「＋1万円」が浮き、箱の数字が増える。左右がそろうと箱が「＝」でつながり光る。月の売上が大きいほど湯気・炎が強くなる | C22、C1 |
| 合わない場面 | 日本語の長い文（ドットは読めない）、社会人・受験生の「勉強の画面」（賭けの演出に見える恐れ、Balatro は12歳以上の区分）、毎回の仕訳（派手さが成績を下げる向き、Juul） | |

**推しの組み合わせ**【推論】：店・町・会話・プロローグは案A、帳簿・月報の数字と町の地図は案B、正解・締め・決算の瞬間だけ案C のエッセンス（2つの箱の式、数字の大きさが絵の強さになる）を案Aの絵の上で使う。3つの案は色の組（箱の種類5色）と角丸・影・余白の段を共有し、作風だけを場面で切り替える（カービィの「頻繁に使う UI は汎用、1回限りは特化」の型、[[web:uiref:uC-kirby-ui-gamewatch|「頻繁に使用するUI」]]）。

## うまくいく理由

1. **規則がある→主役に絵と動きを厚く重ねられる→チープに見えない**。Duolingo は少人数で年に何百枚も描くために最小の形の規則を決めた（[[web:uiref:uC-duolingo-shape-language|「QUICK TO PRODUCE」]]）。規則が先にあるから、絵を増やしても統一が崩れない。BIZ-FUNVISUAL 3.0 の「規則を決め、主役を厚く描く」と同じ向き。
2. **手ごたえの大きさ＝出来事の大事さ→強弱の段ができる→大きな出来事が大きく感じる**。作り手の調査の最終の枠組みに入った項目（[[web:uiref:uC-hicks-goodgamefeel|「feedback reflect」]]）。いまの画面は全部が同じ（ほぼ動かない）ので、決算も札1枚も同じ重さに感じる【推論】。
3. **操作の後に確かめる手ごたえ→やりとげた感じ→次の操作へ**（[[web:uiref:uC-arx-juicy-vis|「the rewarding theme」]]）。
4. **データと結びついた絵→思い出す手がかり→日をあけても覚えている**（[[web:uiref:uC-bateman-useful-junk|「two-to-three-week gap」]]）。簿記は日をあけた想起が大事（PEDAGOGY 0.3）なので、学びの目的と合う。
5. **数字の変化を動かす→どれがどれだけ変わったかを追える→反映の場所が分かる**（Heer）。P3 への直接の効き。
6. **「あたたかさ」の規則→角を丸め強いコントラストを避ける→難しそうに見えない→幅広い年齢が手に取る**（[[web:uiref:uC-kirby-ui-denfami|「コントラストの差をきつくしない」]]）。

## うまくいかない理由

1. **派手さ→見た目の評価は上がる→しかし重複した手ごたえが認知の負荷を上げる→成績は下がる向き**（[[web:uiref:uC-juul-juicy-feedback|「barely made them」]]、有意ではない）。仕訳を正しく読むことが目的の画面で起きうる。
2. **毎回くり返す演出→待たされる→飛ばしたい**（[[web:uiref:uC-gp-pokemonsleep|「スキップ又は再生しない」]]、図解の研究の [[web:uiref:uC-arx-juicy-or-dry|「animations to finish」]]）。
3. **関係のない飾りが図の隣にずっとある→注意がそれる→学びが下がる**（[[web:uiref:uC-wsu-seductive-details|「58 studies」]]）。
4. **仕組みの説明を動画のように流す→速すぎ・複雑すぎて見えない→静止図に勝たない**（[[web:uiref:uC-tversky-animation|「too complex or too fast」]]）。
5. **業務の場面だと手ごたえは邪魔に感じる**（[[web:uiref:uC-arx-juicy-vis|「get the work done」]]）。簿記の帳簿を読む画面は「仕事寄り」になりうる【推論】。
6. **業務のダッシュボード・暗い地の配色をまねる→ゲームなのに業務アプリに見える**（C7・C8 の悪い面。依頼文 7章の否定側の問い）。
7. **増減を良し悪しの色にする→費用・借入金が「悪い」と誤って学ぶ**【推論】（簿記の勘定は良し悪しでない）。

## 反証と限界

- ジュースの研究は人数が少ない・短い・英語圏（Juul 46人6分、Campos 少数、Fabre 45人、Liang 47・46・26人）。どれも数週間の遊びや学びの定着は見ていない。Kao の大規模な研究（中ほどと高いが良く、無しと極端は悪い）は本文を取れず、他の論文の引用（[[web:uiref:uC-arx-juicy-or-dry|「Goldilocks effect」]]）からしか言えない
- Heer の実験は2007年、大きな画面、仕事でグラフを使う大人。スマホの小さな画面・中高生には確かめていない
- Bateman は20人、絵は Holmes の作品（プロの作り手）。我々の絵が同じ質でなければ同じ効きは言えない
- WSU は広報の記事で、論文の本文は読んでいない。感情の面の良い効果は調べられていない
- Collect UI・Muzli の作品は英語圏のデザイナーの作品集・業務の製品が多く、ゲームではない。日本のゲームの画面はカービィの講演の画面だけで、日本のスマホゲームの画面は担当 B の範囲
- ストアの画面写真は宣伝用に作られた画面で、実際の遊びの画面と違うことがある
- 自分に不利な資料：Juul の結果は「派手にすると上手くなる」を否定する。Tversky は「動きで分かりやすくなる」を否定する。WSU は「飾りで楽しく学べる」に反する。これらを本文の結論に入れた（5章）

## やっていないこと

- **Figma を参照していない**。依頼文の決まり（外部への通信は research-fetch だけ、各サイトの API を直接呼ばない、figma.com は robots で禁止）と、オーナーの「Figma もコネクトしてある」が食い違う。接続（MCP）を使ってよいかの判断を取りまとめ役・オーナーに相談したい

- **Muzli の記事の元の作品のサイト**（nathansmith.design・Love & Money・Loop など）まで進んでいない

- **WSU の誘惑的な細部は広報の記事だけ**で、メタ分析の本文は読んでいない
- **Robinhood の紙吹雪の廃止（ごほうびの演出が金融で批判された例）は使っていない**。AP の robots.txt が Anthropic のロボットを名指しするため。CNBC など他の配信元は規約を確かめていない
- **GAME Watch の記事の画像は遅延読み込みで取れておらず、開いていない**

- **担当 A・B の成果とは突き合わせていない**（並行で作業中）
- 研究の多くは英語圏・大人が対象で、中高生・日本語の画面での確かめはない
