2026-11-02、担当 MB1（進み具合・目標・ダッシュボード・数字）。依頼文は `docs/BRIEF-UIREF-MOBBIN.md`（9章 MB1）。決まりは `docs/QUALITY.md`（4章 性悪説・5章 論証の表・6章 出典・7.1 体験の検討）。

**番号**：この文書の実例は X1〜。一覧の画像の番号（#1〜#86）は `research/notes` のノートの本文に書いた。第1回の実例は M1〜M19 のまま参照する。

## 要点

1. **「本来あるべき」中心の形は、帳簿＝店のダッシュボードそのもの**。家計・業務アプリの良い画面は、どれも「お金の全体を1つの大きな数で出し、その下で内訳と比べを開く」形をしている（YNAB の純資産＝資産と負債の棒の上を純資産の線が通る X34、Mercury の月ごとの貸借の対の棒 X36、QuickBooks の「Business at a glance」X28）。我々のゲームでは、**1か月の記帳の結果がそのまま店のダッシュボードの数になる**ことが芯で、別の「成績の画面」を作らない【推論】。
2. **ホームは「いま大事な1つ」と「済んだ」の2状態**。Oura（大きな数1つ＋1行の問い X19）、Opal（1つの点が3つの部分の点に枝分かれ X20）、Shopify（「1 Order to fulfill」の後に「That's it for now」X24）。我々のホームは「今月の未処理の書類」が主役で、全部済むと「今月は締めるだけ」に変わる【推論】。いまの「上部の帯に数を並べる」形（BIZ-UIREF 18章 問1）とは別の答え：数は常に並べず、**ダッシュボード（帳簿）の画面に移し、ホームは1つ**。
3. **大きな目標（1億・満点）は「見込みの線」で出す**。Wealthfront（今日から92歳までの線と星の目標 X5）、Acorns（いまの額から「Potential $70.1K」へのつまみ X6）、ANZ Plus（「週に約$24 で届く」X7）、Bloom（いまの点から点線の見込み X18）。**いまの額ではなく、いまのペースで届く日を出す**ことで、毎月の判断が大きな目標に返る【推論】。
4. **目標の段は「年・月・目の前」を縦に並べる型が既にある**が、多くは量への報酬（Duolingo の月・週末・日のクエスト X14【禁止の型】、Rocket Money の連続入金 X2【禁止の型】、Ten Percent Happier の連続日数の印 X16【禁止の型】）。写すのは段の並べ方と期限の見せ方だけで、段の中身は**会社の状態**（純資産・借入の残り・自動仕訳ルールの数）にする。状態で段を作る良い例は Crypto.com の「駅」（段ごとに特典＝権限が増える X12）と Quizlet の「未学習・学習中・習得」X17。
5. **比べは「先月の同じ時点」と「相手を名指し」が強い**。Strava「今月3回、先月のこの時点では0回」X50、Lloyds「6月の同じ時点より£80少ない」X47、FotMob の2チームの対戦の表 X53、Stripe の「似た事業と比べる」X49。ライバル店との比べは、順位表（第1回 M12）より**相手1店と並べる対戦の表**の形が、量の競争に寄らずに済む【推論】。
6. **月報・決算は「数枚の札を順にめくる物語」**。Copilot の「March In Review」（支出→予算→収支→資産の4枚 X58）は、我々の月末の締めの順（損益→予算→資金繰り→貸借）と同じ並び。Strava の月の振り返り（巨大な月の名→合計→一番の種目→一番長い走り→ねぎらい X59）は、決算（年1回）の型。
7. **数が変わる瞬間は「どこを通って、いまいくら」**。Wise の送金の段（設定→引き落とし→支払い→完了 X57）と GoHenry の「残高はいま£1」X56。仕訳が帳簿に入った瞬間を「書類→仕訳帳→勘定→試算表→ダッシュボードの数」の段で見せる型の実物【推論】。
8. **反対の事実**（6章）：業務の画面（Square・Stripe・QuickBooks・Deputy）は数の列が多く、そのまま写すと「事務の画面」になる。Mobbin には本物のゲームの経営画面がない（第1回と同じ）。オーナーの好み（動き・Coffee Inc 2）と同じ向きの材料は、静止画では確かめられない。

## 反対の事実と合わない型

### 反対の事実（オーナーの好みと同じ向きの結論ほど厚く）

1. **「Coffee Inc 2 のような絵の世界を主役に」への反対**：Mobbin の数の画面の多くは絵を使わず、白い札と数だけで読みやすさを作っている（YNAB X34・Mercury X36・Revolut X38・Square X25）。絵を主役にした数の画面は Acorns X6・Cleo X31・ANZ Plus X7 の3件で、どれも数の詳しさ（内訳・比べ）を別の画面に置いている。**絵を主役にすると、数の読み取りは1段深い画面に回る**【推論：見た画面の並びから】。帳簿の学びに数の読み取りが要る以上、ホームは絵、帳簿の画面は数、の分け方になる（S1・S2）
2. **「動き（数え上げ・光る）」への反対**：Mobbin は静止画で、動きの有無・長さは1枚も確かめていない。Copilot の月報（X58）は「CONTINUE TO 〜」の押す操作で進み、自動で進む演出かは分からない。BIZ-UIREF 0章-4（Liang：成績を理由には足せない）を変える材料はこの調べにない
3. **「ドラッグ」への反対**：MB1 の範囲の画面で、数をドラッグで動かすのは第1回の Cleo のつまみ（M14）だけで、今回の86枚にはない。進み・ダッシュボードの画面は押す・めくるで足りている
4. **「本来あるべき」への反対**：引いた型の多くは**大人の家計・業務**の画面で、中高生が遊ぶゲームに合うかは確かめていない。純資産・前年比・予算の超過は、大人が自分のお金で関心を持つから読まれる【推論】。ゲームの中の架空の店のお金に、同じ関心が生まれるかは分からない
5. **「数を減らしてホームは1つ」（S1）への反対**：ウマ娘は能力の値を常に出す（BIZ-UIREF 0章-2）。経営シムは数を見張ること自体が面白さで、Copilot X30・QuickBooks X28 も数を多く並べる。S1 の「1つ」は、BIZ-UIREF 18章 問1 の (b) を選ぶことになり、オーナーの決定を先取りしている。S2 に全部の数があることで和らげるが、決めるのはオーナー

## うまくいく理由

1. **1つの大きな数→押すと3つ→押すと詳細**（X19→X20→X38）：見る人は上だけ見て帰ってよく、知りたい人だけ掘る→画面が混まない→毎回見に来るのが負担にならない。損益計算書（合計から内訳へ）と同じ形なので、掘る操作がそのまま P5（区分）の学びになる【推論】
2. **比べを1文の言葉に**（X47・X50・X41）：数の比べ（％・差）は読むのに頭を使う→1文の向き（多い・少ない・なぜ）なら数を読まなくても分かる→数の苦手な人も結果を受け取れる。PEDAGOGY 0.1-2（暗記の苦痛を減らす）の向き
3. **目標をペース（傾き）で見せる**（X5・X7・X1）：遠い目標の％は動かない→傾きなら今月の行動で変わる→毎月の判断に意味が戻る。経営の本物の見方（成長率）とも同じ
4. **資産と負債を同じ軸、その差を線**（X34・X36）：式（資産−負債）を読まずに形で分かる→貸借の等式が絵で身につく
5. **月の区切りを札の物語に**（X58・X59）：1枚に1つの問い→めくるだけで全体→区切りが儀式になり、「1か月＝1ステージ」の終わりが感じられる
6. **相手を名指しして左右に並べる**（X53）：順位表は全員と競う→対戦の表は1者と項目ごとに比べる→勝ち負けの理由（どの項目）が見え、次の判断につながる

## うまくいかない理由

1. **業務の画面の数の多さ**（X25・X29・X67 の札6つ）：店主は毎日見るから多くても読める→遊ぶ人は月1回の結果を見る→多い数は読まれず、事務の画面に見える
2. **％の比べの壊れ方**（X35 の88%・X49 の +∞）：小さい額や0からの変化は％が極端→誤った驚き→信用を失う。はじめの月の我々の店は額が小さい
3. **量の印の並び**（X16・X56）：未取得の灰色が並ぶ→「足りない」の感覚→義務になる【推論】
4. **見込みの点線の根拠のなさ**（X18・X5）：前提が見えない見込みは嘘の安心→外れたとき信用を失う
5. **毎回の結果の画面は待ち**（X56・X58）：くり返すと飛ばされる→結果が返る体験が消える（BIZ-UIREF 7章 うまくいかない1 と同じ）

## 反証と限界

- 資料は画面だけ。「その型が効く」証拠（利用者の声・実験）はこの調べにない。効く理由の鎖は画面の構造からの【推論】
- Mobbin にゲームの経営画面がない（第1回の要点1と同じ）。Coffee Inc 2・カイロソフトの画面と並べて比べていない
- Robinhood は Mobbin の結果に出なかった（検索の記録 #11・#12）。Square の iOS の画面も出なかった（#4。web は出た）
- 縮小のプレビューではなく原寸から作った一覧で見たが、一覧の1枚は幅500px に縮めてあり、細かい数字（表の小さい字）は読み違いがありうる
- 動き（数え上げ・光・札のめくり）は静止画で見ていない
- 中高生に合うかは確かめていない（反対の事実4）
- 素案（S0〜S10）はこの担当の【推論】で、試作も試遊もしていない

## 捨てた案と理由

| 案 | 捨てた理由（学習効果・面白さ・正しさ・規約） |
|---|---|
| 進みを「記帳した数・連続日数」で出す（Rocket Money・Ten Percent Happier の型） | 学習効果：PEDAGOGY 1.8・0.1-3 が量への報酬を禁じる。量で進むと、正しく処理したかと関係なく進む |
| ライバルとの比べを町の順位表にする（第1回 M12 の型） | 面白さ：順位は量の競争に寄り、どの項目で負けたかが見えない。対戦の表（X53）の方が判断につながる |
| 損益・貸借の画面を業務アプリの表（Mercury・Square）の形で写す | 面白さ：事務の画面になる（依頼文 5章-4）。棒と線の絵（X34・X36）を主役にし、表は押したときだけ |
| 1億の目標を％の棒（X1 の型）だけで出す | 学習効果・面白さ：何年も1%台で動かず、毎月の判断に返らない。傾きと見込み（X5）を主役に |
| 3つの輪（Bevel X22）で利益・資金・借入を出す | 正しさ：輪は満点に対する割合の意味で、資金・借入に満点はない。誤った読みを教える |
| Mobbin の頁（mobbin.com/screens/…）を取得して説明文を読む | 規約：Mobbin の規約は自動取得を禁じ、取ってよいのは MCP の image_url だけ（sources.json） |

## やっていないこと

- 動き（数え上げ・光・札のめくりの長さ）は見ていない。Mobbin の MCP は静止画だけ
- 引いた86枚のうち、実例の台帳の「見た所」は一覧の画像（1枚あたり幅500px、web は1400px）で見た。原寸を1枚ずつ別に開いてはいない
- Robinhood・Square の iOS の画面は Mobbin の結果に出ず、引けなかった（検索の記録 #4・#11・#12）
- freee・マネーフォワードなど日本語の会計アプリは探していない（Mobbin の結果に出るかを確かめていない）
- 通知はアプリ内の受信箱の画面だけで、端末のロック画面の通知（プッシュの見た目）は探していない
- web の検索は Square・Stripe・飲食店の業務・貸借の4回だけで、ホームの階層・目標・月報は iOS だけ
- MB2・MB3 の範囲（振り分けの操作・判断・地図・オンボーディング・学びの画面）は探していない。重なる所（X11・X17・X55・X62）は MB1 の視点だけで書いた
- 素案は絵にしていない。試作も試遊もしていない。中高生に見せていない
- 書いた本人以外の判定・論証の検査は受けていない
- research-check で、Quizlet（X17）と Vocabulary（X55）の2本のノートが「anchors が0個」のエラーになる。原因は、同じ2つの画面を別の担当が後から取り直し、取得記録が `.html` のファイル名で残ったため（画像だけの文書と判定されない）。MB1 の取得記録（`.jpg`）とノートは正しい。取得記録は追記だけの決まりなので MB1 は直していない（取りまとめ役に返す）
