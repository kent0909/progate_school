# 日本語のアプリの画面から学ぶ（UI・UX の参考の調べ 担当A）

版 0.1（2026-10-30）。依頼文は `docs/BRIEF-UIREF.md`（9章の担当A）。決まりは `docs/QUALITY.md` の全章。数は全部スクリプトで数えた：実例・画像・資料の種類は `docs/analysis/uiref-A-count.js`、利用者の声は `docs/analysis/uiref-A-voices.js`。読了ノートは `research/notes/web/uiref/uA-*.md`（33本）。ゲームのファイルは変えていない。

## 0. 要点

1. **いまの画面が「Web のフォーム」に見える芯は、上部の帯（P8）と本文の両方が「同じ大きさの小さな字の箱を、同じ間隔で積んでいる」こと**（1章）。帯の字は 11〜13px が多く（`css/ramen.css` の `.r-kpi small` 12px・`.r-gl` 11px・`.r-tabs button` 13px）、デジタル庁デザインシステムが本文と UI の下限とする 16px（[[web:uiref:uA-dads-typo|「16 CSS px以上が基準値」]]）を下回る。日本の金融アプリは逆に、**大きな数字を1つだけ**出し、ほかは隠すか別の板へ逃がしている（A1・A9・A12・A16）。
2. **問題文が分からない（P2）への一番直接の手本は、Duolingo の3段（指示・材料・答える部品）と、freee の「専門の書式を、日常の言葉の問いに分けてから最後に書式へ戻す」**（A21・A33）。freee は確定申告書を ○× の問いに置き換え、説明文でも [[web:uiref:uA-gp-freee|「質問に答えるだけで」]] と言う。
3. **どこに反映されたか（P3）への手本は3つの型**：お金の「どこから→どこへ」を入れ物の絵と矢印で見せる（みんなの銀行の振替 A2）、帳簿の枠そのものに置かせる（パブロフ簿記の表示区分 A35）、出来事の順に点と線でつなぐ（WESTER の経路 A31）。2つ目は DESIGN-JOURNAL-UX 10章の「大胆」と同じ向きで、いまの設計の推し（最小）とぶつかる（末尾の章）。
4. **チープに見えない日本のアプリは、色を絞ったうえで、絵か動きのどちらかを主役にしている**。グッドデザイン賞の審査評はみんなの銀行を、白黒だけで個性的な UI を作り、[[web:uiref:uA-gmark-minna|「モーションデザインに力を入れており」]]、それが気持ちよさに直結すると評した。ただし反対の事実もある：Zaim の口コミには表示の変更が [[web:uiref:uA-applion-zaim|「子供ぽっく」]] なったという不満があり、パブロフ簿記は見た目が素朴でも分かりやすさで選ばれている（口コミ11件中、見た目を言うのは1件。A35・A36）。
5. **利用者の声は 8アプリの口コミ 160件を全部読み、見た目・操作・分かりやすさに触れる 75件（定型文をまとめた後）に符号を付けた**（5章、`uiref-A-voices.js`）。多い順に、使いやすい・シンプル 18、操作に迷う・一覧や並べ替えがほしい 15、見た目がよい 13、ゲーム感覚 12、キャラへの愛着 10。**動き・音は好き（5件）と嫌（3件）が同じアプリ（mikan）の中で両方出る**ので、「動きを増やす」は強さの設定と、既定を派手にしないことと組で言う。
6. **写さないもの**：連続記録（炎）・ログイン日数・受取期限・ハート（間違いの罰）・広告。日本のゲーム的なアプリ（おぢポ・Duolingo・シャドテン）はこれを画面の上の一等地に置くが、PEDAGOGY 0.1・0.2 が禁じる表層の報酬で、口コミでもハートは [[web:uiref:uA-applion-duolingo|「けっこうヒリヒリします」]] と嫌われる。写すのは、その隣にある「自分の行動で絵が変わる」（おぢポのおじさん、毎日まめの豆）の方。

## 問いの設計

**肯定側（なぜうまくいくか）**
- 日本語の金融・学びのアプリは、文字の多い日本語で、なぜ詰まって見えないのか。何を削り、何を足しているのか（作品ごとに両方）
- 迷わない・気持ちいい・もっと触りたい、は、情報の量と並べ方・絵・動き・文言・操作のどれとどれが絡むから起きるのか
- 業務のアプリ（銀行・家計簿・会計）が、業務に見えないために何をしているか（みんなの銀行・おぢポ・エポス）

**否定側（なぜうまくいかないか）**
- 同じ部品（カード・タブ・グラフ）でも、迷う・見づらいと言われる画面は何が違うか（口コミの NAV-・TEXT-・CHANGE-）
- 金融・学習アプリの見た目・操作への不満の最多は何か（5章の数え）
- 会計アプリの業務的な見せ方をゲームに写すと、どこが合わないか（各件の「対象に合うか」「悪い面」）

**写し方**：各件に、いまの画面の w番号、最小の写し方、大胆な写し方（絵・動き・構成・操作の作り直し）、仕訳の画面の作り直しのどの段（①〜⑤・全）に使えるか。

**問わなかったこと**：ゲームそのものの画面（担当B）、色・動きの規則の案（担当C）。Coffee Inc 2 の町の見せ方（P9）は日本語のアプリの側からだけ見た（A25・A31）。Refero・Mobbin・Dribbble・design-library.jp・Figma は規約・robots で取れない（反証と限界、やっていないこと）。

## 3. 楽しさ・面白さに何が効くかの表

実例の「どこ（部品・配置・動き・文言）」が、遊ぶ人の「何（手ごたえ・期待・達成感・迷わなさ・愛着）」にどう効くか。【推論】の印は、資料が因果まで言っていない所。

| 実例 | どこ | 遊ぶ人の何 | 因果の鎖 |
|---|---|---|---|
| A1 | 画面の主役を絵にし、数字を1つに | 迷わなさ・愛着 | 開くと絵が目に入る → 読む所が1つに決まる → 「また開きたい」生活の一部になる（口コミの記憶のフック）【推論：ゲームの月の画面でも同じか】 |

## うまくいく理由

**鎖1：1つを大きく、ほかを逃がす → 迷わない**
日本語の金融アプリ（A1・A11・A16）は、画面の一番上で大きく出す数字を1つに決め、ほかの機能は格子の板（A12）か、端の覗き（A11）か、下タブの奥へ逃がす。数字が1つだから読む所が決まり、日本語の字が多くても詰まって見えない。デジタル庁の余白の規則の「大きな余白を持つ物が重要に見える」（A38）が同じことを規則として言う。何と何が絡むか：**数の削減（情報量）と、大きさ・余白の差（並べ方）の両方**。片方だけでは効かない：マネーフォワードは一番上の枠を大きくしたが縦に長すぎて下が見えなくなり不満が出た（[[web:uiref:uA-applion-moneyforward|「一画面で見える範囲が狭くなり」]]）。

**鎖2：専門の形の前に、日常の問い → 何を聞かれているか分かる**
freee（A33）は確定申告書を ○×の問いに分け、答えると書式ができあがる。Duolingo（A21）は指示1行・材料・部品の3段にし、指示の上に難しさの札を出す。どちらも「書式（または問題の種類）を先に読ませない」。PEDAGOGY 0.2 の「用語を先に出さない」と同じ向きで、ピヨ商店の P2 に一番効く。絡み：**文言（問いの言葉）と配置（指示と材料と部品を分ける）**。

**鎖3：入れ物の絵と矢印、または盤そのもの → どこに入ったか分かる**
みんなの銀行の振替（A2）は出どころと行き先を上下に置き、入れ物に絵を付け、矢印でつなぐ。パブロフ簿記の表示区分（A35）は盤に直接置かせる。WESTER（A31）は出来事の順に点と線。どれも**入れた所と結果の所が同じ画面の、目で追える距離にある**。

**鎖4：色を絞り、絵か動きを主役に → チープに見えない**
みんなの銀行は白黒と黄の1色に絞り、線画を主役にし、審査委員は色を絞った分を動きに回したと評した（A4）。エポスは上半分を絵にした（A14）。Vocabulary は3色の等角の町（A25）。どれも**色の数を減らしたうえで、主役（絵か動き）を1つ厚くする**。BIZ-FUNVISUAL 3.0 の「規則を決めたうえで主役を厚く描く」と同じ結論に、日本語のアプリの側から着いた。

**鎖5：自分の行動で絵が変わる → 愛着**
おぢポのおじさんは歩くと見た目が変わり（声 CHAR+）、毎日まめは1日1粒の豆の暦（A30）、エポスは自分で選んだ絵（A14）。**自分の行動・選択が、数字でなく絵に返る**と、その画面を見ること自体が楽しみになる（Zaim の [[web:uiref:uA-applion-zaim|「毎日画面を見るのが楽しみ」]]）。

## うまくいかない理由

**鎖6：同じ部品でも、場所の一覧がないと迷う**
みんなの銀行はミニマルで絵も好かれるのに、定型の口コミにさえ [[web:uiref:uA-applion-minna|「見に行く場所が多いため」]] 迷う、という不満が残る。削った分の行き先を見渡す場所（全体の一覧）がないと、ミニマルは「迷う」に変わる。d払いの格子の板（A12）はこれへの答え。

**鎖7：変更が利用者の手順を壊す**
mikan・マネーフォワード・Zaim は、見た目・操作の変更で「望む勉強ができない」「隠せる範囲が変わった」「子どもっぽくなった」と言われた（CHANGE- 4件）。作り直しは、いま遊んでいる人の手順（どこを押せば何が出るか）を壊す。ピヨ商店は今は遊ぶ人が少ないので影響は小さいが、セーブを持つ人の手順（タブの位置）は変えた時に一度だけ案内が要る【推論】。

**鎖8：演出が読む物を食う**
mikan の利用者は、ほかのアプリで演出が派手になり単語の字が小さくなったのを乗り換えの理由に挙げた。演出・絵を足すとき、読む物（問題文・数字）の大きさを削ると、学びのアプリでは逆効果になる。

**鎖9：ゲームの報酬の形は、罰と作業に変わる**
Duolingo のハート（間違えると減る）は [[web:uiref:uA-applion-duolingo|「ヒリヒリします」]]、おぢポ・マネーフォワードの広告は邪魔（AD- 3件）。ゲーム的なアプリの「連続・ハート・受取期限」は、続ける理由と同時に、圧と作業を生む。PEDAGOGY 0.1・0.2 で禁じている形で、写さない。

**鎖10：業務の見た目を写すと、事務の画面になる**
三井住友（A16・A17）・株価（A18）・WESTER（A31・A32）は分かりやすいが、細い罫・警告の三角・青い帯・黒地の細い字は、ゲームを事務の画面に見せる。いまのピヨ商店が Web のフォームに見えるのも同じ原因（白いカードに字とボタンの縦積み）。写すのは形（行の4要素・点と線）だけで、見た目（罫・色・字の細さ）は写さない。

## 反証と限界

- **見た目は選ばれる理由の主ではない、という反証**：簿記の学習で一番近い比べの相手のパブロフ簿記は、罫線と手書き風のボタンの素朴な見た目で、口コミ（11件）は解説の分かりやすさばかり言い、見た目を言うのは1件（キャラがかわいい）。見た目の作り直しより、問題文と解説の分かりやすさ（P2）の方が遊ぶ人の満足に効く可能性がある。
- **かわいさは幼さに見える**：Zaim の表示が [[web:uiref:uA-applion-zaim|「子供ぽっく」]] なったという声。絵とキャラを足す向きは、社会人の遊ぶ人に安っぽく見える危険がある。
- **動きの評価は見ていない**：みんなの銀行の動きの評価は審査委員の文で、動きそのものは見ていない（UI Pocket は静止画、グッドデザイン賞のページも静止画）。動きが効くかどうかの根拠は、この調べでは文と口コミだけ。
- **ログインの壁**：UI Pocket はログインなしでは各アプリの最初の1〜2の流れしか見られない。家計簿の入力、銀行の履歴、Duolingo のレッスンの流れの途中、などの画面は、一覧の代表の3枚に出たもの以外は見ていない。
- **口コミの偏り**：APPLION の載せ方は高評価に偏る。否定の数（23件）は実際より少なく出ている。8アプリの1ページ目だけで、2ページ目以降は読んでいない。
- **英語のアプリが混ざる**：Vocabulary・Brilliant は英語のみ。日本語の字の多さでの見え方の根拠にはしていない（台帳の「対象に合うか」に書いた）。
- **取れなかった所**：Refero・Mobbin・Dribbble（規約でスクレイピング禁止）、design-library.jp・Behance（robots.txt が Anthropic を名指しで禁止）、Figma（robots）、Red Dot（robots が名指しで禁止）、livedoor の転載記事（robots）、Airレジ（Google Play に掲載なし）。Refero の行（画面の構成・配色や余白の決まり）は、日本語アプリの実物とデジタル庁デザインシステムで代えたが、SmartHR などの企業のデザインシステムは取れていない。
