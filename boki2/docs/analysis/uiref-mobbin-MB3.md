# Mobbin で探した「本来あるべき」物語・学び・はじまりの UI・UX（担当 MB3）

2026-11-02、担当 MB3。依頼文 `docs/BRIEF-UIREF-MOBBIN.md`（9章 MB3）。第1回 `docs/analysis/uiref-mobbin.md` の M1〜M19 は番号で参照するだけにし、新しい画面を探した。

**取り方**：オーナーが接続した Mobbin の公式 MCP（search_screens・search_flows）で 25 回検索し、引いた画面の image_url を **全部 research-fetch で取得**した（取得元 `mobbin-mcp`、集合 `screens`、doc は画面の id）。取得は 129 枚（単独の画面 79 枚＋流れ4本の全画面 50 枚）。番号を付けた一覧の画像（8枚ずつ、17枚）を作り、全部を Read で開いて見た。文字の細かい PC の画面2枚と、一覧で読みにくかった1枚は原寸を開き直した。見た所は読了ノート `research/notes/mobbin-mcp/screens/<id>.md` の image_seen（129本、各60字以上）。数は末尾の「数の出力」のスクリプトで数えた。

**この文書は、書いた本人以外の判定・論証の検査をまだ受けていない**（QUALITY 2.3・5章）。

## 要点

1. **はじまりは「登録の画面」でなく「物語の1場面」にする**。Finch はひなが「名乗ったから、きみの名前は？」と聞き（Q1）、入力が会話の返事になる。Brilliant の最初の課題は「もう知っているよね、証明しよう」と言って、**説明より先に地図の上で札を置かせ、やり終えた後で名前（loops・logic）を付ける**（Q78）。これは PEDAGOGY 1.2 の4拍（困りごと→操作→結果→名前）と同じ順で、我々の「はじめの1回の手本」の芯になる。反対に、Brilliant の Onboarding は14画面のうち学びが0で、質問・通知・利用者の声・登録が先に来る（Q77）。質問を先にする型は写さない
2. **会話は「絵の部屋の上半分＋下の1行」か「チャット」の2型**。Kit（Q11）は部屋の絵と下の帯の1行を再生ボタンで送る＝オーナーの言う紙芝居の形そのもの。GoHenry・Brilliant・Tolan（Q12・Q16・Q13）は返事を選ぶ・聞き返すチャットで、**会話が「分からない所を特定する」道具になる**（Brilliant の先生は「どこが分からなかった？」に2つの候補を出す＝分かれ道）。本来の形は、困りごとを人物の1行で出し、つまずいたら聞き返しで分かれ道を選ばせる
3. **「なにを聞かれているか」（オーナーの原文）への答えは3つの型**：①問いを「穴のある1文」にし、答えの札が穴に入る（Acorns Q21）②答えを図の上で選ぶ（Brilliant のグラフ Q28・町の地図 Q78）③結果が対象の物にすぐ出る（Mimo の「お店の頁」に枠が付く Q24）。どれも「問いの文を読んで頭の中で対象を組み立てる」負担を画面が肩代わりする
4. **誤りの返しは「直す所の名指し」**：Mimo「Make sure to pick h1」（Q23）、Duolingo の違う語だけ下線（Q17）と「~~son~~ → petit」（Q18）、Turo「partially correct」（Q20）、Nibble は選んだ選択肢の中に説明を開き「I don't know」も選べる（Q19）。PEDAGOGY 1.1 の「森さんは場所だけ示す」の実物
5. **試験の形**：始める前に「時間」と「戻れること」の2つだけ言う（Expensify Q32）、格子＋いまの問いの帯（Apple News Q33）、採点後に目次の点が正誤の色＋合格までの差（Unity Q36）、結果を「どのスキルが上がった・下がった」で出す（Khan Q39）。**検定会場は業務的な見た目でよい唯一の場所**（本番の形に寄せる）
6. **復習の予定は「鍵の付いた日付」**（Cleo Q43）。間隔反復 1/3/7日を「森さんから3日後に届く封筒」として見せられる。連続日数（CapWords Q48・Mindvalley Q56・Duolingo の月のバッジ Q55）は禁止に当たる
7. **図鑑は「帳面」**（Finch の綴じた帳面のコレクション Q49）と「生まれた場面つきの札」（Moonlitt の場所・日・時刻 Q52）。影絵の格子（Swarm Q50）は**名前を影の下に出しているので PEDAGOGY 4.3 に反する**。数（1/60）も外す
8. **中断は「休業中」の札**（Finch の PAUSED と「いつでも戻ってきて」Q63）、再開は「あらすじ3行＋続き」（Brink Q64）。セーブは最後の保存の時刻を見せる（Life Reset Q67）
9. **Mobbin には本物のゲームの「物語の分岐」の画面が無い**（S23 で分岐する物語を探して出なかった）。分岐の見せ方は Mobbin からは引けない【推論：1つの問いの結果から】

素案は「本来あるべき画面の設計の素案」の章（画面 S-1〜S-12）。

## 本来あるべき画面の設計の素案（MB3 の範囲：物語・学び・はじまり）

前提：いまの画面・コード・PR #7 に合わせない。ゲームの芯（1か月＝書類が届く→記帳→締め→会社に返る、4拍で名前がつく、PEDAGOGY 0.2 の禁止）だけを前提にする。MB1（進み・ダッシュボード）と MB2（振り分けの操作・判断・町）の画面とつながる所は「→MB1」「→MB2」と書いた。

### 全体の考え方（3つ）

1. **画面の層は「店の絵（舞台）」「人物の帯（会話）」「手元（札と帳簿）」の3枚に固定の役を持たせる**。どの画面も、上に舞台、下に人物の1行、その間に手元。会話の画面・問題の画面・結果の画面を別の頁にせず、同じ舞台の上で帯と手元が入れ替わる（Kit Q11 の部屋＋下の帯、Mimo Q24 の結果がその場に出る、Duolingo の店の部屋 M1）。理由：問題の画面に移ると舞台が消え、「何のための記帳か」が切れる（オーナーの「なにを聞かれてるのか」の一因と推測【推論】）
2. **問いは人物が言い、答えは物の上に置く**。問いの文を読んで頭で組み立てる代わりに、取引相手の1文（Speak Q80）と、穴のある1文（Acorns Q21）、置く先の図（Brilliant Q28・Q78）で聞く
3. **報酬は「状態が変わる」だけ**。XP・連続・バッジは使わない（PEDAGOGY 1.8）。済んだ札が緑に変わる（Headspace Q79）、帳面の頁に科目が貼られる（Finch Q49）、店の絵が変わる（Mimo Q24）

## うまくいく理由

因果の鎖。どれも画面からの【推論】で、利用者の数で確かめていない（資料の内訳の章）。

1. **返事が来る質問は尋問にならない**：選ぶ（Q3・Q77）→案内役の台詞と絵が変わる（Q77 の「Source code by starlight.」とマグカップ）→1問ごとに小さな反応がある→答えることが会話になり、離脱しにくい。我々では、屋号・方針の選択が社長の反応と屋台の絵の変化を生むので、同じ鎖を物語の中で作れる
2. **操作が先、名前が後だと「もう知っていた」になる**：扉で「もう知っているよね」と言う（Q78）→図の上で操作して結果が見える（車が着く）→後で loops と名前が付く→名前が「新しく覚える物」でなく「やったことのラベル」になる。PEDAGOGY 1.2 の4拍と同じ構造で、Brilliant が最初の1回にこの順を選んでいることは、4拍の順が商用の学びのアプリでも使われている例になる
3. **問いが人物の1文と穴のある文になると、何を聞かれているかが分かる**：相手が先に話す（Q80）→文脈ができる→指示が1行（Say, “…”）→穴に何が入るかが文の形で分かる（Q21）。問いの文を読んで頭の中で状況を組み立てる負担を、人物と文の形が肩代わりする
4. **直す所の名指しは、自分で直す余地を残す**：誤り→「Make sure to pick h1」（Q23）→答えは言わない→2回目に自分で正す→正したのが自分の手柄になる。Duolingo の下線（Q17）は差を見せ、Brilliant の聞き返し（Q16）は分からなさを2つに分けて特定する
5. **済んだ物が残り、次が大きくなると、量を見せずに進みが分かる**：札が緑に変わる（Q79）→次の札が大きくなる→「どれだけやったか」でなく「次はこれ」が見える。PEDAGOGY 4.3 の「数や％を出さない」と両立する
6. **集めた物に場面が付くと、図鑑が記憶の入口になる**：札に場所・日・時刻（Q52）→押すとそのときを思い出す→PEDAGOGY 4.2 の「生まれた場面」をもう一度再生できる。帳面の形（Q49）は、集めることを「記録をつける」と同じ動作にする（簿記の題材と重なる）
7. **休むことが状態になると、戻りやすい**：PAUSED（Q63）→来なかった日が失敗でない→戻るときの気まずさがない。連続日数の型（Q48・Q56・F2-12）と逆の向き

## 反証と限界

- **効いた証拠がない**：画面だけを見た。利用者の声・続く割合・作り手の説明は読んでいない。「効く理由」は全部推論で、反対に「その画面は売上のために作られていて学びには効かない」という読みも同じ画面から組める（例：Brilliant の Onboarding の質問は、学びでなく課金の誘導の材料集めかもしれない。流れの最後が登録・前に課金の流れ「Subscribing to Brilliant Premium」も検索に出た）
- **動きを見ていない**：MCP は静止画だけ。「済んだ札が緑に変わる」（Q79）の動き方・長さは分からない
- **物語の分岐の画面は Mobbin に無い**（S23）。分岐・結末（バッドエンド）の見せ方は Mobbin では探せない。ゲームの資料（BIZ-UIREF の担当 B）に戻る必要がある
- **15歳以上に合うか**：Duolingo ABC・Kit・GoHenry は子ども向けで、絵柄の幼さは合わない恐れ（第1回 M6 と同じ）
- **PC の画面は2枚だけ**（Unity・Expensify）。スマホの型を PC の検定会場にどう広げるかは見ていない
