# 旧版の機能をピヨ商店へ移す設計（2026-10-20、Fable）

旧版（`classic.html`・`js/app.js`）にあって、ピヨ商店の練習室にないもの：仕分けラッシュ・勘定科目図鑑・ボス戦。PEDAGOGY 5（ラッシュ→廃止・保留、ボス→監査・税務調査・銀行審査、見た目は捨てる）と 4.2（図鑑の仕様）に沿って、形を変えて入れる。

| 旧機能 | 判定 | 置き場所 | 一言 |
|---|---|---|---|
| 仕分けラッシュ | 形を変えて入れる（**札の速さ**） | 検定会場のメニュー＋練習室の入口。会社の中には置かない | 第1問15分・CBT の候補選びの速さに直結。ただし全250科目・XP・コンボ・60秒は関所と報酬方針に反する。出す札を既習だけに、記録を「迷った札」に、検定会場の第1問の候補へ流す |
| 勘定科目図鑑 | 形を変えて入れる（**札で見る**） | マップの3つ目のタブ。記帳画面の「札の一覧」（`cardList`）をここへ | PEDAGOGY 4.2 の仕様（原理→兄弟、生まれた場面、兄弟との違い1行、本試験の呼び名、決算書での位置、未習は輪郭） |
| ボス戦 | そのままは入れない（**監査の点検**＋**自動仕訳の棚卸**） | 会社の中（年度末）と検定会場 | 外からの評価（銀行の審査・監査意見）は済。足りないのは「混ぜて判別させる」と「自動化で腕がなまっていないかの点検」 |

前提（2年目の終わりで教わる勘定科目は 58／250。旧ラッシュをそのまま動かすと8割が未習語）。

## 1. 札の速さ（仕分けラッシュの変形）
- 3モード。1回＝20枚固定、カウントダウンなし。終わったら「20枚を○秒。迷った札：…」と前回の秒数だけ（順位・点数・コンボ・XP は出さない）
  - A 札の置き場所：`S.taught ∩ B.accounts` を5グループ（教わる前は `gw()` の棚の言葉）＋マイナスの札へ。札が1つもないグループの箱は出さない。既習が12札以上で解放
  - B 増えたら左？右？：自分の会社の帳簿 `S.T` の各行から（「売掛金が増えた」）。`knows('借方')` で解放
  - C 決算書のどの区分？：既習の札だけ。箱は既習の区分語に合わせて段階的に増える（もうけの中身／棚の絵 → 売上原価・販管費・営業外 → 流動・固定 → 表示科目「繰越商品→商品」）
- 誤りは減点せず1行の理由（`B.accounts[a].d` など）。同じ札を同じ回の後ろでもう一度出す
- 終了画面：迷った札ごとに「生まれた場面をもう一度」と「札で見る」へ
- 記録 `S.speedLog: [{acc, mode, ok, ms, t}]`（上限つき。STORAGE.md に追記）。`growth` の苦手の理由に「札の置き場所で3回以上迷った」。`hall.shortOptions` の候補に、その人が混同した札を優先して混ぜる。迷った札は次回の先頭に
- 検査：sim-check で各月の `taught` を再現し、生成した札・箱・理由文を `LX.unknown` に通す

## 2. 札で見る（図鑑の変形）
- `mapOverlay` のタブを「考え方で見る／試験範囲で見る／札で見る」に。並びは原理（札を teaches した発見の `p`。`namings[acc].p` を足す）、切り替えで棚
- 1枚：①名前・グループ・一言 ②生まれた場面（発見は `replay()`、名前の札は `namingScreen` の再生モード） ③兄弟との違い1行（`js/data/siblings.js`。兄弟が未習なら名前を出さず「まだ出会っていない兄弟がある」） ④本試験での呼び名（繰越商品→商品、2027年度の帯、その札が答えの読める問題の文） ⑤決算書での位置（`js/data/kubun.js`） ⑥自分の記録（元帳＝`ledgerView` を全既習札に、自動仕訳の印、1回目で正しく書けた割合、札の速さで迷った回数）
- 検索は既習の札の中だけ。未解放の数は出さない。旧版の実務カードの本文（`ch.real`）は練習室の参考書の末尾と先輩の手帳へ

## 3. 監査の点検・自動仕訳の棚卸（ボス戦の変形）
- 監査の点検（会社の中、年度末の決算の机の前）：`{ t: 'audit' }`。森さんが5〜8枚。①自動仕訳の条件外（登録できる kind ごとに `D.traps[kind]` を1つ以上） ②兄弟の取り違え（社長が書いた仕訳） ③訂正仕訳。`deskScreen` の形で選び→`docScreen(fixMode)` で書き直す。直せなかったものは `ledgerGap()` に残り、銀行の格付け・監査意見に反映。`S.fixLog` に `audit: true`
- 自動仕訳の棚卸（検定会場、PEDAGOGY 1.6）：`S.T` のうち `S.rules` の kind の正解仕訳を金額を変えて10枚、`mountJournalCBT(exam:true)`。`examLog` に `auto:<kind>`、誤りは月初の想起の優先候補へ

## 4. 実装の順番
1. データ：`js/data/kubun.js`（engine の `COGS/NONOP/FIXED/SHOW` と classic の `PL_BINS/PL_ITEMS` を統合。`byContext` で貸倒引当金繰入の区分）・`js/data/siblings.js`・`namings[].p`。検査（coverage・lexicon-check・sim-check）
2. 札で見る
3. 札の速さ（`speedLog`・`shortOptions` への接続・growth）
4. 自動仕訳の棚卸
5. 監査の点検
6. 仕上げ：工場2年目の「原価計算の方式の一覧」を札で見るに。PEDAGOGY 5 の表を書き換える
