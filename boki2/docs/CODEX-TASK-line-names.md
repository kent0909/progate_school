## なぜ要るか
`boki2/js/data/tokyo23.js` の路線名は国土数値情報の**正式の線名**（JR の「東北線」「東海道線」、メトロの「丸ノ内線分岐線」など）。遊ぶ人が知っている呼び名（京浜東北線・山手線の環状・宇都宮線など）や路線の色と違うので、地図とカードで「どの線の駅か」が分からない。面白さには「知っている町と路線が地図に出る」実在感が効く。

## やること
1. **表** `boki2/tools/data/line-display.json`：`tokyo23.js` の `lines[]`（60本、`op` と `name`）の全部と、駅の `lines[]` に出る全部の組について、遊ぶ人に見せる呼び名と色（16進）を書く。
   - 1つの正式の線に、いくつもの呼び名が通るもの（JR 東北線の区間を京浜東北線・山手線・宇都宮線・高崎線・湘南新宿ライン・東北新幹線が走る、など）は、**路線の区間（`lines[].paths` の線）ごと**に、どの呼び名かを決める形にする。区間の決め方（駅の並び・座標）を表に書く
   - 山手線は環状の1本の呼び名として見せる（正式は品川〜新宿〜田端の山手線と、田端〜東京の東北線、東京〜品川の東海道線）
   - メトロ・都営の色は各社の路線の色、私鉄は各社の代表の色。ラインカラーを知らないものは「要確認」
2. **道具** `boki2/tools/stations-build.py` が読む形にする：表を読み、`tokyo23.js` の `lines[]` に `display`（呼び名）と `color` を、駅に `displayLines`（呼び名の一覧）を足す。**`stations-build.py` の変更は、この表を読んで項目を足す所だけ**にする（駅・候補地の作り方は変えない）。元の zip がそちらにない場合は、取りまとめ役に PR で頼む（取りまとめ役が作り直してコミットする）
3. 表の確かめの台本 `boki2/tools/line-display-check.js`：`tokyo23.js` の全部の線と、駅の全部の線に、表の行があること（抜け0）、色が16進であること、同じ事業者の中で違う呼び名に同じ色を使っていないこと（山手線の環状のように、わざと同じにするものは表に理由を書く）

**触ってよいファイル**：`tools/data/line-display.json`・`tools/line-display-check.js`（新しい）、`tools/stations-build.py` の表を読む所だけ。地図の画面（`js/ramen/stationmap.js`）は PR #10 の担当なので変えない（表示に使うのは PR #10 の後で頼む）。

## 手抜きの予想（先に禁じる）
1. **正式の線名をそのまま呼び名にコピーして埋める**（「東北線」のまま。基準1）
2. **1つの正式の線に呼び名を1つだけ付ける**（東北線＝京浜東北線、のように。区間ごとに決める。基準3）
3. **知らない色を、それらしい色で埋めて「要確認」を付けない**（基準4）
4. **抜けを例外の一覧に入れて検査を通す**（基準2）
5. **`stations-build.py` の駅・候補地の作り方まで変える**
