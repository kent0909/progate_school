## 設計1：3級既習者の近道

### 1.0 結論
- **聞く時点は「初回の1画面」**（(e)2 の年度確認と同じ画面。2問だけ）。プロローグのあとに聞く案は捨てる。理由：省く対象そのものがプロローグ（約5分）で、あとで聞いても手間は減らない。また `fresh()` は `S.mi=0` から始まり、`endingScreen` の「最初から」は `S.mi=1` から始める経路（engine.js:1460）がすでにあるので、屋台を飛ばす入口はコード上も自然。
- 「はい」と答えた人には **「近道の切符」3問**（本試験の形の仕訳。候補の札から選ぶ CBT 入力、ヒントなし、1分）を出し、**正解した問ごとに、対応する型2つを自動仕訳に初期登録**する。自己申告だけで全部を飛ばさない（忘れている人を守る）。3問とも外れたら通常の道（近道は切らず、語の先取りもしない）。
- **止める場面＝「2級の出来事」と「判断の弧」**。1年目で**手の操作まで残す発見**は3つ：`d-bank`（銀行勘定調整表＝2級）・`d-allow`（貸倒引当金の個別評価＝2級）・`d-cash`（7月の判断が11月に返る弧の核）。残りの1年目の発見（`d-capital`・`d-sales`・`d-siire`・`d-truck`・`d-stock`・`d-dep`・`d-accum`）は**「確認だけの1画面」（lite）**にする：困りごとの台詞と書類＋名前カードを1画面で見せ、「知っている」で進む。操作・予想・理由は省くが、そのあとの「本試験の文で確かめる」（`discQuiz`）は**残す**。これが3級者の「測定」になり、成長の記録に本試験の印がつく。
- 判断（uncle・report・volume・recon・dun・crunch・crunch2・credit・kessan・kessan2・dep）は**全部そのまま**。決算の机・締め切り・開始記入・決算書を組む・銀行の審査もそのまま。2年目は一切変えない（2年目の型は全部2級）。
- 自動で進んだ分は、地図・成長の記録で**「3級の型（見ただけ）」**。手で書いて初めて「自分でできた」になる。手で書く場は、検定会場の「自動仕訳の棚卸」（`autoQs`）・練習室・腕だめし・7日後の確かめ。

### 1.1 聞き方（初回の1画面 `setupScreen`）
タイトルの「はじめる」を初回に押したとき（`!S.setup`）。1画面に2問、ボタンは1つ。
- 問1「受験する年度」：既定は今日の日付で決める（2027年3月までは2026年度）。(e)2 のとおり。
- 問2「日商簿記3級の内容（掛けの仕入・売上、給料、減価償却、貸倒引当金の仕訳）は、もう書ける？」 選択肢：「書ける（3級に合格した・勉強した）」／「まだ」／「わからない」。
  - 「書ける」→ 切符3問へ。「まだ」「わからない」→ 通常の道（`S.pro3 = { on: false }`）。
- 文面の約束：「近道では、3級の型の書類をパソコンが自動で書く。2級の出来事と、社長の判断は全部ある。あとで切れる」（180字以内、lexicon-check の対象に入れる）。
- 設定の置き場：`S.setup = true`、`S.pro3 = { on, gate: [{kinds, ok}], at }`。プロファイル単位（`store.js` の保存に S ごと入る。版上げ不要、`fresh()` に `pro3: null, setup: false` を足すだけ）。タイトルの `<details>` に「近道：3級の型は自動（切る／始める）」を足す。途中で切る＝`preset: true` の `S.rules` を消す（`S.rules[k].preset` だけ削除、`taught` は残す）。途中で始める＝切符3問から。

### 1.2 近道の切符（`gateScreen`）
- 3問。入力は `B.hall.mountJournalCBT`（検定会場・練習室と同じ、候補の札から選ぶ・半角）。問題は `SIM.pro3.gate`（scenario.js）に固定で置く（数字は1年目の書類と変える。validate の対象に入れる）：
  1. 「商品￥120,000を掛けで売り上げた」→ 売掛金／売上 → 正解で `sell_credit`・`collect_ar`
  2. 「商品￥80,000を掛けで仕入れた」→ 仕入／買掛金 → 正解で `buy_credit`・`pay_ap`
  3. 「従業員の給料￥35,000を普通預金から振り込んだ」→ 給料／普通預金 → 正解で `pay_salary`・`cash_sale`
- 正誤はその場で出す（「書けた」「ここが違う」＋正しい行。(e)4 の返し方）。記録は `S.pro3.gate` にだけ残し、`examLog` には入れない（成長の記録を汚さない。切符は測定ではない）。
- 2問以上正解 → 近道 on。1問以下 → 「今回は通常の道をおすすめ」。それでも近道を選べるボタンは出さない（忘れている人に自動で進ませない）。

### 1.3 「既知の型」の一覧（S.rules に入れる kind）
1年目の `SIM.rules` にある6型そのもの（scenario.js:127-153）。2年目の型（`sell_credit_vat` 以下）は入れない。
| kind | 条件文（`conds` の ok かつ非 broad） | 仕訳 |
|---|---|---|
| buy_credit | 商品を掛けで仕入れたとき | 仕入／買掛金 |
| sell_credit | 商品を掛けで売ったとき | 売掛金／売上 |
| collect_ar | 掛けで売った代金が、預金に振り込まれたとき | 普通預金／売掛金 |
| pay_ap | 掛けで仕入れた商品の代金を、預金から払ったとき | 買掛金／普通預金 |
| pay_salary | 働いてもらった給料を預金から払ったとき | 給料／普通預金 |
| cash_sale | 屋台で商品を売り、代金をその日のうちに預金へ入れたとき | 普通預金／売上 |
登録の形：`S.rules[k] = { cond, broad: false, at: 0, preset: true }`。**狭い条件で登録**するので、12月のチラシ（`flyer`, `trapFor: 'buy_credit'`, scenario.js:571）は罠にならず手で書く（`autoRule` は `broad` のときだけ罠を返す：engine.js:983-987）。D社・E社の大口（`manual: true`）も手で書く。
入れない型：`found`・`uncle`・`sign`・`truck`・`pay_other`・`fee`・`loan`・`discount`・`pay_late`・`repay`・`stock`・`allow`・`dep`・`tax`（いずれも年1〜2回。3級の内容だが、手で書いても手間はほぼ増えず、`kindIntro` の「はじめての動き」を先に済ませておけば1画面で終わる）。

あわせて先取りするもの：
- `S.introSeen`：`pay_ap`・`collect_ar`・`discount`・`pay_late`・`repay`（1年目の `kindIntro` 全部。どれも3級の動き）。2年目の `kindIntro`（消費税3行・配当・機械）は残す。
- `S.ruleIntro = true`（「毎回同じなら覚えさせたい」の導入会話は出さない）。代わりに近道の最初の1画面で「登録した6つの条件文」を一覧で見せる（条件文を読ませる＝PEDAGOGY 1.6 の言語化の代用）。
- `S.taught` の先取り（`SIM.pro3.words`）：1年目の名前カード・名前の札で教える語のうち3級の語だけ。候補：仕訳・借方・貸方・資産・負債・純資産・株主・株式・帳簿・記帳・収益・費用・売上・給料・普通預金・資本金・売掛金・買掛金・仕入・掛け・三分法・借入金・支払利息・未払金・車両運搬具・取得原価・付随費用・広告宣伝費・支払手数料・繰越商品・売上原価・減価償却・減価償却費・耐用年数・月割・定額法・車両運搬具減価償却累計額・減価償却累計額・間接法・帳簿価額・貸倒引当金・貸倒引当金繰入・差額補充法・決算・発生主義・実現・法人税等・未払法人税等・監査・自動仕訳。**入れない語**（2級、または近道でも手で見つける）：銀行勘定調整表（d-bank で発見）・定率法（判断 dep が教える）・貸借対照表・損益計算書・決算書（report が教える）・損益・繰越利益剰余金・締め切り・当期純利益・決算振替（closingScreen が教える）・前期繰越・開始記入。
  - 理由：`gw()`・`knows()`（engine.js:30-34）が画面の言葉を切り替えるので、語を先取りすると最初から正式名で出る。`namingScreen` は `knows` なら出ない（engine.js:989-991）。`autoScreen` は namings を通らずに記帳するので、**自動にする型の札は必ず先に taught に入れる**（入れないと、札で見る・元帳で未習の札が出る）。
  - 「見つけた札」の起点（`cardOrigin`・`cardDetail` の「○月に、会社で見つけた」）は `discDone` を見るので、lite の発見で `discDone` を入れれば崩れない。

### 1.4 プロローグ・名前の札・発見の扱い

### 1.5 成長の記録・地図（`scopeState` の own）での扱い
- 新しい状態 **`lite`**（表示語「3級の型（見ただけ）」）。`scopeState(it)` に足す：
  - `disc` 側：`S.metrics.disc[d].lite === true` の発見を含む → `own` の条件（`first` が真）を満たさないので own=false。さらに `lite=true` を返す。
  - `kinds` 側：いまの判定 `kinds.some((k) => S.rules[k] || mastered(k))`（engine.js:255）を **`kinds.some((k) => (S.rules[k] && !S.rules[k].preset) || mastered(k))`** に変える（preset のルールは「自分で登録した熟達の結果」ではないので own に数えない）。preset の kind がどれも mastered でなければ `lite=true`。
  - `met`：preset で自動記帳した `S.L` の行も `mets` に入るので「○月に起きた」は今のまま出る。
- 表示：`scopeView` の `word` に `st.lite ? '3級の型（見ただけ）' : …` を追加（CSS `.s-cell.lite` を薄い枠に）。`scopeDetail` に「検定会場の『自動仕訳の棚卸』か練習室で手で書けたら、自分でできたになる」。`growth.js` の `item()`：`lv` は 1（会社で起きた）のまま、`why` に「3級の型として自動で進めた。手で書くと上がる」。`G.LV` の語は増やさない（成長の帯の段を変えない）。
- 昇格の道：
  - `autoQ(kind)`（engine.js:518-527）は `S.rules` の全 kind を出すので、preset の6型は検定会場の「自動仕訳の棚卸」に最初から並ぶ。正解は `examLog` の `auto:<kind>` に入り、`scopeState` の `ex` が拾って `exam1`（「本試験の文章でも書けた」）になる。これが「見ただけ」→上の段への道。不正解は7日後の確かめ（`dueReview` の `auto:` 分岐）に乗る。既存の仕組みで足りる。
  - lite の発見の直後の `discQuiz` 1問も `examLog` に入る。
  - `mastered(k)` は `docLog` を見る。preset の kind は自動で書くので `docLog` が増えず、`mastered` にはならない（＝「自分でできた」は手で書いた証拠がないと付かない）。意図どおり。
- `auditScreen` の「ふだんの書類」は `auto` を先に選ぶ（engine.js:793）ので、監査の点検に preset の自動記帳が混ざる。そのままでよい。
- `recallScreen` は `!x.auto` の書類だけを出す（engine.js:865）ので、月はじめの思い出すは手で書いた書類からだけ出る。そのままでよい。
- ヘッダー「自動で書く書類 N種類」は初月から6。`autoScreen` の題を「パソコンが N件を帳簿に書いた（3級の型）」に（preset の分だけのとき）。
- `endScreen` の開発用の記録に「近道：切符 2/3、lite の発見 7、自動で進んだ書類 N」を1行。

### 1.6 検算と遊びの検査
**データは scenario.js に `SIM.pro3 = { words, kinds, intros, lite, gate, card }` として置く**（engine と tools の両方が読めるように。sim-check・lexicon-check は engine を読まない）。

sim-check に足す検算（`--pro3` でなく常に走らせる。1秒で終わる静的検査）：
1. `pro3.kinds` の各 kind に `SIM.rules[k]` があり、`conds` に `ok && !broad` が1つ以上ある。
2. `pro3.lite` の各 id は1年目（`year` なし）の `discover` に実在し、その `b4.teaches` が全部 `pro3.words` に含まれる（＝2級の語を教える発見を lite にしていない）。逆に、1年目の discover で `b4.teaches ⊆ pro3.words` なのに lite でないものは `d-cash` だけ（弧の核として明示の例外リスト `pro3.keep`）。`d-bank`・`d-allow` は teaches に非 words 語（銀行勘定調整表・差額補充法を words から外す）があるので自動的に lite 不可。
3. `pro3.words` は、1年目の全イベント（`b4.teaches`・`teaches`・`namings[].teaches`・closing/opening/report が teach する語）を遊ぶ順に集めた集合の部分集合。2年目で初めて教える語は1つも入っていない。`pro3.words` に「銀行勘定調整表」「定率法」が入っていたら失敗。
4. `pro3.intros` ⊆ 1年目の `kindIntro` の鍵。
5. 近道で通す1年目の事象列（prologue を除き、lite を「discDone を付けるだけ」に置き換えた列）で、**decision の数と id の列が通常と同じ**（判断の弧が欠けていない）。sim-check の `run` は decision ごとに枝分かれするので、`pro3` の事象フィルタを通した `flat` で同じ検算を1周走らせ、`結末` の到達が通常と同じ集合であることを確かめる。
6. 切符3問（`gate`）の仕訳が貸借一致し、科目が `B.accounts` にあり、`kinds` の割当が重複なく6型を覆う。

lexicon-check に足す検査：
- 2周目として「近道の順」で読む：`taught` を `pro3.words` で初期化し、prologue を飛ばし、lite の発見は「b1.talk＋b4.line＋b4.exam」を1画面として字数（180字＋試験の文は例外）と未習語を検査する。設定画面・切符・「この会社の言葉」の文も対象に入れる（語数の約束：1画面180字、1文60字）。
- `pro3.words` に lexicon の語彙にない語がない。

遊びの検査（2回目の検査者：3級既習の受け直し役と、2026年度受験の社会人に割り当て。REVIEW-ROUND1 4章の20番を具体化）：
1. 初回の1画面で年度と3級の2問が出る。「書ける」→切符3問→結果の文言（「書けた」「ここが違う」）を記録。
2. 切符で1問わざと外す → その型だけ手で書くことになり、別の月に2回正しく書いたら `ruleOffer` が提案してくる（既存の道に戻る）。
3. 1年目で**止まった場面の一覧**を本人に書かせる。期待：d-bank（10月）・d-cash（11月）・d-allow（決算）と全判断・机・締め切り・決算書・銀行。lite の7画面は「確認だけ」と分かるか。2級の語（銀行勘定調整表・個別評価・定率法）が自動で流れていないか。
4. 1年目の所要時間（目標20〜25分）。退屈の位置（REVIEW (a) の6〜9月）が消えたか増えたか。
5. 地図：b-credit・b-expense・s-sanbunpo が「3級の型（見ただけ）」。検定会場の「自動仕訳の棚卸」に6枚並ぶ → 手で書く → 地図が「本試験の文章でも書けた」に変わる。1枚わざと外す → 7日後（検査では時計を進める）の月はじめに出る。

### 2.3 配当の計算の直し（454条）
いまは `divLimit = down(reNow/1.1, 10000)`（総額を1万円単位で切り捨て）で、1株あたりが割り切れない（340,000/530＝641.5）。配当は株式数に応じて割り当てる（454条。読了ノート egov-kaishaho の pages に454条あり）ので、**1株あたりの配当（整数円）を先に決め、総額＝1株配当×総株数**にする：
- `divPer(S, opt)`：max → `floor(floor(reNow/1.1) / shares)`（半分の枝は `floor(reNow/shares)`）、half → `floor(limitPer/2)`、all → `floor(reNow/shares)`（「全部」は1株あたりで切り捨てた全部。残りの端数は貯まりに残る）。
- `divOf = divPer×shares`、`resOf = min(floor(divOf/10), capNow/4 − resNow)`（全額の枝）。`divLimit = limitPer×shares`。
- 既存の数字が少し動く（標準・全額の枝：340,000→340,260、全部：374,600→374,180）。be5 の「超えた額」「積み立てていない準備金」は関数から作っているので自動で追従。REVIEW D1 の「切り捨ての説明」は試算に「1株あたり○円×○株」と書けば解ける。
