## やること
1. **段9：auto.js の拡張**（l.2 の段9）
   - 作戦の机・一杯の組み立て・月報・ふりかえり・分かれ道・開店の前の判断（物件・資金・看板4択・仕入先3択）を、すべて画面の取っ手を押して進める。
   - ボットの「打ち方」を引数で選べるようにする：`idle`（何も変えない）・`random`（seed で各手を無作為）・`skilled`（`tools/sim-ramen.js` の `smartX` の3方針と同じ考え）。
   - 正解が要る場面（書類・作業台・ふりかえりの問い）は、今までどおり台本から正解を読む。わざと間違える割合も引数で選べるようにする。
   - harness の log に、`plan`（選んだ手の一覧）・`bowl`（一杯の組み立て）・`decision`（開店の判断・札）の操作を **kind つきで** 残す。S.choices を log に写す。
2. **段10 の準備：ボット3,000周の道具 `bot-runs.js`**
   - Playwright（`/opt/pw-browsers/chromium`。ネットは止める）で ramen.html を、打ち方×seed で並列に回し、1周ごとに結果を JSON 1行で出す（seed・打ち方・倒産・詰み・1年目の月次の営業利益・初めての月次黒字の月・翌4月の口座・ページのエラー・横にはみ出した画面・選んだ手の数・かかった時間）。
   - 集計の表を出す：打ち方ごとの「1年目の倒産」「初めての月次黒字の月の分布」「エラーのあった周」「はみ出しのあった周」。
   - 途中で止めても続きから回せる（出力の JSON を読んで、済んだ seed を飛ばす）。

## 受け入れの基準
1. **面白さ**：skilled と idle で、1年目の「初めての月次黒字の月」と翌4月の口座の分布が、遊ぶ人に見えるほど違うかを、集計の表で出す（合否ではなく数を出す。いま1年目がほぼ赤字なのを設計で直している最中なので、その確認に使う）。
2. `node boki2/tools/playtest/bot-runs.js --style idle,random,skilled --seeds 0-29 --width 1280` が最後まで通り、ページのエラー0・詰まり0（同じ画面で進めなくなった周 0）。
3. 同じ seed・同じ打ち方を2回回すと、結果の JSON が同じになる（乱数の再現）。
4. スマホの幅（390）でも `--seeds 0-9` が通る。
5. AGENTS.md の6つの検査が通る。
6. 3,000周を実際に回す必要はない。かかる時間の見積もり（1周の秒数×3,000÷並列数）を PR に書く。
