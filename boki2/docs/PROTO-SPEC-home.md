## 2.1 切り替え `stale`（全版に掛ける。URL の `&stale=1`。既定は 0。11/04 オーナーの決定）
- **ねらい**：帳簿をつけないと会社の数が分からない（Coffee Inc 2 の「経理部人員不足のため…財務諸表の更新も遅れております」、画面写真 s08 の発想を、プレイヤー＝帳簿をつける人に写した。Coffee Inc 2 で遅れの原因は人の数で、記帳していない書類ではないので、置き換えた案）
- **`stale=1`**：書類は3回に分けて2枚ずつ届く（5月7日に #1・#2、14日に #3・#4、21日に #5・#6。前の2枚を記帳し終えると次の日付へ進んで届く。判断の札は #3 の後のまま）。ホームに出す数（`b1`・`b2`・`c`・`d`・`e` の数と線）は**記帳した書類だけ**で計算し、届いたのにまだ記帳していない書類があるうちは、数の横に「◯日の帳簿まで・まだの書類 N枚」の印を付け、数を薄く（不透明度 0.5 ほど）する。全部記帳すると印が消える。`a` は数がないので、札の重なりの横に「まだの書類 N枚」だけ出す
- **`stale=0`**：書類は1枚ずつ届き（いまのまま）、印は出さない。数は記帳した分まで（いまのまま）
- 「◯日」は最後に記帳した書類の日付（書類の日付は上の届いた日）。月の締めは 5月31日
- 記録に足す：印を押した回数、印が出ていた時間の合計、印が出ている間にホームを開いた回数
- 悪い面（試遊で見る）：古い数を正しい数と読み違える、印が罰に感じられる、急いで片づける作業感

## 3. 1か月の中身（全版で同じ。11/04 に Codex の相談 PR #14 を受けて書き直した）
**ゲームの目標**：ネットキャッシュ（現金＋普通預金−借入金）1億円、期限は10期＝120か月（`docs/DESIGN-RAMEN.md` のゴールと期限、段0）。数と線はこの目標に合わせる（純資産ではない）。

**月初（1年目の5月、仮）**：普通預金 3,000,000・現金 100,000・借入金 0 → ネットキャッシュ 3,100,000。経過は1か月（残り119か月）。

**先月（仮の固定の値。先月比に使う）**：売上 180,000、先月末の手もとに残るお金（現金＋普通預金）3,100,000（＝今月初）、先月のネットキャッシュの増え方 +40,000（先々月末 3,060,000 → 先月末 3,100,000）、先月の純利益 40,000（先月は掛けもカードもなく、もうけとお金の増えが同じだった、仮）。手もとに残るお金の先月比は「今月のいまの値 − 3,100,000」（月末で −25,000、チラシなら −45,000）。月初のペース +40,000 だと b1 の見込みは約2,423か月（約202年）で、そのまま出す（届かないことが見えるのが比べどころ）

**今月の書類6枚**（この順。仕訳の机は簡略：札を押すと正しい仕訳が出て「記帳した」を押すだけ。比べるのはホーム）：

| # | 書類（相手の1文） | 仕訳 | 動く数 |
|---|---|---|---|
| 1 | レジ「今週の売上、現金で 120,000円」 | 現金 120,000 ／ 売上 120,000 | 売上・現金 |
| 2 | 問屋「食材 40,000円、月末払いで」 | 仕入 40,000 ／ 買掛金 40,000 | （現金は動かない） |
| 3 | 大家「今月の家賃 80,000円、口座から引き落とし」 | 支払家賃 80,000 ／ 普通預金 80,000 | 普通預金 |
| 4 | アルバイト「今月のお給料 60,000円、現金でお願いします」 | 給料 60,000 ／ 現金 60,000 | 現金 |
| 5 | カード会社「カードの売上 90,000円、入金は来月」 | 売掛金 90,000 ／ 売上 90,000 | 売上（現金は動かない） |
| 6 | 道具屋「お玉、5,000円。現金で」 | 備品 5,000 ／ 現金 5,000 | 現金 |

**判断の札**（3枚目の後に1回）：「チラシを打つ（20,000円、現金）／打たない」。打つなら 広告宣伝費 20,000 ／ 現金 20,000。

**月末の結果**（検算済み）：売上 210,000（先月比 +30,000）。純利益は 210,000−40,000（仕入）−80,000（支払家賃）−60,000（給料）＝30,000（先月比 −10,000）、チラシを打てば広告宣伝費 20,000 を引いて 10,000（先月比 −30,000）。備品 5,000 は費用でなく持ち物なので引かない。手もとに残るお金は 3,100,000＋120,000−80,000−60,000−5,000＝3,075,000（チラシを打てば 3,055,000）。ネットキャッシュも同じ（借入金 0）で、今月の増え方は −25,000（チラシなら −45,000）。売上は増え、もうけも黒字なのにお金は減る。差 55,000 の内訳：カードの売上の入金が来月（−90,000）、備品を現金で買った（−5,000）、仕入の掛けをまだ払っていない（＋40,000。お金を多く見せる向き）。30,000−90,000−5,000＋40,000＝−25,000（11/04 検算）。`c` はこの3つの数（売上・純利益・お金の増え）が同じ画面に並ぶ。**これが数を見せる版で気づけるかが比べどころ**。

**見込みの計算**：
- `b1`（見込みの日付）：ペース＝今月のネットキャッシュの増え方（記帳した分まで）。月初でまだ記帳がないときは先月の +40,000 を使う。見込みの月数＝(1億−いまのネットキャッシュ)÷ペース。ペースが0以下なら「このペースでは届かない」。「このペースだと◯年目の◯月」を出す
- `b2`（逆算）：必要な毎月の増え方＝(1億−いまのネットキャッシュ)÷残りの月数（120−経過）。「1億まで、毎月 ◯円ずつ増やせば10年目に届く（いまは毎月 ◯円）」
- 前提（ペースの出し方・期限）は線を押すと出す。計算の式はコードのコメントに書く

## 4. 記録（外へは送らない）
`localStorage` と「記録を書き出す」ボタン（JSON）：版、1か月を終えるまでの時間、ホームを開いた回数、数・線を押した回数、判断の札の選択、月末に出す2つの問い（「いまお店の口座のお金はいくら？」「1億まであとどれくらい？」を4択で）の答え。

## 5. 見た目と大きさの約束
幅 390×844 と 1280×800。`e` の店の絵の高さは、ほかの版の店の絵と同じ描き込みで、大きさだけ変える（絵の出来の差で比べが歪まないように）。字は 14px 以上、押せる所は 44×44px 以上。各版で「次の書類の札」の上端の位置（画面の上から何 px か）と、店の絵の高さを測って記録する。動きは数が変わるとき 1秒以下、`prefers-reduced-motion` で止める。

## 6. 受け入れの基準
1. 6画面（a・b1・b2・c・d・e）×`stale` の 0 と 1 の全部（12通り）で1か月を最後まで遊べる（自動の打ち手で確かめ、出力を残す）。`stale=1` では、届いた直後に印と N が正しいこと（例：5月7日に届いた直後は「まだの書類 2枚」、#1 を記帳すると 1枚、#2 で消える）と、印の間の数が記帳した分までの値であることを確かめる
2. 5章の測り（2つの幅×6版×`stale` の 0 と 1。印が出ると数の部分の高さが変わりうるため両方測る。`stale=1` は印が出ている状態、5月7日に届いた直後で測る）：次の書類の札の上端の位置、店の絵の高さ、帯・数の部分の高さ（`d` は 211px 以内か）、最小の字、最小の押せる大きさ
3. 4章の記録が書き出せる
4. ゲームのファイルを変えていない
