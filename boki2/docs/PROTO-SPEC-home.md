# ホームの試作の仕様（PROTO-SPEC-home）：T1 店の前の数

2026-11-04、取りまとめ役。元は `docs/DESIGN-UI-IDEAL.md` 2.2 画面2・6.1 T1・9章 問1、`docs/BIZ-UIREF.md` 18章 問1 と上部の帯の測り（197.8px＝23.4%、14px で 240.9px）。

## 1. 目的
ホーム（店の前）の「数」の置き方を4版（(b) は2通りで計5画面）作り、**同じ1か月**を遊ばせて比べる。主役は全版で「次の書類1枚」（決定済み）。ゲームのファイルは変えず、`boki2/proto/home/` の中だけで完結。

## 2. 版（URL の `?v=` で選ぶ。試遊のときは `&lock=1` で切り替えを隠す）

| v | 中身 |
|---|---|
| `a` | 数なし。上半分に店の絵（仮の四角でよい。屋台・客・店員の位置が分かる程度）、その下に次の書類1枚の札（相手の顔の丸・1文・額）。受け箱の残りは札の重なりで |
| `b1` | `a`＋1億への細い線1本と「このペースだと◯年◯月」の1文（見込みの日付） |
| `b2` | `a`＋1億への細い線1本と「1億まで、毎月あと◯円」の1文（逆算。X7 の型） |
| `c` | 上端に大きな数2つ（「売上」「手もとに残るお金」と先月比の1行。Coffee Inc 2 の型）、その下に次の書類1枚、その下に店の絵（縮む） |
| `d` | いまの帯の数（口座のお金・借入金・手もとに残るお金・月・方針）を残し、字を 14px 以上にして並びを作り直した帯。帯は画面の4分の1（211px）以内に収める工夫をする（収まらなければ収まらないと記録する）。その下に次の書類と店の絵 |

## 3. 1か月の中身（全版で同じ）
- 月初の数：口座 3,000,000・借入金 0・純資産 3,000,000（PEDAGOGY のプロローグの後の開店前に近い値。試作の仮）
- 書類4枚（PROTO-SPEC-desk の4枚と同じでよい）。仕訳の机は簡略でよい（書類の札を押すと、正しい仕訳が出て「記帳した」を押すだけ）。**この試作で比べるのはホーム**
- 記帳するたびに数（`c`・`d` の数、`b` の線）が動く。全部終えると次の書類の札が「今月は締められる」1つに変わる
- 月の途中で、判断の札を1回出す（「チラシを打つ（20,000円）／打たない」）。数を見て判断を変えたかを記録するため

## 4. 記録（外へは送らない）
`localStorage` と「記録を書き出す」ボタン（JSON）：版、1か月を終えるまでの時間、ホームを開いた回数、数・線を押した回数、判断の札の選択、月末に出す2つの問い（「いまお店の口座のお金はいくら？」「1億まであとどれくらい？」を4択で）の答え。

## 5. 見た目と大きさの約束
幅 390×844 と 1280×800。字は 14px 以上、押せる所は 44×44px 以上。各版で「次の書類の札」の上端の位置（画面の上から何 px か）と、店の絵の高さを測って記録する。動きは数が変わるとき 1秒以下、`prefers-reduced-motion` で止める。

## 6. 受け入れの基準
1. 5画面（a・b1・b2・c・d）の全部で1か月を最後まで遊べる（自動の打ち手で確かめ、出力を残す）
2. 5章の測り（2つの幅×5版）：次の書類の札の上端の位置、店の絵の高さ、帯・数の部分の高さ（`d` は 211px 以内か）、最小の字、最小の押せる大きさ
3. 4章の記録が書き出せる
4. ゲームのファイルを変えていない
