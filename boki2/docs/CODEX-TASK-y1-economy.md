## 事実（取りまとめ役が実装の world で測った数。40 seed。スクリプト：下の「再現」）
- 手を打たない店（`world.policy0`）：営業利益の中央値は 4月 −20.2万、9月 −23.3万、3月 −17.2万。1年目に月次黒字が1度でもある周は **1/40**。3年目末（t=35）でも中央値 −0.7万。客数の中央値は 15.8（4月）→27.4（3月）→39.5（3年目末）。
- 手を打つ店（800円・地図・3月から LINE と SNS・小の看板・4〜9月のチラシ3万）：初めての月次黒字の中央値は **12月（t=8）**。1年目に黒字が1度でもある周は **23/40**。
- 作戦の机の試算（4月・商店街・seed 0）：客数 9.4人／日、口座 −25.3万／月。
- 取り込む前（v0.5 の頃）は、影の線（手を打たない店）が5月に黒字だった。いまの sim-check では「初めての月次黒字：なし」。
- v0.3 で「1年目の11/12か月が赤字」を面白さの問題として直した経緯がある（DESIGN-RAMEN の版の表）。

## 見立て（仮説。確かめること）
潜在客 P を「放置の3年目の中央値＝44」に逆算した（potentialScale 0.58）ため、常連が育つ前の1年目の新規の流れが細い。そこに固定費（家賃・パート・その他15/20万・返済）が乗っている。

## やること
1. **原因の切り分け**（実装の sim。`ramen-impl-check.js` の道具か、同じ考えのスクリプト）：次をそれぞれ1つずつ変えて、1年目の「初めての月次黒字の月」「黒字が1度でもある周」「1年目の営業利益の中央値」がどれだけ動くかの表を作る。
   - P の較正（3年目44 に合わせた値 vs 1年目の立ち上がりに効く別の較正）
   - 新規の流れの立ち上がり（`ramp`）・開店の山
   - 固定費（家賃・その他・返済のすえおき）
   - 常連の育ち方（retain・churn）
   - 評判の立ち上がり
2. **直し方の案を3つ以上**、それぞれ実装の sim で測る。各案で次の **2つの表** を出す。
   - (a) 1年目の手ごたえ：手を打つ店（smartX の3方針）と放置の、初めての月次黒字の月の分布、黒字が1度でもある周、1年目の口座の最低。
   - (b) 版1.2.1 の合否の行（`sim-check --ramen --runs 300` の正式な行：上手→基礎・放置、基礎→放置、仕入先、看板、予兆、F7・詰み、入れ替わり、家族）が、どう動くか。壊れる行があれば、そう書く。
3. 1年目の手ごたえの**目安の案**を書く（例：手を打つ店は9〜10月までに初めての月次黒字が来る周が70%以上、放置は1年目に黒字が来ない周が多くてよい）。目安は決めず、案として出す。

## 受け入れの基準
1. **面白さが最初**：各案で「手を打てば1年目に黒字が見えてくる」体験になるか、手を打つ店と放置の差が遊ぶ人に見えるかを、月ごとの数で示す。
2. 原因の表：変えたもの → 動いた数 → コマンドと出力。
3. 案ごとの (a)(b) の表。版1.2.1 の合否を壊す案は、壊すと正直に書く。
4. 数はすべて実装の sim の出力から写す（模型の数は使わない）。周の数は120以上、割合には Wilson の95%区間を付ける。
5. 依頼の対応表と、やっていないこと。

## 手抜きの予想（先に禁じる）

## 再現（取りまとめ役の測り方）
`world.create({seed})` から `world.policy0(W)` で36か月、`world.month(W, pol, { rng: SIMDATA.rng(seed*1000+t+1) })` を回し、`res.N`・`res.op` を記録した（seed 0〜39）。手を打つ店は、方針に `price: t<12?800:900, map:true, line:t>=3, sns:t>=3, sign:'small', signAt:3, flyer: t<6?30000:0` を重ね、`world.fitTime` で時間の予算に収めた。
