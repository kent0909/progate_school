# 保存・確認テスト・成長の記録

オーナーの依頼（2026-10-20）：(5) 人に遊んでもらう遅延テストの保存先と実装手順、(8) 苦手・得意が更新されて成長を追える仕組み、(9) サーバー保存。

## 1. 保存先の候補

| 候補 | 何ができる | 必要なもの | こちらで完結 | 判断 |
|---|---|---|---|---|
| **A. claude.ai の公開ページの保存機能（Artifact の db）** | 遊びの続きを端末をまたいで保存。確認テストの結果を、ページの持ち主だけが読める場所に残す。Claude が `ArtifactData` で読み、集計してリポジトリにコミットできる | 遊ぶ人が claude.ai にログインしていること。個人プランでは、持ち主のほかに書き込めるのは「メールで編集者として招待した人」だけ（リンク共有中は不可） | **できる（実装済み）** | **採用** |
| B. Supabase / Firebase（外部のデータベース） | アカウントなしの匿名でも保存できる。子どもの協力者に向く | オーナーがプロジェクトを作り、接続用の公開キーを渡す。行ごとの権限設定 | キーを受け取れば実装できる | 協力者が増えたら追加。保存の層（`js/sim/store.js`）を差し替えるだけで足せる作りにしてある |
| C. Google スプレッドシート（Apps Script の受け口） | 結果を表に追記。オーナーが表で直接見られる | オーナーが Apps Script をウェブアプリとして公開し、URL を渡す | URL を受け取れば実装できる | 予備 |
| D. GitHub に直接書く | — | ブラウザに書き込み用のトークンを置くことになり、漏れると危ない | — | **採らない**。代わりに、A の結果を Claude が読み、匿名化した集計を `boki2/research/playtests/` にコミットする |
| E. ファイルで手渡し | アカウントなしで、保存データ・テスト結果を JSON ファイルにして渡す | なし | **できる（実装済み）** | A が使えない人の逃げ道として併用 |

## 2. いま入っているもの

- **`js/sim/store.js`（保存の層）**
  - 端末の中（localStorage）には毎回すぐ保存する。
  - 公開ページとして開かれ、遊ぶ人がログインしていれば、4秒ためてから `data/users/<本人のid>/save_<…>_<人>` にも保存する。256KiB の上限に当たらないよう、分割して置く。
  - 開くたびに新しいほうの続きを読み込むので、別の端末でも続きから遊べる。
  - **遊ぶ人（プロフィール）**：1台・1アカウントで何人かが遊べる（親子など）。呼び名は本人の領域にだけ置く。
  - **引っ越し**：タイトルの「保存と引っ越し」から、保存データのファイル化と読み込みができる。
- **`js/sim/growth.js`（成長の記録）**：ヘッダーの「成長」ボタンで開く。
  - 試験範囲の項目ごとの段階を出す（まだ／会社で起きた／自分でできた／本試験の文でも書けた／日をあけても書けた）。
  - 土台・商業簿記・工業簿記、その中の区分ごとの帯グラフ。
  - **得意**：1回目で書けて、月末に直していない項目。
  - **苦手**：理由つきで出す（月末に直した、本試験の文で間違えた、1回目の正しさが6割未満）。
  - **確かめどき**：本試験の文で書けてから7日たった項目など。
  - **伸び方**：月末の締めと腕だめしのたびに段階の数を記録し、ゲームの月ごとの縦棒で見せる。
  - 点数・順位・他人との比較は出さない（DESIGN-REVISION 4章）。
- **確認テスト（`js/sim/testforms.js` と engine の `testScreen`）**：タイトルの「保存と引っ越し・確認テスト」から入る。URL に `?test` を付けても入れる。
  - 1年目の論点9問。ヒントも答え合わせも出さない。
  - 1回目（遊んだ直後）と2回目（7日後）は、同じ形で数字だけ違う問題。6日未満で2回目を始めようとすると確認を出す。
  - 協力者は番号（例 T1）だけを入れる。名前は残さない。
  - 結果は `testlogs/<本人のid>/runs/<番号-回-時刻>` に残る。中身は、各問の正誤・飛ばしたか・かかった時間・書いた仕訳と、そのときの遊びの進み（月・遊んだ分数・成長の段階）。
  - ページのルールで、ページの持ち主（オーナー）だけが全員分を読める。
  - ログインしていない、または書き込めない人の結果は端末に残り、「記録をファイルにする」で渡せる。

## 3. 遅延テストの手順（オーナー向け）

1. **協力者を決める**：推奨は、小学5〜6年生2〜3人、受験直前の社会人2〜3人。保護者の同意を取り、番号を割り当てる（T1〜）。名前と番号の対応表は手元だけに置く。
2. **招待する**：公開ページの共有メニューで、協力者のメールアドレスを**編集者**として招待する。個人プランでは、リンクで共有している間は外部の人が書き込めない。招待した人は claude.ai へのログインが必要。
   - ログインできない子どもは、オーナーの端末・アカウントで「ほかの人もこの端末で遊ぶ」から自分の呼び名を作って遊ぶ。その場合、結果はオーナーの領域に番号つきで残る。
3. **遊んでもらう**：1年目（約40分）を通しで遊ぶ。
4. **直後に1回目**：タイトルの「確認テスト」→ 番号 → 「1回目」。
5. **7日後に2回目**：同じ番号で「2回目」。この間はゲームを遊ばないでもらう（純粋な遅延の効果を見るため）。
6. **集計を頼む**：Claude に「確認テストの結果を集計して」と頼む。Claude は `ArtifactData` で `testlogs` を読み、論点ごとの1回目と2回目の正答・飛ばし・時間を、匿名のまま `boki2/research/playtests/` にまとめてコミットする。

## 4. 制約と今後

- ログインが要る（A の制約）。協力者が増えたら B（Supabase の匿名認証）を足す。`store.js` の `saveTest` と `connect` を差し替える。
- 2回目までの7日間は、現実の時間で数える（ゲームの中の月ではない）。
- 確認テストの問題は1年目の論点だけ。2年目以降の試作ができたら `testforms.js` に足す。
- 成長の記録は、試作の判定（engine の `scopeState`）に従う。DESIGN-REVISION の改修（熟達判定の変更など）が入ると、判定もそれに合わせて変わる。
