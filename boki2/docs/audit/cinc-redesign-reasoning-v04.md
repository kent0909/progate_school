1. **置き値を回す前に commit する手順を作った**（break.js・time v04）。結果を見て値を選ぶ余地が減り、選んだ跡（Ec）も設計者自身が書いた。後から確かめられる形になった。
2. **判断ごとに分母60で数えた**（T2.2-6・T2.2-7）。2つの判断をまとめて割合を下げる数え方が消え、崩せない所が数で見えるようになった。
3. **推奨が手元の数と合わないとき、推奨を替えた**（Q3b・Q5 (c)・V17）。前回の不当のうち3つは、推奨そのものを替えて答えた。
4. **食い違いを機械で探した**（consistency.js）。前回の「一部」の多くを占めた古い文の残りが、本文から消えた（抜き取りの21行が直った）。
5. **数を小さくする向きの直しを、原文を開いて決めた**（大胆な形の20）。

## うまくいかない理由

誤り・弱さと、その原因：
1. **約束の線を「動かせるもの」の外に置いたり、中に入れたりする基準が、結論の都合で決まる**（Q2 (f)・Q7 (a)）。Q2 では線を動かし、Q7 では約束を守る。どちらも「仕組みを変える」選択肢を数えずに結論した。原因：設計の仕組みの数（目標の帯・点検の形）と、測っていない秒を同じ「置き値」と呼び、まとめて動かせないものにした。
2. **物差しの違う数を比べる**（Q5c・N8）。原因：設計書の既存の幅（e.4 L754）を、上側の手の割合の合否に使った。
3. **結果を見た後の直しを、全部の回しにそろえない**（Ec を bowl に入れない）。原因：直しを判断ごとに足し、同じ直しを全部に当てる検査がない。
4. **推奨どうしの帰結を足し合わせない**（Q2 (f) と Q3b (b) で1ターン10分を越える）。原因：問いごとに時間の式を別々に回し、推奨の組で回していない。
5. **19章の「直した」は扱いの申告で、結果の確かめでない**（抜き取り29行で21）。原因：対応表の列が「扱い・どこで・どう直したか」で、「直した後に結論が言えるか」の列がない。

## 反証と限界

- **G1・G2 は私が置いた仕組みの案**で、学びと面白さの損（後半の迷いの重さ・点検の回数）は数えていない。線に入るかを示しただけで、G1・G2 を推奨とは言っていない。
- **Ec の読み（c.2 の「なし」は区画が空いている得の意図）は私の読み**で、L262 の較正の約束を区画ごとに当てる設計者の読みも原文から立つ。どちらが正しいかは、オーナーか DESIGN-RAMEN の書き手が決めること。
- **Q5c の「2号店の客数・粗利の式の方が崩れている」は逆の読みの1つ**で、回していない。DESIGN-RAMEN b.3 の「多店舗のみの中央値の店は届かない」は、設計者の読みを支えうる。
- **引き継いだ202の判定**は、文が同じでも、ほかの所が変わったことで意味が変わりうる（たとえば Ec が入って T2.2-6 以外の数の読みが動く）。文の比べでは拾えない。
- **69行の抜き取りは無作為ではない**。重みのある行を多めに選んだので、「直った」の割合は全体より低く出る向きがある。
- **J-D の判定書を見ていない**。事実の誤りがあれば、ここで妥当とした結論も崩れうる。
