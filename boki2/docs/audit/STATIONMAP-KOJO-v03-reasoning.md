### b. 「規則 A・U は両立しない」の「両立」の定義は回す前に決めてあったか【確かめた】
- 決めてあった：PLAN.md 9.1 の129行（「規則のあと湾岸が2か所以上なら両立しうる、0〜1なら両立しない」）。PLAN.md は 02:09:22、rules.md・rulesk.js は 02:10:04（`ls --time-style=full-iso`）。PLAN-after.md 1章も同じ時刻を貼っている。ただし PLAN.md 9章の頭（112行）が書くとおり、書いた担当は25か所の値を先に見ていたので、どの規則が当たるかはおおよそ見えていた。
- それでも問題が2つある。

## うまくいく理由
- 規則と物差しを回す前に PLAN に書いた → 結果を見て規則・線を選ぶ道が塞がれた → 「両立」の物差しが後づけでないことを時刻で確かめられた（b）。

- 都合の悪い結果を頭に書いた → 検査役は「どこまで悪いか」でなく「その悪さが置き値の1点の産物か」に時間を使えた。

## うまくいかない理由
- 「置き値は動かさない」を回す前に決めた → 感度を測らないことが手続きとして正しく見えた → 1点の数が、条件なしの結論（どの列でも届かない・当たる組なし）になった（F1）。
- 感度を capLunch だけ回した → 「勝つ数は capLunch に依る」と順序を付けた → オーナーの決定の内側の n が、問い直す候補から落ちた（F2・F3）。
- 平均（12の世界）の順位で数える物差し → 1つの世界で遊ぶ人の体験とずれる（F8）。

## 反証と限界
- 私の感度の結論に反する事実：s・e はほとんど効かない（1/25 のまま）。強さを上げると「湾岸を選べば勝つ」（H3w ×・H1w ×）に寄り、2.14 では n 0.5 で既にそうなる。つまり「n を上げれば解決」ではない。⑪w 形の選ぶ規則は、n 0.5 でも 2.14 で外れる（書いた担当の結論のこちら側は、n 0.5 でも残る）。
- n 0.5 は、資料のない幅の上の端。私は n を上げるべきとは言っていない。言っているのは「結論に n の条件を付けよ」「問いに n を並べよ」まで。
