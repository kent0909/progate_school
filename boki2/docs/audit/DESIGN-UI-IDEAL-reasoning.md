## 3. 特に厳しく見た5点

### 3.1 ① 仕訳を「差を0にする」遊びにする
- **範囲**：根拠は会計の照合（Xero）・家計の分割（Monarch・Quicken）・予算の割り当て（YNAB）。どれも「作業を終える」ための道具で、学ぶ人に効いた材料も、遊んで面白かった材料もない（MB2 の要点1 自身が【推論：遊ぶ人に効くかは試していない】）。
- **向き**：Xero の原寸は、警告の赤字のまま緑の「Totals match」で確定できる。照合の型は「そろえる」ことを報い、正しさは保証しない。素案はこれを悪い面に書いたが、4.5 で差0を報酬に数え、4.3-3 で差0を「済んだ」と同じ緑にした（R12・R15）。
- **学びとのぶつかり**：差額の論点で帯が答えを出す（PEDAGOGY 1.7 と逆）、単純仕訳では差0がほぼ自動、差0で確定を止めると締めの試算表の不一致が起きない（PEDAGOGY 1.1 の遅延の返りが消える）。3つとも素案のどこにも書いていない【確かめた】。
- **逆の結論**：「差の帯は置かず、行がそろった後の理由の1タップ（PEDAGOGY 1.3・DESIGN-JOURNAL-UX 4.7）と確定の後の正誤で終わりを示す」が同じ材料から言える【問い】。素案の推し（T2 で比べる）は残してよいが、「決めた」は不当。

### 3.2 ② ホームに数を置かない
- 素案の根拠3枚は、原寸では3枚とも数を置き、2枚は数が上（0章 1）。BIZ-UIREF 18章 問1 の推し（(c) の試作→収まらなければ (b)）とウマ娘の例は「数を残す」側で、素案はそれを反対の事実に書いたが、根拠の側の事実の向きを誤ったため、反対の事実が「少数派」に見える。
- 帯の測り（197.8px・240.9px）は「数を残すなら帯をどう収めるか」の問題で、「数をなくせば問題が消える」の根拠ではない（R9）。
- 「決めない」と書きながら体系全体が数なしを前提に組まれている（Z7）。

### 3.3 ③ 進みの数を出さない
- PEDAGOGY 4.3 の「数や％・進捗バー・残り項目数は出さない」は**試験範囲マップ**の節の決まり。図鑑（4.2）は数を禁じず、1.8 は「自動仕訳ルールの数」を進みに数える。
- 素案は 4.3 を帳面（1/60）にまで当てながら、店の前の「あと3枚」と画面15 の「済み・残り」（4.3 の言う残り項目数）を出す。読みが1つの文書の中で揃っていない。オーナーの依頼の「Progress indicator」への答えが、線の引き方の揺れで弱くなっている（C6・R5・S15・S19・T5）。

### 3.4 ④ スワイプを2択に限る
- 「見たスワイプは全部2択」（6件）から「科目選びには使えない」へは飛躍（MB2 も【問い】と書いた）。8章の台帳 #1 の理由「数十の科目をめくると偶然の正解が増える」は、4つの候補を押す形でも同じ確率の当てずっぽうが起きるので、スワイプに固有の理由になっていない【推論：検査役の筋】【問い】。
- ただし決定（左右へ払う＝借方・貸方の2択）は DESIGN-JOURNAL-UX 4.1（オーナー承認済み）と同じで、オーナーの「swipe で科目を入れていく」は左右へ払う形で満たす。直すのは理由の書き方と、PEDAGOGY 1.3 の箱を動かす原理（P1・P2・P6）でのドラッグを試作に入れること。

### 3.5 ⑤ 「本来あるべき」といまの設計
- **根拠なく外した**：PEDAGOGY 1.1・1.2 の机の B/S パネル（素案の全文で0回）、DESIGN-JOURNAL-UX 6章の同じ画面の棚と置いた時点の予告（C9・S8・D4）。どちらも論証の検査を経た決定で、外す理由（学習効果・面白さ・正しさ・規約）が書かれていない。
- **引きずられた**：D4 で、いまの設計の試遊（盤か列か）を「本来あるべき」の問い（机に帳簿を置くか）の答えの代わりに使った。C12 のスワイプ・4.4 の長さはいまの設計と同じだが、根拠（オーナー承認・試作で比べる）を書いているので後退ではない。
