- 表を SUMMARY から台本で作る → 本文の表は台本の出力の写し → 差は diff で全数が見られた（0）。
- 試しの写しの台本が元と同じ出力を出す → 回し直しが cmp で一致する → 試しの数は再現できる（5本・地図1つ）。
- 規則の入力（zone・desc・メッシュ）を原データから台本で引いている → 手の写し間違いが入らない（25行の全部で元の記録と同じ）。

## うまくいかない理由
- 規則の入力をゲームのデータ（tokyo23.js）からだけ取る → ゲームの都合で作った値（割り当てた駅までの歩きの見積もり）が「現実の店が出せるか」の印として使われる → F1。
- 面白さの数を主の列（7.9・seed 6）で書く → 段の比が決まっていないのに言い切りになる → F2。
- 依頼書が2つの案を並べ、片方の案の測定の側を書かない → Codex が決めることになる → F3。

## 反証と限界
- F1 は「元の記録の最寄り駅」が正しい歩きだという前提に立つ。ゲームでは候補地は割り当てた駅に属し、その駅からの歩きが人通りの距離の倍率に入るので、ゲームの中では 1,030m にも意味がある。X5 の理由（敷地に歩いて入れない）に照らすと元の記録が合う、というのが判定の根拠。
- F2 の 2.14 の H3w は湾岸7か所の中央と全体の中央の差が数万円で、seed で入れ替わる大きさ。「成り立たない」より「どちらとも言えない」が近い。
- 判定は試しの台本（月の中が期待値・K12）の数を見ただけで、正本の道具の数ではない。
