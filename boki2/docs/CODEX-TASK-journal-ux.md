## 受け入れの基準

- 面白さ（1つ目）：幅 390 と 1280 で、note の画面の動きを録画（Playwright の video か、連続の画面写真）し、5.1 の時間の線と同じ順に動くことを示す。強さ3段それぞれで、止まる動き・残る動きが 5.5 の表どおり
- 4つの入力（ドラッグ・スワイプ・押して選ぶ・キーボード）で、note の画面を最後まで書ける（Playwright の検査）。置いた札を1枚だけつかみ直して直せる
- 「：」で組む表示（engine.js 1206行）が note の画面から消えている
- `S.noteLog` に1回目に置いた列が残る。誤りのあと、説明を閉じるまで同じ札を払えない
- AGENTS.md の6つの検査、`ramen-y2-check.js`、bot の通し（`bot-runs.js` idle の seed 0〜2、幅 1280 と 390）が通る
- 保存：古い保存（v4）を読んでも壊れない。新しい項目は保存の大きさの上限（2MiB）に収まる
- PR の本文に「依頼の対応表」（上の原文の一文ごと・設計書の節ごと）と「やっていないこと」

## 手抜きの予想（先に禁じる）

- ドラッグだけ・押して選ぶだけを作って、ほかの入力を後回しにする
- 動きを CSS の transition 1つで済ませ、5.1 の時間の線（札→列→絵と数字の順）を守らない
- 強さ「控えめ」を、全部の動きを消すだけにする（5.5 では色と不透明度は残す）
- 設計書と違う形にしたのに、PR に書かない（違えるなら理由を4つの理由で書いて聞く）
- bot が押せるように、画面を設計書と違う形に変える
- 検査の基準を、通すために後から緩める
