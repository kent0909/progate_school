# 依頼文：仕訳を書く画面の作り直し（設計）

取りまとめ役が書いた依頼文。型は BRIEF-TEMPLATE、決まりは QUALITY 4章・5章・7章。

## 依頼の原文（オーナーの言葉をそのまま。要約しない）

初めての試遊のあと（10/25、プロローグだけ遊んだ時点）：

> まだプロローグしか触ってないけど
> ・アニメーション要素無さすぎて紙芝居になっててしんどい
> ・問題文がわかりづらい。なにを聞かれてるのか
> ・自分が左右選んだ科目が帳簿のどこに反映されてるかわからない。
> ・一つ取り消す、というか自分が選んだ特定の科目のみを修正する仕様にしたい。
> ・というかドラッグ、スマホならswipeで科目を入れていくスタイルの方がUXは良いのでは？

プロローグの「ノートに書く」画面（`ramen-y1.js` の prologue の `k: 'note'`）の画面写真を見せて：

> そうここの問題文がなにを問われてるのか、わからない。
> いや問題文自体が二つの文の羅列で間に:があるだけで何をいいたいのかわからん。

取りまとめ役の案への答え：

> Bで。他の修正もおけ。

- **案B（決定）**：出来事を見出しにする（「親方に1万円借りた」）。札には変わったものだけを書く（「小銭 ＋1万円」「親方に返すお金 ＋1万円」）。今の「親方に1万円借りた：小銭が増えた 10,000」の形はやめる
- **「他の修正」（承認）**：
  - 仕訳を書く画面をドラッグ（PC）・スワイプ（スマホ）で札を列に入れる形に作り直す。押して選ぶ形も残す（スワイプが苦手な人・キーボードの人のため）
  - 札が列に入る動き、口座の数字が増えていく動きなど、意味のあるアニメーションを入れる
  - 置いた札を1枚ずつつかみ直して直せるようにする（「ひとつ取り消す」だけにしない）
  - 問いの文で「何を手がかりに左右を決めるか」を言う（例：左の列＝何があるか（左の棚）、右の列＝どこから来たか（右の棚））。前の画面の棚と、同じ色・同じ並びにそろえる
  - 最初の1枚はピヨが手本で入れて見せる
  - 同じ型の問い・「A：B」の書き方の札を、全部の場面で洗い出す

## 目的

ゲームの芯の操作（取引を左右に分けて書く）を、触って気持ちよく、どこに何を書いたか目で追え、間違えた1枚だけを直せる形にする。面白さ（手ざわり・動き）と学び（左右の意味が分かる）の両方に効かせる。

## 受け入れの基準

1. **面白さ（1つ目）**：札を入れる1回の操作で、何がどう動き、どこに入り、数がどう変わるかを、画面ごとに書く（動きの台本：始まり・途中・終わり・時間の長さ）。「紙芝居」に見えている今の画面の具体的な場面を10か所以上挙げ、それぞれに入れる動きを決める。動きのせいで遅く感じないための長さの上限と、飛ばす操作を決める
2. **問いの文**：仕訳・分類を問う画面の問いの文と札の文を、全部（プロローグ・1〜4年目の台本 `ramen-y1.js`・`ramen-y2*.js`・`cards*.js` など）洗い出して表にする。各行に、いまの文・何がまずいか（手がかりがない・「A：B」・何の数か分からない など）・直した文を書く。プロローグの note の画面は案Bで書き直した文を出す
3. **操作**：ドラッグ（PC、マウス）・スワイプ（スマホ、指）・押して選ぶ（両方）・キーボード（Tab と矢印・Enter）の4つで同じことができる。置いた札をつかみ直す・戻す・入れ替える操作。誤操作（指がすべった・途中で離した）の扱い。画面の幅 390 と 1280 での配置の絵（文字の図でよい）
4. **反映の見え方**：札が列（帳簿の行）に入ったことが、入った場所で分かる。帳簿（T字の勘定・口座の残高）のどこが変わったかを、同じ画面か次の画面で示す
5. **作る範囲**：今の `engine.js` の board（k: tap・sort・note・card・choice・form）と、月の書類（t: 'doc'）の記帳の画面の、どれをどの順で作り直すか。触るファイル・壊さない検査（AGENTS.md の6つと、ramen-y2-check、bot の auto.js が押す取っ手）・要る新しい検査
6. **学び**：PEDAGOGY（とくに 1画面に新しい科目名2つまで、1画面180字）を守ること。左右の意味（何があるか／どこから来たか → 借方／貸方）への橋渡しを、どの年・どの画面で言葉にするか
7. **アクセシビリティ**：動きを減らす設定（prefers-reduced-motion）、色だけに頼らない、読み上げで札と列の名前が分かる

## 手抜きの予想（先に禁じる）

- プロローグの1画面だけ直して、月の書類の画面（t: 'doc'）を洗い出さない
- ドラッグだけ作って、押して選ぶ形とキーボードを消す（または、その逆でドラッグを作らない）
- 動きを「フェードイン」だけで済ませる（意味のある動き＝札が列へ飛ぶ・数が増える・どこが変わったかを示す、になっていない）
- 「A：B」の書き方の札を、見つけた数件だけ直して全部を数えない
- 問いの文の書き直しで、手がかり（何を見て左右を決めるか）を書かず、言い回しだけ変える
- 資料を読まずに「スワイプはよい」とする（肯定側の根拠がない）

## 肯定側の問い（必須）

- 札を左右に払う・つかんで落とす操作は、なぜ気持ちよく、なぜ覚えやすいのか。うまくいっている例（カードを左右に払うアプリ・ゲーム、ドラッグで並べるパズル・教材、会計の教材で T字に入れる操作）で、何と何が絡むから効いているのか
- 動きが学びに効く条件は何か（どこに入ったかを目で追える・原因と結果がつながる）

## 否定側の問い

- ドラッグ・スワイプが失敗する条件（誤操作・指で隠れる・スクロールとぶつかる・遅い・読み上げで使えない）。動きが邪魔になる条件（毎回待たされる・酔う）
- 左右に払う操作が「あてずっぽうで払う」を招かないか

## ゲームへの写し方の問い

- 最小の写し方（今の画面の作りのまま、札の形・動き・つかみ直しを足す）と、大胆な写し方（帳簿の画面を T字の勘定のボードにして、取引の札を直接そこへ入れる。月の書類も同じボードで書く）の両方。どちらを勧めるかと、その理由
