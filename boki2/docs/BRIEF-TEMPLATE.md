# 調査の依頼文の型（BRIEF-TEMPLATE）

調査を頼むときはこの型を埋めて渡す。決まりの理由は docs/QUALITY.md（4章：任せた相手は手を抜く・都合よく解釈する前提で書く）。

```
依頼の原文（オーナーの言葉をそのまま。要約しない）：

受け入れの基準（数・章・表で確かめられる形）：

手抜きの予想（3つ以上。ここで先に禁じる）：
- 

目的：（ゲームの何を良くするための調査か。面白さ・自由度・リアリティ・学びのどれに効くか）

肯定側の問い（必須）：
- なぜうまくいっているのか／なぜ長く遊ばれる・売れる・続くのか
- 何と何が絡むから効くのか（変数の絡み）

否定側の問い：
- なぜうまくいかないのか／何が不満・失敗の源か

ゲームへの写し方の問い：
- 最小の写し方と、大胆な写し方（抜本的に作り直す場合）の両方

資料の種類の目標：
- 一次資料・統計／実務者・業界／研究／事例（成功と失敗の両方）／利用者の声（数十件を数えて分類）／作り手の話／反対意見 のうち4種類以上

捨てるときの理由：学習効果・面白さ・正しさ・規約の4つだけ。時間・作業量・実装の難しさ・範囲外は理由にしない

成果の形：先頭に <!-- quality:v2 -->。章「問いの設計」「資料の内訳」「うまくいく理由」「うまくいかない理由」「反証と限界」「捨てた案と理由」「依頼の対応表」（原文の一文ごとにどこで応えたか）「やっていないこと」（浅いままの所・推測の所。空にしない）を持つ。node boki2/tools/report-check.js <ファイル> を通す

情報収集の決まり：research-fetch を通す・読了ノート・30字以上の一致なし・終了コード3は止まらず代わりの資料へ・research-check をエラー0で
保存：章ごとに commit & push
```
