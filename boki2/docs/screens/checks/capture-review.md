# 撮影の停止・中断と掲載範囲（PR #15 / 6620878899への回答）

## 1. mobile-darkの停止

写真は [S338](../images/S338-390-dark.jpg)。2年目11月の「11月のレジ締め日報（現金）」、出来事id `sale19`、月位置31・出来事位置1。

自動の打ち手が、貸方2行目の科目を選んだ後、金額を `input[data-s="cr"][data-i="1"]` にfillしようとして、12,000msの操作待ちを超過した。写真では貸方2行目（仮受消費税）の金額が空。借方910,126、貸方の売上828,141で、差は81,985。

**撮影道具が入力待ちで終了したという観測であり、「何を押してもゲームが進まない」と確認したものではない。** この画面で手動の行追加・金額入力・記帳を試していない。DOMの属性・再描画・実行負荷のどれが原因かは未切り分けで、ゲームの不具合とも断定していない。ゲームは修正していない。

当時の再現用設定は、ゲーム37135cb、撮影道具7eda636、seed=0、skilled/strategy=1、390×844、touch/mobile、dark。`SCREEN_PROFILE=mobile-dark SCREEN_OUTPUT=work/repro-dark node boki2/tools/screens/inventory.js` でプロローグから進め、2年目11月の同書類の貸方2行目への入力を見る。当時の待ち時間は12秒、現在の道具は60秒。一度の停止記録であり、同じ設定で必ず再発するとは確認していない。完全なエラーはinventory.jsonのerrorsに保存した。

## 2. mobile-lightの中断後

最初のskilled/strategy=1のスマホ周回は、進行ログ1300手・3年目3月まで到達した後、環境接続の切替で撮影プロセスが停止した。その同一枝を最初から丸ごと撮り直してはいない。

その後の補足は、(a) 理由の選択と2年目4月の全作戦項目を通常操作で再撮影、(b) スマホ自身で進めたidleの標準保存から続行して4年目6月の倒産を撮影、(c) PCで完走した同一seedの標準保存を通常のファイル入力で読み込み、スマホの通常終端を1枚撮影、である。保存ファイルはtools/screens/fixturesに保存した。__simへの書き込みや、未プレイの進行を作った保存ではない。

lightのスマホとPCの画面分類の集合は一致しており、列挙された種類・指定4時点の不足は0。ただし、中断したskilledのスマホ枝で3年目決算から4年目6月までの各取引・金額・各月の姿をすべて撮ったという意味ではない。その区間の同じ枝の通し操作・再撮影は未実施。

## 3. lightとdarkの範囲

lightは依頼書の列挙した種類をスマホ・PCの両方で掲載。darkは10種類以上という条件に対して62種類を掲載し、倒産を撮っていない。darkの表の空欄は「未撮影」とし、「見つからなかった種類なし」はlightに限ると明記した。

## 4. 14px未満の集計方法

inventory.jsonの各行の `minFont`（最小px）を14と比較する。1箇所でも14px未満があれば1画面と数える。本文全体が14px未満という意味ではなく、SVGの図・表・ルビ・注記・入力欄も対象。

337枚の時点では `rows.filter(r => r.minFont < 14).length` は337。停止写真を足した338枚では338（スマホlight117・PC light115・スマホdark106）。12px未満は323。

INDEXを `|` でsplitすると、0起点の11が「最小px」、10が「文字サイズ種類」、12が「縦画面数」。JSONのminFontとINDEXの最小pxを別々に機械集計し、一致を確認した。取りまとめ役の99という数はこの集計では再現しなかった。数の原本はsummary.jsonのtypography。
