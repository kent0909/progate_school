# 仕訳の机の試作の仕様（PROTO-SPEC-desk）：T2 差の帯・T3 B/S の棚・T10 入力

2026-11-04、取りまとめ役。元は `docs/DESIGN-UI-IDEAL.md` 2.5 画面5・6.1 T2/T3/T10・9章 問2/問3/問5 とオーナーの決定（11/04）。

## 1. 目的
画面5（仕訳の机）の3つの問いを、**同じ4枚の取引で、切り替えだけ変えて**遊ばせ、比べる。本番のゲームではない。ゲームのファイル（`boki2/js`・`boki2/css`・`*.html`）は変えず、`boki2/proto/desk/` の中だけで完結させる。

## 2. 切り替え（URL の `?` で選べ、画面の隅の小さな歯車からも変えられる。試遊のときは歯車を隠す `&lock=1`）

| 名前 | 値 | 中身 |
|---|---|---|
| `band`（T2） | `diff` | 上端に「左右の差 ◯円」を常に出し、差0で確定の札が押せる（問2 (a)） |
| | `scale` | てんびんの絵（左右の棒の長さ）で「そろった／そろわない」だけ。額は出さない。確定は止めない（問2 (b)） |
| | `none` | 何も出さない。確定は止めない（問2 (c)。いまの DESIGN-JOURNAL-UX） |
| `shelf`（T3） | `on` | 左右の列の下に B/S の棚（もっているもの／返すお金／返さないお金。収益・費用の帯は 4枚目から）を常に出す。札を置いた時点で、行の右に「→ もっているもの」のように動く帯の名前だけを出し、確定で棚の帯が伸び縮みする（問3 (a)） |
| | `off` | 棚なし。確定の後に、店の絵の中の小さな札（「小銭が増えた」）と、下の「帳簿」タブの赤い点で知らせる（問3 (b)） |
| `input`（T10） | `swipe` | 札を押すと「左へ／右へ」の札が出る。札を左右へ払っても置ける（いまの 4つの入力のうち3つ。キーボードも） |
| | `drag` | 上に加えて、札をつかんで**棚の帯（`shelf=on` のとき）か左右の列**へ引いて落とせる。落とせる所は引いている間だけ光り、名前が出る（問5 (b)）。`shelf=off` のときは列へだけ |

全部で 3×2×2＝12 通り。どの組み合わせでも同じ4枚が遊べること。

## 3. 4枚の取引（この順で出す。額と科目は2級の正しい仕訳）

| # | 書類（取引の相手の1文） | 正しい仕訳 | 何を見るか |
|---|---|---|---|
| 1 | 親方「この1万円、おつり用に貸すから。月末に返してくれ」（借用書） | 借方 現金 10,000 ／ 貸方 借入金 10,000 | 2行の仕訳。差の帯がほぼ自動で0になる（帯の効き目がないことの確かめ） |
| 2 | 道具屋「寸胴鍋、5,000円ね。現金で」（領収書） | 備品 5,000 ／ 現金 5,000 | 「へったら反対の列」 |
| 3 | 問屋「食材 30,000円分。今日 10,000 もらって、残りは月末払いで」（納品書） | 仕入 30,000 ／ 現金 10,000・買掛金 20,000 | 複合仕訳（3行）。帯が「あと何が要るか」を示す力 |
| 4 | 業者「この券売機、60,000円で引き取るよ」（取得原価 120,000・減価償却累計額 50,000 の台帳の写し） | 減価償却累計額 50,000・現金 60,000・固定資産売却損 10,000 ／ 備品 120,000 | 差額の論点。`band=diff` だと差の額（10,000）がそのまま答えになる。`scale`・`none` では、書類の値から自分で差額を求める（計算パッドを出す） |

- 科目の棚：各取引で使いうる4つ（うち1つ以上は典型の誤り：1 は「売上」、2 は「消耗品費」、3 は「売掛金」、4 は「固定資産売却益」）と「全部の棚」
- 日常語の見出し：左「何があるか（もっているもの・増えた費用）」、右「どこから来たか（返すお金・返さないお金・増えた収益）」（DESIGN-JOURNAL-UX 7.2）
- 金額は書類の値を押して拾う（打ち込まない）。4 の差額だけは計算パッドで求める
- 置いた札は押すと「左へ／右へ／棚へ戻す」で1枚ずつ直せる

## 4. 返し（問8 の決定：全部すぐ返す）
確定の札を押したら、すぐに正誤を返す。誤りは「どの行か」だけを先輩の1行で示し、選び直させる（正解をすぐには見せない）。2回目も誤りなら正解を見せる。正しければ相手の「確かに」の1文と、`shelf=on` なら棚の帯の動き、`off` なら店の絵の小札。

## 5. 記録（試遊の集計のため。外へは送らない）
1枚ごとに、`localStorage` と画面の「記録を書き出す」ボタン（JSON をテキストで出し、コピーできる）に残す：切り替えの値、取引の番号、最初の確定までの時間、確定の回数、1回目の正誤、どの行を誤ったか、置き直し（直した）回数、入力の種類ごとの回数（押す・払う・引く・キー）、払いや引きが途中で戻った回数（しきい値未満）、別の列へ落とした回数、計算パッドを開いたか。

## 6. 見た目と大きさの約束
- 幅 390×高さ 844（スマホ）と 1280×800（PC）の両方で、**取引1〜3は縦のスクロールなしで確定の札まで見える**こと（取引4は行が多いのでスクロールを許すが、スクロールが要るかを記録する）
- 字は 14px 以上（デジタル庁の原則。BIZ-UIREF 1.1）、押せる所は 44×44px 以上
- 動きは札の着地 400ms 以下・棚の帯の伸び縮み 1秒以下（DESIGN-JOURNAL-UX 5.1、BIZ-UIREF 6章 #8）。`prefers-reduced-motion` のときは動きを止めて色だけ
- 絵は仮でよい（四角と色、絵文字なし）。試作で比べるのは配置と操作で、絵の出来ではない

## 7. 受け入れの基準（取りまとめ役が確かめる）
1. 12通りの組み合わせの全部で、4枚を最後まで遊べる（自動の打ち手で確かめ、その出力を残す）
2. 4枚の正しい仕訳で確定すると「正しい」、典型の誤り（3章の表の誤りの札）で確定すると「誤り」の返しが出る（自動で確かめる）
3. 6章の大きさの約束を、12通り×2つの幅で測った表（帯と棚を含む画面の高さ、確定の札の位置、スクロールの要否、最小の字、最小の押せる大きさ）
4. 5章の記録が JSON で書き出せる
5. ゲームのファイルを変えていない（git diff で示す）
