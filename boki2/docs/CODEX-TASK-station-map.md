## オーナーの原文（要約しない）

- 「簿記二級ゲームにおいてCoffee inc2のように出店する店舗立地をマップグラフィック上から選べる仕様にしたい。最低でも東京２３区の主要路線（JR、東京メトロ、）駅エリアは再現、各駅の人口に合わせて出店できるピン数を変える。イメージ伝わる？」
- 地図の見た目：「ゲーム風の地図（おすすめ）」（本物の地図の画像を敷くのではなく、自分で描く地図）
- 「駅自体だけで係数決めるのではなく、各駅規模に応じた候補立地が複数選択肢があって、それらの選択肢の中に駅×属性（商店街近く,オフィスビルの近く,住宅地）みたいなのがあるイメージ。伝わるかな？例えば渋谷駅も松濤エリアは住宅街、西口エリアはオフィス街、センター街は歓楽街、みたいな感じじゃん？」
- 画面の大きさ（10/20）：「スマホ規格のゲームをPCでやるのしんどい」→ スマホでもPCでも良い体験にする
- 見た目（10/22）：「正直いまの我々のグラフィックデザインはチープすぎるので。」／動き（10/25）：「選択肢、文字や背景にもアニメーションや動的表現を設けないとドパガキには耐えられないと思う」

## やること（仕事1だけ。需要の式・台本にはつながない）

`boki2/js/data/tokyo23.js`（`SIMDATA.tokyo23`。中身の形は設計書3章と `tools/stations-build.py` の末尾）を読んで、**出店の地図の部品**を作る。

1. 新しいファイル `boki2/js/ramen/stationmap.js` に、部品 `RAMENMAP.mount(el, opts)` を作る。opts：`{ onPick(siteId), mine: [siteId…], rivals: [{siteId, type}…], vacant: (siteId) => bool }`。戻り値に `{ focus(stationId), destroy() }`。
2. 描くもの：23区の輪郭（区名つき）・路線（`lines[].op` で事業者が分かる）・駅（乗降客数で大きさ）・ピン（属性で色と**形**。色だけで区別しない。**属性は版0.2 で6つ**：hanka 繁華街・shogyo 店とオフィスが混ざる商業地・office オフィス街・shoten 商店街・jutaku 住宅地・kojo 工場・倉庫の町。知らない属性が来ても落ちずに「その他」で描く）・自分の店とライバルの印（opts から）・空きでないピンは薄く。地図の隅に `SIMDATA.tokyo23.src`（出典、CC BY 4.0 の決まり）
3. 拡大の3段：①23区全体（乗降客数25万人以上の駅だけ名前）→ ②駅のまわり（全部の駅名とピンの町名が読める）→ ③ピンのカード。つまむ・ホイール・＋−ボタン・ドラッグで動かす
4. ピンのカード：町名・区・属性・駅名と歩く距離・駅の乗降客数（段で）・地価（万円/㎡）・周りの土地の様子（`desc`）。需要と家賃の数（客層・家賃・1日に余計に要る杯数）は**まだ決まっていない**ので、枠だけ作って「仮」と出す。「ここに出す」ボタンで `onPick(siteId)` を呼ぶ
5. 試しに開ける頁 `boki2/stationmap-demo.html`（部品だけを載せる。ramen.html にはまだ入れない）
6. 検査の道具 `boki2/tools/stationmap-check.js`（Playwright。この環境では `require('playwright')` がそのまま使える）

**触ってよいファイル**：上の 1・5・6 の新しいファイルと、地図の CSS（新しいファイル `boki2/css/stationmap.css`）だけ。`tokyo23.js` は手で直さない（道具の出力）。`stations-build.py`・`world.js`・`ramen-y1.js`・`ramen.html`・`art.js`・`ui.js` は変えない。外を変える必要があれば先に PR のコメントで聞く。

## 手抜きの予想（先に禁じる）

1. **数を決め打ちして、データが変わると黙って通らなくなる／通ってしまう検査にする**。数は `SIMDATA.tokyo23` から読む
1. **見た目を整えるために、駅やピンを間引く・重なる所を消す**。数はデータと一致させる（基準1）。重なりは「まとめ」で解き、消さない
2. **`tokyo23.js` を手で直す・別のデータを作る**（座標を丸める・ピンを動かす）。データの直しが要るなら PR のコメントで頼む（取りまとめ役が道具を直す）
3. **本物の地図の画像（タイル）や地図のライブラリを使って「ゲーム風」をやめる**（基準6）
4. **PC の幅だけで作って、スマホで確かめない**（基準4・5）。またはその逆
5. **需要の数（家賃・客数）を自分で決めてカードに出す**。設計書の判定の前なので「仮」の枠にする
6. **検査の道具が「描けた」を自分で言うだけで、数を数えない・押さない**（基準1〜4は DOM を数え、実際に押す）
7. **基準を通すために後から基準をゆるめる**（例：重なりの判定を「半分まで重なってよい」に変える）。ゆるめるなら理由を報告に書いて先に聞く
