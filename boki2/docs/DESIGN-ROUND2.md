## 0. 結論の要約

1. **範囲の網羅（決定1）**：区分表（2026・2027年度）の全項目を **5つの年**（商業1〜5年目、工場は2年目10月〜4年目の2年）に割り付けた（2章の表）。谷を作らない作り方は3つ：**(a) 論点は判断の帰結としてしか出さない**（手続きだけの論点は上流の判断の「代償」として置く）、**(b) 月の型を4つに分け、同じ型を2か月続けない**（判断の月・返りの月・工場の月・締めの月）、**(c) 判断も外乱もない月を sim-check で失敗にする**。1年目5・8・9・12月、2年目7・9月には既習の札だけで書ける「外乱カード」を置く。**5年目は「仕上げの年」**：連結の2年目に加え、1〜4年目の出来事が別の会社・別の数字で再来する（間隔をあけた再出題そのもの）。
2. **周回（決定2）**：周回の単位は **「年」**（通しでも、年を選んでも遊べる）。**変種**（会社名・業種・取引先・数字の倍率・出来事の順・社長の案の正誤）を seed から決め、論点の骨（固定の出来事）は変えない。**持ち越す**のは自動仕訳の型・原理マップ・成長の記録・結末の図鑑・日誌の年表・検定会場の記録、**持ち越さない**のは帳簿・口座・判断。**段（足場外し）** を6段で定義し、年の始めに自分で選ぶ（成長の記録が推奨を出す）。**「満点が取れる状態」**は4条件（全項目が「日をあけても書けた」／本番の形の検定会場で2回続けて100点、2回は7日以上離れ別の題／自動仕訳の棚卸が全型正解／分かれ道の直近の誤り0）で定義し、成長の記録に条件の一覧として出す（点数は検定会場だけ）。周回の楽しさの芯は「同じ論点が別の皮で来る驚き」と「段が上がる達成」と「自分の前の周との比較」。似たゲーム：Slay the Spire の Ascension と解放 [[web:simgames:r3-fable-wiki-slay-the-spire]]、Hades の館と周回が物語になる作り [[web:simgames:r3-fable-wiki-hades]]、ローグライトの「固定の出来事＋変わる中身」 [[web:simgames:r3-fable-wiki-roguelike]]、強くてニューゲームの持ち越しの約束 [[web:simgames:r3-fable-wiki-newgameplus]]、MG の「毎期自分で決算書を作り次期を計画する」 [[web:simgames:accountant-otaru-mg]]、Papers, Please の「台本つきの出来事＋周回ごとに変わる属性」 [[web:simgames:designer-papersplease-gd2014]]、ルセッティアの「落とすと終わるが持ち越しがある」 [[web:simgames:designer-recettear-gd2010]]。
3. **工場の月（決定3）**：毎月の同型の書類を手で書く形をやめ、**月末の「工場月報」1枚から帳簿の行を組む**形にする。型を登録した行は一括確定、**今月変わった行だけ**手で書く（段0では「？」の印、段1からは自分で見つける）。学びは4つの仕組みで守る：**月初の「川を描く」**（白紙の勘定連絡図に先月の数字を入れる＝検索練習、第4問(2)の型）、**抜き打ち**（自動化した型を月1枚、別の数字で手書き）、**混ぜる**（月報に店の行・給料と賃金・材料と仕入を混ぜて判別させる＝交互配置）、**毎月1つの判断**（払出方法・本数・外注か自前か・予定価格・予定賃率・予定配賦率と操業度・部門の配賦法・特注の受注価格・平均か先入先出か・検査点・組別と等級別・標準の厳しさ・値下げ・生産量）と翌月以降の返り。工業簿記の全範囲（費目別・部門別・個別・総合（仕損・減損）・工程別組別等級別・標準と差異分析・直接原価・CVP・固定費調整・本社工場・製造原価報告書）を工1（2年目10月〜3年目決算）と工2（4年目）に割り付けた（4章）。
4. **検定会場の延長（決定8）**：**90分の鐘はそのまま鳴らし、鳴ったあとに「+5分」を押した回数だけ足す**（絶対値。回数の上限なし、記録に残す）。結果は「90分時点の得点」と「延長後の得点」を並べ、自己ベストは90分時点だけ。設定に「はじめから+N分」（配慮用の事前の絶対値）も持つ。倍率は採らない。日商の公開ページに受験上の配慮（時間延長）の記載はなく、本番の制度を模す根拠は取れなかった【要確認】[[web:uiux:r3-fable-kentei-netexam]] [[web:uiux:r3-fable-kentei-report]]。
5. **書き方の規範（決定11）**：**試験の書き方を正、会社の書き方を alt（通るが橋渡しの一言が出る）** とし、表（`B.kubun.examForm`）を1か所に持つ。具体：外注加工賃は「仕掛品／買掛金」が正、「外注加工賃／買掛金→仕掛品／外注加工賃」は alt。減価償却累計額は3年目から個別名（機械装置減価償却累計額）が正、一括の札は alt。前払家賃（勘定）と前払費用（表示）は年度表で切替。法人税等は「法人税、住民税及び事業税」を兄弟1行。工場の労務は10月から「賃金」。普通預金だけの会社に3年目5月で「当座預金」を開く（本試験の多数派の口座）。体験を損なう所だけ例外（数字の規模：会社は万円、検定会場と段3は本試験サイズ）。
6. **実装の順**（9章）：REVIEW-ROUND2 (i) の順（正しさ→記録の正直さ→器→PC→面白さ→範囲→検定会場）を保ち、その中に本書を差し込む。周回の骨（run・meta・段・年の選択・変種の最小＝名前と数字の倍率）は **3年目を書く前** に入れ、3年目以降は最初から変種に対応した書き方（金額は関数）で書く。
7. **オーナーに決めてほしいこと**は10章に14件（推しつき）。大きいのは：年数（5年を推す）、周回の単位（年）、段の切り替え（自分で選ぶ）、役替え周回（監査役だけ入れる）、3年目以降の新科目の上限（月3つに緩める）、外注加工賃と累計額の正の形。

## 2. 設計1：物語で2級の範囲を全部扱う（谷を作らずに）

### 2.1 谷を作らない3つの仕組み

**(a) 論点は判断の帰結としてしか出さない。**
- 判断に付随できる論点（払出方法→先入先出／平均、予定配賦率→配賦差異、配当額→準備金、買収価格→のれん）はそのまま判断にする。
- 手続きだけに見える論点は、**上流の判断の代償**として置く。例：本支店会計は「2号店を支店にして帳簿を分けるか」の判断の代償（分けると支店勘定・本店勘定と合併F/S が要る。分けないと3年目の人事（支店長の権限）が通らない）。精算表は「決算を1枚で確かめたい」の社長の要求。株主資本等変動計算書は「佐藤さんに説明する」。計数の変動は「資本金を大きく見せたい社長」の判断の帰結。
- 判断の形は3種を混ぜる（designer の分類）：戦略型（結果が好みで分かれる）、試算型（試算を読めば分かる）、誘い型（社長の案を止めるか。**社長はときどき正しい**：7.2）。1か月に少なくとも1本、年に戦略型を4本以上。

**(b) 月の型を4つに分け、同じ型を2か月続けない。**
| 型 | 中身 | 1か月の画面の目安 |
|---|---|---|
| 判断の月（decide） | 新しい発見1〜2＋判断1＋日常（自動） | 8〜12 |
| 返りの月（return） | 前の判断の返り（数字＋書類）＋外乱カード1＋想起 | 5〜8 |
| 工場の月（factory） | 工場月報＋判断1＋川を描く＋抜き打ち1（4章） | 6〜9 |
| 締めの月（close） | 決算作業台の区切り（机・時間・1枚に）＋銀行 | 10〜14 |
`month.type` を台本に持ち、lexicon-check が「同じ type が3つ続く」「decide が2つ続く」を失敗にする。

**(c) 判断も外乱もない月を失敗にする。**
sim-check に「各月に `decision` か `shock`（外乱カード）が1つ以上あり、その返り（`returns` か試算の数字）が後の月に存在する」を足す（既存の「返りのない判断」検査の拡張）。

### 2.6 データの形と検査
- `scope.js`：各項目に `ep`（主担当エピソード）、`y`（初出の年）、`m`（月 or 'close1'…）、`dec`（生む判断の id、なければ null）、`ret`（返りの場所：月と数字の名）を足す。`coverage.js` は (1) 全項目に y・m がある、(2) `dec` が台本の decision に実在する、(3) `sim` の disc/docs/kinds が実在する、(4) 年度モードごとに「出ない項目」が正しく除外される、を検査。
- `months[]`：`type: 'decide'|'return'|'factory'|'close'`、`shock: [...]`（外乱カードは `decision` 型のイベントに `shock: true` の印）。
- `sim-check`：(1) 各月に decision か shock が1つ以上、(2) 各 decision に `returns` か後の月の数字の差（試算の `trial` の関数が判断で値を変える）が存在、(3) 同じ type が3つ続かない、(4) 新しい原理が月に1つ以下（lexicon-check）。
- 3年目以降の数字の前提は付録B。sim-check は各年の全枝を「1つ替え＋BE の到達条件」（YEAR2 6.2）で検算。年をまたぐ開始残高は前の年の締め切り後の残高（既存の `S.carry`）。

## 3. 設計2：周回

### 3.1 「満点が取れる状態」の定義と測り方
検定会場の点数は本番の合否の代理に過ぎないので、4つの条件で定義し、成長の記録に **条件の一覧**（満たした／まだ）として出す。点数・順位は出さない（検定会場の中だけ点数）。

| 条件 | 測り方 | 記録 |
|---|---|---|
| A 全項目が「日をあけても書けた」 | 年度モードの範囲内の scope 全項目が lv4（現実の7日以上離れた2回の正解、2回は別の数字・別の問題） | `scopeState`（記録の正直さの直し #3〜#8 が前提） |
| B 本番の形の検定会場で2回続けて100点 | 段3（5.3・3.5）の通し（90分・延長なし・候補は本番形式・解説なし）で2回連続100点。2回は7日以上離れ、大問の組（`examSeen`）が異なる | `S.meta.exams` |
| C 自動仕訳の棚卸が全型正解 | 持ち越した自動仕訳の型をすべて手で正しく書けた（直近の棚卸） | `S.meta.autoInv` |
| D 分かれ道の直近の誤り0 | `fork` ごとに直近の2回が正解 | `S.meta.forks` |

- 「満点」は本番の試験では保証できない（出題の揺れ）。画面の文言は「満点の準備ができた」ではなく「**この4つを満たした**」。theory の懸念（「準備ができた」と読める表示）はここで吸収する。
- A が最も重い。1周（5年）では A は満たせない設計（間隔が要る）ので、**周回が前提**になる。2周目以降の月初の想起と5年目の変種の再来が A を満たす道。

### 3.2 周回の単位と構造
選択肢：
- 案A **「年」を単位に、通しも年の選択もできる（推し）**。1年の終わり（決算→銀行→もしも）が周の区切り。次の年に進む／同じ年を別の変種で遊び直す／別の年に飛ぶ（既習の年だけ）を選べる。遊び直す年の開始残高は「前の周の自分の終わり残高」か「その年の標準の開始残高（変種に合わせて倍率）」を選ぶ。
- 案B 通し（5年）だけを1周とする。ローグライトの「1周は短く」[[web:simgames:r3-fable-wiki-roguelike]] に反し、周回の動機が弱い。
- 案C 「月」を単位にする。短すぎて判断の返り（数か月後）が周をまたぎ、芯が切れる。
推し＝案A。理由：判断の返りは年の中で閉じるか翌4月までに返る（YEAR2 の設計）ので、年が「勝利条件のある短い周」になる。Slay the Spire の「3幕で1周」と同じ長さの感覚 [[web:simgames:r3-fable-wiki-slay-the-spire]]。

周（run）の流れ：
```
年の始め：段を選ぶ（推奨つき）→ 変種が決まる（seed）→ 開始残高を選ぶ → 12か月＋決算 → 銀行 → もしも → 年のふりかえり（前の周の自分と並べる）→ 次へ（進む／遊び直す／検定会場）
```

### 3.3 周回ごとに変わるもの（変種）
論点の骨（固定の出来事：発見・判断・決算・銀行・納税）は変えない。皮を seed から決める。Papers, Please の「台本つきの出来事＋指定しない属性は乱数で埋める」[[web:simgames:designer-papersplease-gd2014]] と同じ作り。

| 変える | 1周目（seed 0） | 2周目以降の例 | 守ること |
|---|---|---|---|
| 会社名・商品・単位 | ピヨ商店・レモネード・杯／本 | コーヒー豆の焙煎（袋）、パン（個）、陶器（点）、文房具（箱） | 軽減税率8％の品（飲食料品）か10％の品かで消費税の行が変わる（陶器は10％）。工場の工程名（殺菌→焙煎／焼成）を lexicon の docWords に持つ |
| 取引先の名前 | B社・D社・ハッピー問屋・みらい銀行 | 名前の表から引く | 架空の名義（EPISODES 3.9） |
| 数字の倍率 | ×1 | ×1.3、×2.7、×10（段3は本試験サイズ） | `n(S, base)`＝`round(base×k, unit)`。検算の不変条件（貸借、消費税の端数、分配可能額の切り捨て、損益分岐点が整数）を seed ごとに sim-check |
| 出来事の順 | 台本どおり | 同じ型（return）の月の中で外乱カードの順を入れ替える。発見の順は変えない | 依存関係（EPISODES 4.5）を崩さない |
| 社長の案の正誤 | 7.2 の固定の表 | seed で「正しい回」が変わる（年に2〜3回） | 正解の理由（reasons）は変えない |
| 需要の変種 | 標準 | 冬の需要が高い年（1,500本が正しい）、D社の注文が大きい年 | 資金繰りは決定論のまま（台本で固定。運ではない） |
| 結末 | 1周目で見た結末は図鑑に | 見ていない結末に届く枝が、年のふりかえりの「もしも」に出る | — |

周回の楽しさとしての狙い：**同じ論点が別の皮で来る驚き**（「前はレモネードの瓶だったのが、今度は陶器の窯。でも仕掛品の箱は同じ」＝転移の練習そのもの）。1周目で「論点の順が先」と見えた2年目も、皮が変わると出来事として読める。

### 3.4 持ち越し（メタ進行）
強くてニューゲームの約束（持ち越すもの／持ち越さないもの／鍵の道具は改めて渡す）[[web:simgames:r3-fable-wiki-newgameplus]]、Hades の「館」（周回のあいだの拠点。周回の中だけの資源と恒久の資源を分ける）[[web:simgames:r3-fable-wiki-hades]]。

| 持ち越す（`S.meta`） | 持ち越さない（`S.run`） |
|---|---|
| 自動仕訳の型（ただし段で外れる）、原理マップの葉、成長の記録（累積）、結末の図鑑（見た／輪郭）、日誌の年表（周ごとに冊が増える）、権限証、検定会場の記録、`S.plan`（想起の予定表）、栞（周ごとに別） | 帳簿（S.L・S.T）、口座・会社の状態、判断（S.decisions）、その年の docLog・fixLog、月の位置 |

- **鍵の道具＝発見イベント**。周回でも発見は飛ばせない。ただし段2以上では「もう知っている」で **本試験の文1問**（検索練習）に置き換えられる。正解なら発見を省略、誤りなら発見を通る。
- 「館」＝**経理部の机**（年の始めと終わりの画面）。机の上に：日誌の年表（周が重なるほど冊が増える）、成長の記録、結末の図鑑、前の周の自分の口座の推移（**自分との比較だけ。他人との比較は禁止**）、先輩の手帳。

### 3.5 段（足場外し）
Slay the Spire の Ascension（勝つたびに1段開く、負の条件が積む）[[web:simgames:r3-fable-wiki-slay-the-spire]] を、会計の学習では「敵の強化」ではなく **支えを後ろから外す**（最後の歩から自分で [[web:learnsci:grosse2015-fading-modeling]]）に置き換える。段は年の始めに自分で選ぶ（成長の記録が推奨を出す。強制しない）。Hades の God Mode の逆（負けるほど支えが増える）は「自動で段を下げる」安全弁として持つ（年の途中で誤りが続くと、森さんが「支えを戻そうか」と1回だけ聞く）。

| 段 | 外れる支え | 開く条件（推奨） |
|---|---|---|
| 0 初回 | なし | — |
| 1 | 名前カードの「たとえば」と手帳の自動表示（押せば出る）、工場月報の「？」印、予想の選択肢→自由入力 | その年を1回通した |
| 2 | 記帳直後の返し（月末までは「書けた」だけ）、ヒントの3段目、書類のタップ入力（キー入力のみ：CBT と同じ）、発見を本試験の文1問で省略可 | その年の項目の7割が lv2 以上 |
| 3 本番の形 | 科目の候補を本試験と同じ（問題ごとのプルダウン）、数字は本試験サイズ（倍率×10）、月初の想起が本試験の文、自動仕訳の提案なし（全部手で。棚卸の代わり） | その年の項目の7割が lv3 以上 |
| 4 監査役 | 役替え（3.6）：自分は森さんの側。社長と新人（AIではなく台本）が書いた帳簿を点検し、誤りを見つけて直す。判断は「指摘するか・意見を付けるか」 | 段3を通した |
| 5 名人 | 延長なし・栞なし・もしもなし・月末の見直しなし（誤りは決算で初めて分かる） | 段3で全項目 lv3 |

- 段は年ごとに記録（`S.meta.tiers[year]`）。段3で通した年だけが「満点の条件 B」に数えられる。
- 段4（監査役）は **交互配置の仕上げ**：社長の帳簿には「条件外の取引を自動仕訳の形でまねた」誤り（既存の監査の点検 `t:'audit'` の拡張）が月に2〜4枚混ざる。これは「似た見た目で違う手順」の判別練習 [[web:learnsci:theory-interleave-rohrer2007]]。
- 段ごとの設定は1か所（`SIM.tiers[]`）に表として持ち、engine は `tier().has('coachNow')` のように問い合わせる。sim-check は「全段の設定が全部の鍵を持つ」を検査。

### 3.6 周回でしか開く判断・結末
| 開くもの | 条件 | 理由 |
|---|---|---|
| 社長の案が正しい回の「乗る」判断の返り（社長を信じて得をする台詞・日誌の矢印） | 2周目以降（1周目も起きるが、2周目は回数が増える） | 1周目は誘い型の学びを守る |
| 役替え周回（段4 監査役、将来：税理士＝課税所得の計算） | 段3を通した年 | 判別の練習 |
| 別の業種の会社 | 2周目以降 | 転移 |
| 結末の図鑑の「輪郭」の結末（例：BE6 解任の本番、BE7 上場審査の不合格、BE9 工場のライン停止） | 該当の枝を選んだ周 | 1周で全結末は不可能。周回で集める |
| 「もしも」に自分が選んだ道の裏側（designer 4位） | 2周目以降は、前の周の自分の判断を「もしも」の起点にできる | 数字は仮定の道で計算し直す（#14 の直し前提） |
| 5年目の変種の再来の「2回目だから社長が正しい」 | 5年目 | 間隔をあけた再出題 |
| CFO の判断（資金調達の組み合わせ：増資・借入・リース・ファクタリング・補助金を1枚の資金計画で） | 3年目を段2以上で通した | 判断の統合 |

### 3.7 検定会場の得点と周回の関係
- 検定会場はいつでも受けられる（現状どおり）。周回との結びつきは3つ：
  1. **落とした論点が次の周の変種に優先して出る**（`S.plan` 経由）。検定会場の結果は「次に何が来るか」を変える（情報としての記録。報酬ではない）。
  2. **段3の通しだけが満点の条件 B** に数えられる。段0〜2の通しは練習（点数は出るが条件に数えない）。
  3. 年のふりかえりに「この年の範囲の検定会場（大問別）」の入口を置き、年の範囲に絞った大問だけで受けられる（範囲を選んで検定会場：PEDAGOGY 4.3 の今後）。
- 得点が周回の報酬にならないようにする：段を開く条件は成長の記録（lv）で、検定会場の点では開かない。

### 3.8 想起・間隔反復を周回に組み込む（S.plan）
REVIEW-ROUND2 (e) の R2（想起の予定表）を周回の芯にする。
- `S.plan`（持ち越す）：項目 `{ id: scope id or kind or fork, due: 実時間, lastOk: 実時間, lastMiss: 実時間, n: 正解の連続数, source: 'doc'|'recall'|'exam'|'auto'|'fork' }`。
- 選ぶ順（毎月の月初の想起・工場の抜き打ち・5年目の変種・検定会場の第1問の候補が同じ表から読む）：①前に間違えた（lastMiss が lastOk より後）②間隔が来た（due ≤ 今。間隔は 7→30→90日と広げる。迷ったら長め [[web:learnsci:theory-spacing-cepeda2008]]）③自動化した型 ④先月の書類。範囲外（ポイント等）は除く。金額は丸い額を指定。
- 周回では、前の周の記録が plan に残るので、2周目の月初の想起は前の周の誤りから出る（現実の間隔が自然に空く）。これが条件 A を満たす道。
- 「日をあけても書けた」は現実の日付のまま（theory の推し）。検査用に時計を進める道具（`?clock=+7d`）を harness 側に用意。
- Her Story 型（社長の質問に答えるために過去の書類を引く）【資料なし・theory の案】は、月初の想起の見せ方の1つとして採る：「去年の家賃、いくら費用にした？」→ 日誌・元帳を引いて答える（段2以上）。

### 3.10 データ・engine・検査・移行
- **S の形（v4）**：
  ```
  S = { v: 4,
    run:  { id, seed, year, tier, startedAt, mi, ei, phase, L, T, decisions, rules(段で効く分), kinds, docLog, fixLog, closes, diary, bm, carry, trapHit, silentIntro, ruleIntro, introSeen, declined, metrics },
    meta: { profileV, mode(2026|2027), pro3, runs: [{id, seed, year, tier, endedAt, rating, ends}], tiers: {year: maxTier}, rules: {kind: {cond, broad, at, run}}, leaves, taught, seenEnds, ifSeen, growth, examLog, exams, examSeen, speedLog, speedRuns, audits, autoInv, forks, plan, diaries: [{run, entries}] } }
  ```
  既存の `S.xxx` の読み書きは `S.run.xxx` へ。`taught` は meta（周回でも教わった語は残る。ただし段2以上で発見を省略した語は `taught` に `via:'skip'` の印）。
- **変種**：`SIM.variant(seed)` → `{ company, product, unit, parties, k(倍率), unit(丸め), order, presRight: Set(decision id), demand }`。台本の金額は `n(S, base)`、名前は `V(S).party('B')`。既存の1・2年目の数字（定数）は、まず `k=1` でそのまま通し、変種対応は段階的に（9章）。
- **段**：`SIM.tiers = [{ id:0, coachNow:true, hints:3, tapInput:true, autoOffer:true, nameExample:true, reportMarks:true, predictChoice:true, ...}, ...]`。engine の該当箇所（docScreen の coach、discoverScreen の hints・predict、autoScreen、reportScreen、hall の候補）が `tier()` を見る。
- **年の始め・終わりの画面**：`deskYearScreen`（館）。年の選択は `D.years[]`（`months` は年で区切られた配列を連結したまま。`S.run.year` の月だけ render）。
- **sim-check**：seed を 0〜N（まず 0・1・2）で回し、各 seed で既存の全検算＋「変種で変わる数字が不変条件を満たす」。段ごとの設定の鍵の網羅。plan の選ぶ順の単体検査（誤り→間隔→自動化→先月）。
- **移行（v3→v4）**：`loadLocal` が v3 を読んだら `migrate3to4(S3)` で `run`＝S3（seed 0、year＝yearOf(mi)、tier 0）、`meta` は S3 の leaves・taught・seenEnds・ifSeen・growth・examLog・exams・examSeen・speedLog・speedRuns・audits を移し、`plan` は examLog と fixLog から作る。保存の鍵は `boki2sim.v4`（store.js の keyOf はそのまま）。v3 の鍵は読むだけで消さない（戻れるように）。決算の区切り「決算（売掛金）」の追加で月がずれた古い保存（HANDOFF）は、`mi` を区切りの id で引き直す表（`MI_MAP`）で移す。
- **lexicon-check**：年ごとの上限（新科目2→3）、段2以上の「本試験の文で省略」に使う問題が既習語だけで読めること。

### 4.1 いまの問題（検査で確かめたこと）
- 2年目10〜1月、facDocs が月ごとに同じ並びの書類を8〜15枚生成し、全部手で書く（year2.js:548-593）。判断は11月 lots・1月 price/line2 だけ。10人全員が谷（#27）。
- 「慣れた」の提案が工場の型に来ない（designer §2-5）。外注加工賃の2段と試験の1段が食い違う（#11）。出荷原価が後入先出（#1）。給料と賃金が月で変わる（#38）。思い出すが工場の型を出さない（retaker）。
- 学びの側：同じ型を同じ回に何枚も書くのは「やり過ぎ」で、見分けの力は育たない [[web:learnsci:theory-interleave-rohrer2007]]。手で全部書くことが定着を生むのではなく、思い出す回数と間隔が生む [[web:learnsci:theory-retrieval-roediger2006]]。

### 4.2 原則
1. **検索練習**：書くのではなく思い出す場面を月に2つ置く（川を描く・抜き打ち）。
2. **間隔**：工場の型は `S.plan` の間隔で戻す（翌月・3か月後・翌年＝4年目・5年目の変種）。
3. **交互配置**：月報に店の行（仕入・給料・支払手数料）を混ぜ、材料／仕入、賃金／給料、外注加工賃（仕掛品）／支払手数料、製造間接費／販管費 の判別を毎月させる。
4. **足場外し**：段0は月報に「？」（今月変わった行）の印、段1から印なし、段2から月報の数字を自分で計算（賃金の消費額・配賦額・完成品原価）、段3は本試験サイズ。
5. **判断**：毎月1つ。返りは差異・在庫・原価率・口座・工員の士気（仕損率）。
6. **自動化の代償**：自動化した型は、月1枚の抜き打ち（別の数字）と、決算②の「製造原価の内訳を白紙から組む」（第4問の勘定記入）で払う。段3では自動化なし。

### 4.3 工場の1か月（新しい型）
```
月初  川を描く：白紙の勘定連絡図（材料→仕掛品→製品→売上原価、脇に製造間接費・差異）に、先月の数字を思い出して入れる（段0は箱の名前あり・数字の候補あり、段2は箱も自分で）。先月の月報は見ない。合わない箱だけ森さんが場所を示す
      判断：今月の判断1つ（4.5）。試算は数字だけ
月中  商業の出来事（あれば1つ。工場の発見のある月は商業の発見なし）
      工場の発見（その月に新しい論点があるとき。5拍）
月末  工場月報（1枚）：工場長から。材料の受払（期首・入庫・出庫・期末、単価と方法）、賃金の計算表（支払・前月未払・当月未払、予定賃率）、経費（検針票・外注・月割）、製造間接費の集計と配賦、完成・検品・出荷（本数と原価、払出方法）、仕損・減損
      → 帳簿の行を組む：型を登録した行は一括確定（自動仕訳と同じ「ルール」の画面で「今月の工場：12行を自動で書いた」）。「？」の行（今月変わった行：新しい論点・数字の変わり方が違う・混ぜた店の行）だけ手で書く。段0は「？」が付く、段1からは自分で見つける（見つけ損なうと月末の見直しで「書類と合わない」）
      抜き打ち：自動化した型から1枚、別の数字で手書き（S.plan が選ぶ）
      月末の予想（できあがりの箱に残る本数、差の箱の向き）→ 締め → 見直し
```
- 月報は1枚だが、行ごとに証憑の元（出庫票・検針票・請求書）を開ける（タップで原本）。「月報から帳簿の行を組む」は、本試験第4問(1)の「資料から仕訳」と第4問(2)の「勘定記入」の両方の型。
- 手で書く枚数：月に3〜6（？の行2〜4＋抜き打ち1＋商業の行1）。10〜15枚から減るが、**思い出す回数は増える**（川を描く1＋抜き打ち1＋？の行）。
- 「慣れた」は工場の型にも効く（kind ごとの `mastered`）。月報の行に kind を持たせ、既存の rules と同じ仕組みで登録。条件外の罠（付録A の表）は月報の行に混ぜる。

- **外注加工賃**：6章の表に従い、請求書の正は「仕掛品／買掛金」、alt「外注加工賃／買掛金」＋月報の「仕掛品／外注加工賃」。

## 5. 設計4：検定会場の時間の延長

### 5.1 本番の制度（確かめたこと）
- ネット試験は会場ごとの随時試験。電卓は四則演算のみ。合否は即時 [[web:uiux:r3-fable-kentei-netexam]]。計算用紙は持ち出せず、答案は返ってこない [[web:uiux:r3-fable-kentei-report]]。
- 受験上の配慮（時間延長など）の記載は、公開の2ページにはなかった。**本番に延長の制度があるかは【要確認】**（会場への申込みの形から、会場ごとの対応と推測されるが推測）。したがって延長は「本番を模す」ではなく「練習の道具」として設計し、画面には常に「本番は90分」と出す。

### 5.2 選択肢の比較と推し
| 案 | 中身 | 良い | 悪い |
|---|---|---|---|
| A 倍率（1.3／1.5） | 開始前に選ぶ | 配慮の制度の一般形に近い | 「あと何分」が計算で分かりにくい。本番にない時間の感覚が付く |
| B 絶対値を開始前に足す（+5／+10／+30分） | 開始前にボタンを押した数 | 分かりやすい。配慮用に向く | 最初から長い時間に慣れる |
| **C 90分の鐘＋「+5分」ボタン（推し）** | 本番と同じ90分で鐘が鳴り「ここで終える／+5分」。押した数だけ延長（上限なし）。記録に「90分時点の得点」「延長後の得点」「延長 +N分」を残す | 本番の時間の圧をそのまま体験し、足りなかった分が**自分の数字**で分かる（「あと10分あれば第3問が埋まった」）。自己ベストは90分時点だけ | 鐘のあとに集中が切れる人がいる（→ 鐘は音なしの帯の色の変化＋1行） |
| D 大問ごとの目安時間の延長 | 大問別練習で目安を伸ばす | 大問練習には合う | 通しには向かない |
推し＝**C を主、B を設定（配慮）として併設**。D は大問別練習（既存の PART_MIN）に「目安を+5分」として足す。オーナー案（1分・5分・10分のボタン）は C の「+5分」を「+1／+5／+10」の3つにしてもよいが、**ボタンは1種（+5分）** を推す：押した数＝延長の単位が揃い、記録の比較が楽になる。

### 5.3 実装
- `hall.js` の `H.play`：`end` を可変に。`tick()` で `left<=0` のとき、`extendable`（段3・段5以外、または設定で許可）なら `grade(true)` の代わりに `bell()`：帯を赤に、「90分。ここで終える／+5分」の2ボタン（問題は操作できる。採点はまだ）。`+5分` で `end += 5*60000; ext += 5`。90分時点の答案は `snapshot90 = 全 comps の answered 状態と答え` をその場で写す（採点は終了時に2回：snapshot90 と最終）。
- 結果：`rec = { ..., score90, score, ext(分), mode:'timed' }`。「これまでの成績」の表に延長の列。自己ベストは `score90`。
- 設定（タイトルの「受験する年度・ふりがな・文字の大きさ」の並び）：「検定会場の時間：はじめから +N分（0／10／20／30）」。段3では0に固定（満点の条件 B は ext=0 かつ事前延長0）。
- 電卓は四則演算のみ（既存の `calc` を確認。メモリーキー・税込キーがあれば外す）。
- 延長の記録は `S.meta.exams` に残り、成長の記録には「延長なしで通した回数」を1行で出す（点数は出さない）。
