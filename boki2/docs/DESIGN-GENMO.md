## 2. 全体の順序（決算の区切り）
```
3月            …month9(3)、返済、「決算」の台詞、d-stock（売上原価）、stock（繰越商品 50,000／仕入）  ←棚卸表を「帳簿で計算した残り」に直す
決算           desk（7枚）→ fee-3 → d-genmo → genmo（棚卸減耗損 2,000）→ hyoka（商品評価損 1,600）   ←新
決算（売掛金） d-allow → allow                                                                     ←d-allow・allow をここへ移す（新しい区切り）
決算（つづき） d-dep → kessan → … → dep-entry
決算（税金）   tax1（もうけから自動で −3,600 を反映）
翌年4月        report（繰越商品→商品 46,400）→ bank → closing1 → …
```
- 理屈：売上原価は「帳簿の数×仕入れ値」で先に確定（期末商品棚卸高＝帳簿棚卸高）。次に実地と見比べて、数の差（減耗）→値段の差（評価損）の順に繰越商品を直接へらす（2級の標準の順序。先に数、あとで値段）。
- 決算書への返り：B/S 繰越商品（表示は「商品」）46,400（＝砂糖・紙コップ20,000＋きれいな240個×100＋傷んだ40個×60。実地×低い方の値段で一発検算）。P/L 商品評価損 1,600 は売上原価の内訳（kubun.js の put('売上原価', …商品評価損) 済み）、棚卸減耗損 2,000 は販管費（kubun.js の plOf の既定「費用→販管費」で自動）。1年目の決算書に段階利益を入れる改善12（kubunView を1年目に使う方針）のとき、売上総利益＝売上−（仕入の残高＋商品評価損）になる。税金の見込み taxOf・結末の S.__ni・銀行の講評は帳簿から計算するので自動で追随。
- 区切りを分ける理由（lexicon-check の約束）：いま「決算」は新しい科目が貸倒引当金・貸倒引当金繰入の2つで満杯。棚卸減耗損・商品評価損を足すと4つ。3月も繰越商品で1つ使っているので2つ足すと3つ。だから机のある「決算」に倉庫（2科目・発見1）を置き、貸倒れを「決算（売掛金）」（2科目・発見1）に出す。新しい原理はない（P4は9月の d-truck で出ている）。
- 注意：D.months に1つ増えるので、それ以降の `mi` が1ずれる。途中保存（S.mi）を持つ人は位置が狂うので、`fresh()` の `v` を上げて古い保存を捨てるか、読み込み時に mi を直す。year2.js の返り（SIM.returns）は y・m・seg で指すのでそのまま。sim-check の Y1REPS・flat は index を再計算するので変更不要。
