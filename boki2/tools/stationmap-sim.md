## 起動と入力

Node.js 18以上、外部パッケージ・ネットワーク接続は不要。リポジトリの根で実行する。

```sh
node boki2/tools/stationmap-sim.js --help
node boki2/tools/stationmap-sim.js --self-test
node boki2/tools/stationmap-sim.js --K 8 --N 300 --seed 0 --workers 4 \
  --out boki2/docs/analysis/stationmap-sim/initial
node boki2/tools/stationmap-sim.js --override '{"rent.R0":30000,"rent.b":0.4}' \
  --K 8 --N 300 --seed 0 --out boki2/docs/analysis/stationmap-sim/changed
```

- `--params`: `{v,lo,hi,src}`形式の置き値ファイル。既定は`tools/data/stationmap-params.json`。
- `--override`: 項目名と値のJSON、またはそのJSONファイル。部分上書き。
- `--K`: 開店前に見える軒数・型・営業時間・家賃のくじの回数。検査④には2回以上必要。
- `--N`: 各候補地×開店くじごとの将来の乱数周回。既定300。較正にも同じNを使う。
- `--seed`: 0〜2^32−1。開店、参入、天気と仕込み、ボットの学習用将来を別の列にする。
- `--workers`: Nodeのworker数。エージェントの委任ではない。出力順・乱数は変わらない。
- `--limit`: 道具の試運転用の候補地数。本測定の合格の根拠には使わない。
- `--cache`: 途中結果の置き場。既定は作業場所の`work/stationmap-cache/`。
  入力・道具・ゲームのハッシュで分離する。同じコマンドで続きから回る。

`null`は設計書にない値。探索幅の`null`は自由に探索してよいという意味ではない。
段と距離の幅は個別係数の上下限でなく比の制約。`foot.tierRatio`・`foot.distRatio`に転記した。
初期の閉店削減費、保証金の確率、造作の分布、λ一括倍率の探索幅、未定の設計判断を埋めない。

## 出力と物差し

- `report.md`: 期待値・乱数込みそれぞれ①〜⑩の10行と、駅の段別・属性別の中央値。
- `report.json`: 数値・判定・理由、全入力、較正結果、ゲームと道具のSHA-256。
- `sites.csv`: 候補地×開店くじ×測定種別の客数・需要・年の営業利益・月の家賃・競合・上限越えなど。

期待値の列は**週の天気・仕込み誤差を止めた条件付きの経路**。
開店のくじ・参入・ライバルの営業時間はseed付きであり、全乱数を積分した無条件期待値ではない。
乱数込みの列は各候補地×開店くじでN周を実行する。①は各周の3年目平均客数をプールした中央値。
候補地平均の中央値へすり替えない。段別・属性別の表は候補地平均の中央値。
④は候補地内/全体の分散（乱数込みでは各周の利益も含む）。K=1は判定不能。
③はくじと将来を平均した候補地の上位50、⑤は開店くじごとの上位50。
⑧の分母は3年目の平均需要が70人を越えた候補地数。分母0は判定不能。
⑨は属性内の3年目平均客数/1年目平均客数を住宅地と繁華街で割った比。
相関の参考値は同順位に平均順位を付けるSpearman。

⑥の仮実装は規則に合う候補地から一様に選んだ36か月累計営業利益と、
独立したN周の学習用将来から期待累計利益最大を推定して選ぶボットの利益を比較する。
学習用と評価用の将来のseedは分離し、実現した未来を見て選ばせない。
この定義は相談中で、承認前は合格判定しない。
⑩の仮実装は基準の老舗に3年目の初月に50円値下げする介入を置いた参考値。
既存ゲームに設計書のいう値下げ札がなく、金額と時点も未指定なので、札の検査の合格とはしない。

## 探索

例えば次のJSONを`work/search.json`へ保存する。

```json
{
  "mode": "grid",
  "fields": {
    "rent.R0": [25000, 28000, 40000],
    "rent.b": [0.25, 0.4, 0.55],
    "hours.closedSaving": [160000, 200000],
    "regular.retain.jutaku": [1.1, 1.3, 1.5],
    "regular.retain.hanka": [0.5, 0.7, 0.9]
  }
}
```

```sh
node boki2/tools/stationmap-sim.js --search work/search.json --K 8 --N 300 --seed 0 \
  --out boki2/docs/analysis/stationmap-sim/search
```

`mode: "random"`は`trials`回、各配列の最初と最後の間の一様分布で探す。
格子は列挙した値の直積。探索値はパラメータ表の幅を検査し、幅がない項目はエラーにする。
λの段の一括倍率は幅の回答後に探索へ足す。b=0.25/0.4/0.55の試行有無も記録する。
各試行の`trial-0000/`等に全出力、`search.json`に全入力の組・通過組・外れた検査の値と件数、
`search.md`に一覧を出す。未測定を含む組は通過組に入れない。赤字のくじの割合も報告し、4.4の50%を越える組は許容する組に入れない。
結果が通ってもゲームの置き値には採用しない。

## 差し込みの方法と自己検査

`sim-ramen.js`と同じく`ramen-files.js`のstory順でゲームを読む。
`world.js`の文字列はメモリ上だけで、需要・容量の配分・費用の差額・常連・相場の箇所にフックを入れる。
差し込み位置がちょうど1か所でなければ停止する。ゲームのファイルは書かない。
需要式・月次の評判・ライバルの決算・一杯の古びはゲームを使う。
較正・候補地の周回では札と町の行事を止める（回帰台本との条件をそろえる）。
全候補地用の潜在客と価格は候補地ごと、常連は昼夜別、ライバルの決算は月に1回。
営業利益は3年目12か月の合計、客数と需要は1日あたりの3年目12か月平均。

`--self-test`は入力範囲・確率の和・未知キー・探索seed、元のゲームとの36か月同値、
昼だけライバルの夜の分母、架空6属性での各10行、並列数1/2と保存再開のバイト一致を検査する。
テスト中の架空の閉店削減費18万円は、本測定の初期値に採用していない。

## やっていないこと・浅いままの所・推測の所

- 初回の版0.5本測定、λを含む指定項目の探索、N=300の全候補地の表は相談の回答待ち。
- 較正中の参入と基準の老舗の営業時間、参入の時点、閉店帯の常連、増員時の削減費が未確定。
- ⑥の方策、⑨の集計の読み方、⑩の札・金額・時点は測り方の判断を含む。PRで合意が必要。
- 保証金と造作の未指定分布は実装していない。営業利益では初期キャッシュ・倒産率を測れない。
- 期待値列は条件付き経路、ゲームの札や行事を含む全経営の期待値ではない。
- 元の式との同値・再現の検査は道具の検査であり、全10基準を満たす置き値の存在証明ではない。
