# 出店の地図の測定ツール（版0.6）

依頼書 `docs/CODEX-TASK-stationmap-sim.md` と設計書版0.6を測る。
定義の確定はPR #11の6570645286・6619705662。ゲームのファイルは書き換えない。

## 起動

`--entry-mode pin`でも同じ3コマンドを回し、出力先の末尾をpinにする。

Node.js 18以上。検証環境はNode.js v24.19.0。外部パッケージ・通信は不要。
リポジトリの根から実行する。

```sh
node boki2/tools/stationmap-sim.js --self-test
node boki2/tools/stationmap-sim.js --K 2 --N 300 --seed 0 --workers 4 \
  --entry-mode station --cost-mode design --out boki2/docs/analysis/stationmap-sim/v06-initial-station
node boki2/tools/stationmap-sim.js --K 2 --N 300 --seed 0 --workers 4 \
  --entry-mode station --cost-mode part-full --out boki2/docs/analysis/stationmap-sim/v06-part-full-station
node boki2/tools/stationmap-sim.js \
  --search boki2/docs/analysis/stationmap-sim/v06-search-spec.json \
  --K 2 --N 3 --seed 20261104 --entry-mode station --workers 4 \
  --out boki2/docs/analysis/stationmap-sim/v06-search-station
```

- `--params` は置き値のファイル。既定は `tools/data/stationmap-params.json`。
- `--override` は `{"rent.R0":30000,"rent.b":0.4}` のような部分JSONか、そのファイル。
- `--K` は開店前の軒数・型・営業時間・家賃のくじの回数。④には2回以上必要。
- `--N` は各候補地×開店くじの評価用の乱数周回数。較正とボットの学習用にもN周を使う。
- `--seed` は0〜2^32−1。開店・参入・天気と仕込み・ボット学習用の将来を別の列にする。
- `--entry-mode station|pin` は未定の参入場所の強い/弱い両端（6620053704）。最終合否・採用候補ではない。
- `--workers` はNodeのworker数。並列数で乱数・出力の順は変わらない。
- `--limit` は試運転用の候補地数。全候補地の合格の根拠には使わない。
- `--cache` は途中結果の置き場。既定 `work/stationmap-cache/`。入力・道具・ゲームのハッシュで
  分け、候補地ごとに保存する。同じコマンドで中断した続きから再開する。
- `--no-memo` は一杯の純粋な読み出しのメモ化を止める。元の関数と出力を照合する検査用。

置き値は `{v,lo,hi,src}`。`null`の上下限は自由に探せるという意味ではない。
段・距離の幅は比の制約で、係数そのものと混ぜない。決定の出どころはコメントIDも残す。

## データと較正

版0.6の入力は `docs/analysis/stationmap-sim/tokyo23-v06.js`。
元ブランチのデータblob `9ca42219913900bf7340cf2cef0d0cd97489598d` をそのまま固定した。
452駅・981候補地・閑静枠98本・day欠損4本。ゲームの `js/data/tokyo23.js` は編集しない。
各候補地のday欠損を属性のday中央値で埋め、
`Nt=max(0.05,1-day+κ*(food/0.0708-1))`、`L=day/(day+Nt)` を使う。
中央の2値がある場合は平均する。属性ごとの固定のLは使わない。

基準は段3・距離中・商店街・老舗1軒を通し固定。参入なしで組を36か月固定し、
天気・仕込みを含むN周の3年目平均客数の中央値が44人/日になるP_refを二分法で求める。
較正用のLは商店街の274候補地のLの中央値をデータから求める（6619705662で合意）。
値と母数を出力する。較正は候補地ごとにやり直さず、各置き値の組につき1回。

## 版0.6の参入・費用・常連

参入確率は `p0*λ+p1*s`。sは直前の最大3か月の客数の平均と現在の評判で計算し、
開店時点の観測がないときは0。抽選月に求人、翌月に工事、翌々月に開店。
営業中の軒数が5なら開けず、撤退枠には再参入できる。確率0.5で自店と同じ型、
残りは属性の重み。ゲームのnormal型はライバルの老舗に対応する。
各候補地は「そこへ1店出した場合」の反実仮想。参入はその駅の競争として需要の分母に加える。
`station`は同駅の参入すべてが分母に入る。`pin`は駅の全ピン（自店を含む）から
1本を等確率で選び、自店のピンに入ったときだけ分母に入る。他ピンへの参入は件数を別記し、
自店の5軒にも数えない。他ピン店の損益・撤退・枠は測らない。初期競合は両方とも候補地別に引く。
この両端は版0.6の未定の所を挟む測定で、最終合否・採用候補ではない。
ピン間の競争の中間の減衰係数は追加していない。

新規・常連・容量を昼夜に分け、評判は同じ1店舗のものを使う。閉めた帯の常連は通常のchurnで
減り、切替月だけ閉めた帯に+1%。自店だけretain/churnの属性倍率を使い、ライバルの決算は
昼夜を合わせた客数で元のsettleを月1回呼ぶ。撤退も元のsettleを使う。

`--cost-mode design`は版0.6。昼4時間・夜5時間（置き値、幅なし）。パート1人なら閉めた
時間の割合だけ給料を減らし、パート2人なら閉めた帯の1人分20万円を減らす。
光熱は固定分・変動分を合わせたゲームの費用を同じ時間の割合で減らす。
`--cost-mode part-full`はパート1人でも閉めた帯の給料20万円が全部減る参考条件。
**設計書の外**と出力し、本測定の合格組には入れない。探索の項目にも入れない。

part-fullは同じ乱数経路を使う。札・要因分解を止めた本測定では、この費用差は客数・評判・
参入に影響しないので、designのキャッシュがあれば閉じた帯の残りの給料を各月の利益に
加算して求める。直接の36か月計算でも客数・参入の一致と利益差を自己検査している。
この推定は初期キャッシュ・倒産率には使わない。

保証金は6/8/10か月が各1/3、造作は新店内装×0.3・上限300万・10%で0と転記。
今回の物差しは営業利益なので、これらを測定したキャッシュや倒産率としては出さない。

## 出力と10検査

`report.md` は期待値と乱数込みの各10行、段別・属性別の中央値。
`report.json` は全入力・較正・ハッシュ・世界ごとの⑤の数。
`sites.csv` は候補地×くじ×測定種別の客数・需要・利益・家賃・競合・上限越えとday/food/L。

期待値は**週の天気・仕込み誤差を止めた条件付きの経路**。参入と営業時間のくじはseed付きで、
全乱数を積分した無条件期待値ではない。乱数込みは各候補地×開店くじでN周を回す。
町の行事と通常の山札は、旧回帰台本と同じく止める。⑩だけ定義された介入を入れる。

- ①は各周の3年目平均客数をプールした中央値。候補地平均の中央値にすり替えない。
- ②は3年目の平均需要が70人を越える候補地割合。目標なし。
- ③はくじと将来を平均した候補地の上位50。段4種・属性4種・住宅地か商店街8か所以上。
- ④は候補地内/全体の利益分散。乱数込みはN周の揺れも含む。K=1は測定不能。
- ⑤はK世界（乱数込みではK×N世界）それぞれの利益の上位50の、3年目末に0軒の数。
  すべて15以下で合格。開店前の軒数にしない。最小・最大・平均・15超の世界数も出す。
- ⑥は3規則内の一様選択による36か月累計利益と、独立の学習用N周で期待累計利益最大を
  推定して選んだ立地の、別の将来での利益を比べる。3規則すべて85%未満。上手の利益が
  0以下なら比を定義できず測定不能にする。実現済みの未来で立地を選ばない。
- ⑦は候補地平均でオフィスの昼だけ・繁華街の夜だけが通しより得な割合。各20%以上。
- ⑧の分母は平均需要が70を越える候補地。増員が得な所30〜70%。分母0なら測定不能。
- ⑨は属性ごとの平均客数の3年目/1年目を、住宅地と繁華街で割った比。1.3以上。
- ⑩は基準の通しの老舗をt=24〜26の3か月だけ50円下げ、t=27で戻す。乱数を対にし、
  介入3か月平均の自店客数が減るかを見る。3年目全体の平均も添える。

4.3の効きの向きも10行の外で報告する。基準に通しの1軒を追加し、同じ型のほうが
違う型より大きく減る・どちらも需要−5〜−40%かを調べる。
合格組は①〜⑩とこの向き、4.4の赤字のくじ50%以下、design条件を満たすもの。

## 探索

`v06-search-spec.json`は需要側6係数の乱数20組と、家賃R₀2通り×b3通りの
格子6組との直積、合計120組。station/pinそれぞれ同じ組を測る。K=2・N=3の探索用設定で、
N300の初期値より将来の推定誤差が大きい。仮の目標適合組があればN300で追加確認する。
費用は設計の式へ置換されたので16〜20万円の独立した探索軸は残さない。

格子は `mode: "grid"` と `fields` の値の配列の直積。乱数は `mode: "random", trials: 回数` で
各配列の最初と最後の間の一様分布。`gridFields`は乱数組それぞれに直積する格子。
`mandatoryValues`は先頭から指定する乱数組へ必須値を代入する。探索幅外は停止する。

家賃だけの差は需要・評判・参入・他店の損益に影響しない（札・要因分解なしの条件）。
道具は同一の需要経路に元ゲームと同じ丸めの家賃差を投影する。3年目利益・36か月累計利益・
学習用の利益・周ごとの利益をそれぞれ補正し、全120組のランキングと検査を取り直す。
直接36か月を計算した結果と全フィールドが1e-6未満で一致する自己検査を持つ。
この計算再利用で、試した家賃の組や候補地を省略していない。

各組の全入力・出力はtrial-0000等、一覧はsearch.json/md。
`passing` / `allPass`はその端条件の目標適合という仮判定であり、採用候補ではない。
`adoptionEligible`は常にfalse、`assessmentScope`に未確定の両端である旨を保存する。
通過組が0でも試した組数と外れた検査・値・件数を出し、幅全体に解なしとは結論しない。
見つかった組をゲームに採用する操作はしない。

## 回帰と再現

```sh
node boki2/tools/stationmap-sim.js --regression --K 8 --seed 0 \
  --out boki2/docs/analysis/stationmap-sim/regression-v04
```

旧データはtokyo23-v04.js（コミット487aa6a、blob 130bc3b）。DEFは元のlib.jsから読み、
453駅965候補地・旧ポアソン・基準cheap+shinise・旧相場更新で測る。
中央値64.72237075148459・上限越え69.53367875647669%・旧算法相関−0.006158793781421958。
元台本の標準出力全体も保存済み出力とバイト一致。未丸めの参照値をregression-reference.jsonに
保存し、3値すべて元値の2%以内で照合する。同順位を平均順位にした相関は+0.026745373988640308。
新測定の相関は平均順位、旧回帰だけ旧算法を比較に使う。

`--self-test`は元ゲームとの36か月同値、較正、2か月予兆、時間別費用、3か月値下げと復元、
part-fullの費用差、昼だけライバルの夜の分母、架空6属性の各10行と並列数/保存再開の一致を調べる。
一杯の同じ部品の品質・原価・相性の読み出しは元の関数で求めた数をメモ化する。
`--no-memo`で元の読み出しに戻してもJSON/CSVがバイト一致することを別の試運転で確認した。

## やっていないこと・測定条件の限界

- 初期キャッシュ・保証金・造作・倒産率を営業利益の物差しで代用していない。
- 昼夜に別の評判を持つ比較台本とは違い、同じ店舗の評判を使う。
- 比較台本の即月参入・固定光熱だけの削減・未来の実現利益順の⑥・くじ単位の⑧とは条件が違う。
- 探索は120組（需要側20組×家賃6組）であり、範囲の全数検査でも解なしの証明でもない。
- 期待値列は条件付き経路。通常の札や行事を含む経営全体の期待値ではない。
