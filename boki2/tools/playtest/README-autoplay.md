# ラーメン版の自動プレイ検査

画面の `data-*` を Playwright で押して、プロローグから翌4月まで通す。台本の正解は読むが、開始後の `window.__sim` への書き込み、画面を飛ばす呼び出しはしない。

```sh
node boki2/tools/playtest/bot-runs.js --style idle,random,skilled --seeds 0-29 --width 1280
node boki2/tools/playtest/bot-runs.js --style idle,random,skilled --seeds 0-9 --width 390
```

既定の並列数は4。同じコマンドを再実行すると、完成済みの周を飛ばす。失敗した周も残し、集計から除かない。出力は既定で `work/bot-runs-1280.jsonl`（幅390は390）。別の結果と比較するときは `--output work/repeat.jsonl` を指定する。コードや検査条件が変わった場合は古い出力へ継ぎ足さず、新しいファイルを指定する。

3,000周は `--seeds 0-999`（3種類×1,000seed）で指定できる。受入検査で3,000周の実行は不要。

## 実行環境

Node.js、Playwright、Chromium が必要。既定は `/opt/node-tools/node_modules/playwright` と `/opt/pw-browsers/chromium`。別の環境では `--playwright MODULE --chromium PATH`、または `PIYO_PLAYWRIGHT` / `PIYO_CHROMIUM` で指定する。harness.js も同じ環境変数を読む。

ゲームは一時的なlocalhostのHTTPサーバーで提供する。ブラウザはこのサーバー以外への要求をすべて拒否し、service workerも無効にする。外部フォントは取得しない。各周は新しいブラウザコンテキストで、保存の混在を避ける。

## 打ち方

- `idle`：作戦の机は「前月のまま」。開店はパート1人、看板なし、標準の問屋、一杯は既定。札に「据え置き／しない／見送る」等があればそれを選び、なければ先頭。
- `random`：seed付きの同じ乱数列で、画面で選べる手・札・一杯の部品を選ぶ。時間不足で無効な手は選べない。具は画面の上限に従う。
- `skilled`：`sim-ramen.js` の smartX の3方針（常連と地図／一杯と衛生／集客と席）を、画面で開いている手へ写す。既定の方針は `floor(seed/3)%3`。`--strategy 0`（または1・2）で固定できる。1回に変更できる値段・人数の幅、解禁時期、時間の予算に従うため、純粋関数のsim試験と完全に同じ手にはならない。選べなかった手を状態への直接書き込みで補わない。札は画面に出る試算の幅の中点 `(cashMin + cashMax) / 2` が最大の選択肢、同点または試算なしは先頭を選ぶ（PR #3で承認）。

作戦の手直しがあるときは麺を1か所だけ変える。札・開店・作戦の規則は結果を見て調整しない。正答の必要な書類・作業台・ふりかえりは、打ち方にかかわらず台本の答えを使う。`--error-rate 0.1` なら各対象の初回に10%の確率で意図的に誤答し、再試行できる画面はその後正答する。誤答の乱数は経営の乱数から独立している。

## seedと保存

PR #3 の取りまとめ役の承認に従い、ページを開く前だけv4形式の保存をlocalStorageへ置く。runには `{seed}` だけを入れ、月位置・出来事位置・世界・帳簿・判断を置かない。通常のstore.js読み込み後に `initialSaveValid`（seed一致、v4、保存警告なし、未開始）を検査する。

## 出力と再現

- `*.jsonl`：1周1行の結果。seed、打ち方、方針、倒産、救済不能の検出、各月の営業利益、初黒字月、翌4月の帳簿口座、最終世界口座、ページ／操作エラー、進行停止、横はみ出し、手の数、S.choices、判断を含む。
- `*.timing.jsonl`：同じrunKeyに所要秒数・日時・ブラウザパス・並列数・失敗時の診断を結ぶ。実測時間は再現比較の対象外。
- `*.summary.json`：打ち方別の倒産・救済不能・停止・エラー・はみ出し・初黒字月分布・翌4月口座中央値。平均所要秒数×3,000÷並列数の見積もり。
- `*.actions/`：周別の操作ログ。`plan`・`bowl`・`decision`・`report`・`debrief`・`fork` をkindとして、前後の選んだ手・S.choices等を残す。harness経由のautoでも同じkindをハッシュ鎖のログへ記録する。人のclickにも元操作を指すkind行を追加する。

結果JSONはrunKey順に並べ、行全体を比較する。所要時間を含めない方式はPR #3で承認済み。並列数・完了順は結果に含めない。コード・画面のハッシュを含めるので、異なるゲームの測定を混ぜない。

倒産と操作の停止は別。`deadEnd` は作戦確定時または最終時点で既存の `world.rescueFails` を世界の複製へ適用した値。`stuck` は未対応画面・操作失敗・同一画面での停滞・ステップ上限。倒産で終わった周の未到達月・翌4月はnullとし、ゼロ円や成功に置き換えない。

SIGINT/SIGTERMでは現在の周を保存してから停止する。強制終了でJSON末尾が切れた場合はその末尾を `.partial` に保存して再開する。中間行の破損・重複したrunKey・条件の不一致はエラー。同じ出力への二重起動は `.lock` で拒否する。強制終了後のlockは記載PIDの停止を確認してから除去する。

`--max-steps`（既定2400）、`--timeout`（1操作の上限、既定10000ms）も指定可能。失敗周を含む実行は終了コード1、正常終了は0、中断は130。はみ出しは表に残し、0件に偽装しない。
