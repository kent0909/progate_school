# ラーメン版の自動プレイ検査

画面の `data-*` を Playwright で押して、プロローグから翌4月まで通す。台本の正解は読むが、開始後の `window.__sim` への書き込み、画面を飛ばす呼び出しはしない。

```sh
node boki2/tools/playtest/bot-runs.js --style idle,random,skilled --seeds 0-29 --width 1280
node boki2/tools/playtest/bot-runs.js --style idle,random,skilled --seeds 0-9 --width 390
```

既定の並列数は4。同じコマンドを再実行すると、完成済みの周を飛ばす。失敗した周も残し、集計から除かない。出力は既定で `work/bot-runs-1280.jsonl`（幅390は390）。別の結果と比較するときは `--output work/repeat.jsonl` を指定する。コードや検査条件が変わった場合は古い出力へ継ぎ足さず、新しいファイルを指定する。

3,000周は `--seeds 0-999`（3種類×1,000seed）で指定できる。受入検査で3,000周の実行は不要。

## 実行環境

Node.js、Playwright、Chromium が必要。既定は `/opt/node-tools/node_modules/playwright` と `/opt/pw-browsers/chromium`。別の環境では `--playwright MODULE --chromium PATH`、または `PIYO_PLAYWRIGHT` / `PIYO_CHROMIUM` で指定する。harness.js も同じ環境変数を読む。

ゲームは一時的なlocalhostのHTTPサーバーで提供する。ブラウザはこのサーバー以外への要求をすべて拒否し、service workerも無効にする。外部フォントは取得しない。各周は新しいブラウザコンテキストで、保存の混在を避ける。

## 打ち方

- `idle`：作戦の机は「前月のまま」。開店はパート1人、看板なし、標準の問屋、一杯は既定。札に「据え置き／しない／見送る」等があればそれを選び、なければ先頭。
- `random`：seed付きの同じ乱数列で、画面で選べる手・札・一杯の部品を選ぶ。時間不足で無効な手は選べない。具は画面の上限に従う。
- `skilled`：`sim-ramen.js` の smartX の3方針（常連と地図／一杯と衛生／集客と席）を、画面で開いている手へ写す。既定の方針は `floor(seed/3)%3`。`--strategy 0`（または1・2）で固定できる。1回に変更できる値段・人数の幅、解禁時期、時間の予算に従うため、純粋関数のsim試験と完全に同じ手にはならない。選べなかった手を状態への直接書き込みで補わない。札は画面に出る試算の幅の中点 `(cashMin + cashMax) / 2` が最大の選択肢、同点または試算なしは先頭を選ぶ（PR #3で承認）。

作戦の手直しがあるときは麺を1か所だけ変える。札・開店・作戦の規則は結果を見て調整しない。正答の必要な書類・作業台・ふりかえりは、打ち方にかかわらず台本の答えを使う。`--error-rate 0.1` なら各対象の初回に10%の確率で意図的に誤答し、再試行できる画面はその後正答する。誤答の乱数は経営の乱数から独立している。

## seedと保存

PR #3 の取りまとめ役の承認に従い、ページを開く前だけv4形式の保存をlocalStorageへ置く。runには `{seed}` だけを入れ、月位置・出来事位置・世界・帳簿・判断を置かない。通常のstore.js読み込み後に `initialSaveValid`（seed一致、v4、保存警告なし、未開始）を検査する。

## 出力と再現

- `*.jsonl`：1周1行の結果。seed、打ち方、方針、倒産、救済不能の検出、各月の営業利益、初黒字月、翌4月の帳簿口座、最終世界口座、ページ／操作エラー、進行停止、横はみ出し、手の数、S.choices、判断を含む。
- `*.timing.jsonl`：同じrunKeyに所要秒数・日時・ブラウザパス・並列数・失敗時の診断を結ぶ。クリックごとに画面の月位置・出来事の種類/id・取っ手・成功可否・所要ミリ秒を `clickTimings` に残す。計測対象はPlaywrightのclick本体（表示・安定待ちを含む）で、前後の状態読み出しやログ保存は含めない。実測時間は再現比較の対象外。
- `*.summary.json`：打ち方別の倒産・救済不能・停止・エラー・はみ出し・初黒字月分布・翌4月口座中央値。平均所要秒数×3,000÷並列数の見積もり。クリック時間の中央値・95%点（昇順のceil(n×0.95)番目）・最大値、画面の種類×取っ手を最大時間の降順に並べた上位5組も出す。並列数ごとの集計を別に残す。1並列の比較は同じ条件を `--parallel 1 --output work/serial.jsonl` で回す。
- `*.actions/`：周別の操作ログ。`plan`・`bowl`・`decision`・`report`・`debrief`・`fork` をkindとして、前後の選んだ手・S.choices等を残す。harness経由のautoでも同じkindをハッシュ鎖のログへ記録する。人のclickにも元操作を指すkind行を追加する。

結果JSONはrunKey順に並べ、行全体を比較する。所要時間を含めない方式はPR #3で承認済み。並列数・完了順は結果に含めない。コード・画面のハッシュを含めるので、異なるゲームの測定を混ぜない。

倒産と操作の停止は別。`deadEnd` は作戦確定時または最終時点で既存の `world.rescueFails` を世界の複製へ適用した値。`stuck` は未対応画面・操作失敗・同一画面での停滞・ステップ上限。倒産で終わった周の未到達月・翌4月はnullとし、ゼロ円や成功に置き換えない。

SIGINT/SIGTERMでは現在の周を保存してから停止する。強制終了でJSON末尾が切れた場合はその末尾を `.partial` に保存して再開する。中間行の破損・重複したrunKey・条件の不一致はエラー。同じ出力への二重起動は `.lock` で拒否する。強制終了後のlockは記載PIDの停止を確認してから除去する。

`--max-steps`（既定2400）、`--timeout`（1操作の上限、既定30000ms）も指定可能。失敗周を含む実行は終了コード1、正常終了は0、中断は130。はみ出しは表に残し、0件に偽装しない。

## 1年目の0円書類の確認（PR #3 / 承認6384464617）

台本の `t: 'doc'` を確認し、既存の `when` を保った上で、正解の0円行と表の0円の金額行を除く。正解が全額0円なら出さない。世界の計算・帳簿の金額は変えない。

|書類|0円になる条件|対応|
|---|---|---|
|現金売上・カード売上・カード入金|売上またはカード分が0、手数料の丸めが0|全額0は非表示、部分0行を除去|
|クーポンの値引き|値引き対象の現金売上が0|既存の利用条件＋全額0は非表示|
|材料の現金／掛け仕入・買掛金支払|買う材料が0、税額の丸めが0|全額0は非表示、部分0行を除去|
|給料支払|パート0人・家族0人|既存の金額条件を維持、0行を除去|
|光熱費・家賃|固定費の現行設定では通常正。ただし入力の計算結果が0の場合|全額0は非表示、部分0行を除去|
|借入返済|元本は固定で正、利息だけ0の可能性|部分0行を除去（元本は保持）|
|チラシの請求・支払|チラシを選ばない|既存whenを維持、全額0も非表示|
|まとめ買いの小麦|まとめ買いなし|既存whenを維持、全額0も非表示|
|期末在庫 stock|通常材料の残りもまとめ買いの残りも0|全額0は非表示|
|棚卸減耗 genmo|通常材料の残りが0、または丸めで減耗0|全額0は非表示|
|貸倒引当金 allow|カード売上0、または1％の丸めが0|全額0は非表示|
|前払保険料 prepaid-ins|保険に入らない|既存whenを維持、全額0も非表示|
|消費税精算 vat-close|税の残高または差額が0|部分0行を除去、全額0は非表示|
|未払費用 accrued|給料0、光熱費0|部分0行を除去、両方0なら非表示|
|翌4月の在庫振戻 stock-back|期末在庫−減耗−評価損が0|全額0は非表示|
|内装・器材の償却、評価損、手数料、法人税と納付|固定の金額が正、法人税は最低7万円、評価損は発生時1.2万円|金額は変えず共通の0円規則を適用|
|開店前の出資・借入・保証金・内装・器材|現行の固定金額は正|金額は変えず共通の0円規則を適用|

表の情報として必要な文字列の説明・割合は保持し、数値0かつ `amt` の行だけを除く。

## まとめ買いの在庫（承認6384794588）

通常の `bulk` の札はふだんの仕入に含まれて使うので、9月・3月のどの結果でも期末の在庫と評価損を増やさない。costOmenで1月に支払った30万円だけを期末の未使用在庫に含め、その一部の評価損をseed別・独立した乱数で判定する（確率0.3、許可範囲0.2〜0.4）。世界の口座を動かさない。

PR #2は `SIMDATA.y1.bulkInventory(S)` で、この小麦の `purchased`（支払額）・`loss`（期末の評価損）・`carrying`（評価損後の持越額）を読み出せる。Sを書き換えない純粋な読み出しで、通常の材料の在庫と減耗は含めない。

通常材料の在庫15,000円・減耗750円の検査例：

|道筋|stock|減耗|評価損|stock-back|
|---|---:|---:|---:|---:|
|まとめ買いなし|15,000|750|0|14,250|
|bulk t5 cheap/spoil/space（各結果）|15,000|750|0|14,250|
|bulk t11 cheap/spoil/space（各結果）|15,000|750|0|14,250|
|costOmen 湿気なし|315,000|750|0|314,250|
|costOmen 湿気あり|315,000|750|12,000|302,250|

各道筋でstock−減耗−評価損＝stock-back、全額非負を検査した。通常bulkの結果別書類と口座照合は実装・検査中。

## 通常bulkの結果別書類（承認6384829024・6384886194）

選択した月は書類を出さず、翌月に `res.carried` で確定した結果の書類を1枚だけ出す。cheapは普通預金15,000／仕入15,000、spoilは仕入20,000／普通預金20,000、spaceは支払家賃8,000／普通預金8,000。同じ月の月報の自動記帳から、そのbulk分だけを除く。他の札の合計は保持する。

3結果をworldの実際の抽選・月次計算でも作り、書類による口座の増減とworldの増減（+15,000・−20,000・−8,000）が各0円差で一致すること、書類と自動記帳の除外が同じ翌月になることを検査した。修正前も月報の自動記帳だけで現金の増減は一致していたが、判断月に常に非現金の戻し15,000円の書類が出て、結果と異なる勘定・時期で費用と買掛金を動かしていた。

t=11で選んだ結果は、決算で先に抽選しない。このブランチの1年目＋翌4月には次の経営月のplanがないため、その結果は未確定のまま。PR #2の2年目の月次処理へ接続した後に、4月の結果と書類を取りまとめ役が確認する。

通常bulk以外で、正のお金が月報の `普通預金／売上` という一括記帳に入りうる札は5本。負の札と合算されて最終fxが負なら、その月は消耗品費として一括記帳される。この扱いは今回変更していない。

|soup（スープを店で炊くか、買うか）|buy/ok +15,000|
