# ホームの試作（T1）

`docs/CODEX-TASK-proto-home.md` と更新後の `docs/PROTO-SPEC-home.md`（ceed538）に従う、同じ1か月を6版×帳簿の遅れ0/1で比べる独立した試作。ゲーム本体とは接続しない。

## 開き方

`index.html` をファイルとして直接開く。サーバーやビルドは不要。通常のscriptをmodel・scenario・homeの順に読み、グローバルは `BOKI_HOME` の1つにまとめている。URL末尾の `?v=a&stale=0&lock=1` で試遊条件を指定できる。HTTPで配信して開く形でも動く。

|v|ホーム|
|---|---|
|a|数なし、店の絵と次の書類|
|b1|1億への線と見込みの日付|
|b2|1億への線と期限からの逆算|
|c|売上・今月のもうけ（純利益）・それぞれの先月比、その下にお金の増え|
|d|口座のお金・借入金・手もとに残るお金・月・方針の帯|
|e|画面の6割の店の絵に、お金1つと日付を重ねる|

- `stale=0`（既定）：書類が1枚ずつ届く。数は記帳した分まで。古い印なし。
- `stale=1`：5月7日・14日・21日に2枚ずつ届く。未記帳があれば数・線を薄くし、最後に記帳した日付と残り枚数の印を出す。aは残り枚数の印だけ。
- `lock=1`：版とstaleの切り替えを隠す。比較試遊と撮影ではこの指定を使う。

## 共通の1か月

1年目の5月。月初は普通預金300万円・現金10万円・借入金0円。同じ6枚を同じ順で記帳し、3枚目の後にチラシ2万円（現金）の判断が出る。数を確認してから判断できる。未回答なら4枚目の前に判断の札が出る。6枚を終えると「5月31日、今月を締める」から4択2問へ進む。

stale=1では、最初の印は「4月30日の帳簿まで」。#2・#4の後は印なしのホームを見せ、「5月14日へ進む」「5月21日へ進む」の札を1回押すと次の2枚が届く。最後は5月31日の締めになる。確認の窓は挟まない。

目標はネットキャッシュ（現金＋普通預金−借入金）1億円、120か月。経過1か月・残り119か月。b1のペースは今月初からのネットキャッシュの増え方、未記帳の間だけ先月の4万円を使う。0以下なら到達日を出さない。b2は残額を119か月で割る。月数・必要月額は切り上げる。式は `model.js` のコメント、仮の前提は線を押すと読める。

純利益は売上−仕入−家賃−給料−広告宣伝費。備品は持ち物なので引かない。月末は売上21万円（先月比＋3万円）、純利益3万円（先月比−1万円、チラシあり1万円・−3万円）、口座292万円。お金の増えは−2.5万円（チラシあり−4.5万円）、手もとに残るお金は307.5万円（あり305.5万円）。掛け仕入とカード売上で現金を動かさない。

4択の間だけホームの数と絵を隠し、背景も不透明にする。答え終えるとホームへ戻る。数の詳細と書類の机の重ねは半透明のまま。

## 記録

localStorageの `boki2.proto.home.v1` に保存する。追加仕様の試遊は `scenarioVersion:2` とstaleの値で区別する。古い試作の記録も消さず、現在の仕様の新しい試遊を始める。「もう一度遊ぶ」でも古い記録を残す。再読み込みで途中から再開でき、保存不能の端末でもメモリー上の記録を書き出せる。

「記録を書き出す」で全試遊のJSONを表示し、選択・コピーまたはファイル保存できる。

- 版・stale・開始/締め時刻・締めまでのミリ秒（4択の回答時間を含めない）。
- ホームを開いた回数、数・線・印を押した回数、判断。
- 4択の回答・正誤・選んだ位置（0始まり）・実際に出した選択肢の並び `quizOrder`。記録idと問いを種に並べ替え、再読み込みでも同じ並び。
- 印が見えていた時間 `staleVisibleMs`、印が出ている間のホームの回数 `staleHomeOpens`。書類/詳細の窓・隠したタブ・閉じている時間・印が画面外の時間は加えない。
- 2枚ごとの届いた時刻・記帳完了時刻・次へ進んだ時刻 `batchTimings`。「届いてから進むまで」と「印が消えてから進むまで」のミリ秒を残す。
- 操作の時刻の列。

外部へ通信しない。CSPの `connect-src 'none'` でも禁止する。ゲーム本体の保存や計算とは共有しない。

## 自動検査と画面写真

PlaywrightとChromiumを使える環境で `node boki2/proto/home/check/run.cjs` を実行する。本体の依存ではない。検査時だけローカルHTTPサーバーを起動し、終われば閉じる。Chromiumの既定は `/usr/bin/chromium`、別のパスは `CHROMIUM_PATH` で指定する。管理のブラウザがファイルを直接開くことを禁止している環境では、`FILE_CHROMIUM_PATH` に検査用Chromiumのパスを指定して、fileの検査だけ別のブラウザで実行できる。管理設定は変更しない。

- `check/results.json`：6版×stale 0/1×2画面サイズ×チラシ2択＝48通りの打ち手と、実測の生データ。
- `check/measurements.md`：24条件の月初・月末、計48行。stale=1の月初は5月7日に2枚届き、印が出ている状態。
- `check/index.html`：36枚の目録。6版×2幅×月初/月末の24枚（stale=0、チラシあり）、6版×2幅の未記帳の印の12枚（stale=1）。
- `check/record-*.json`：実際の書き出し例。自動操作の記録であり、人の試遊データではない。
- `check/prototype.log`：自動検査の出力。
- `check/regression/`：既存ゲームの必須検査の出力と終了コード。

大きさはDOMの `getBoundingClientRect()` と `getComputedStyle()` で測る。字は見える文字ノード、押す所は見えるボタン・リンク・入力欄。幅と高さを両方判定し、書類・判断・印の説明・4択・書き出しの窓も検査する。店の絵は `.stage` の領域の高さ。dの帯は店名ヘッダーも含む画面上端〜帯の下端。ほかの版の数はその領域だけ（eは絵に重ねた領域）を測る。

## やっていないこと

- 人による比較試遊と、学習効果・楽しさ・続けたさの測定。採用する版を決めていない。
- 新しいMobbin検索や外部資料の取得。指定された設計書を利用した。
- 本番ゲームへの接続、120か月の経営、自由な仕訳入力、町・帳簿・成長の各画面。机は正しい仕訳の確認と記帳だけ。
- 絵の本制作。全版で同じ仮のSVGを使い、描き込みの差で比較が歪まないようにした。
- 実機のタッチ操作、Safari・Firefoxの検査。Chromiumで確認する。`file://` でe・stale=1を直接開き、Chromium 143でエラー0・書類の表示・記帳と次の日への移動を確認済み。HTTPの48通りは通常のChromiumで再実行した。
