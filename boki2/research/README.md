# 情報収集の証跡

開発のために外部サイトから集めた資料について、「何を・いつ・規約を守って取ったか」「本当に中身まで読んだか」「転載していないか」を、あとから機械で確かめるための場所。オーナーの要望（2026-10-20）で作った。

## しくみ

| ファイル | 役割 | git |
|---|---|---|
| `sources.json` | 台帳。取得元ごとの利用規約の確認結果（ok / gray / no-automation / unchecked）、集める対象（expected）、対象外にしたものとその理由（excluded）、一覧ページから全件を拾うパターン | 入れる |
| `ledger.jsonl`・`ledger-pending/*.jsonl` | 取得記録。1回の取得ごとに1行（時刻・URL・状態・サイズ・sha256・保存先・取得方法）。後から登録したものは `via: backfill` | 入れる |
| `notes/<src>/<coll>/<doc>.md` | 読了ノート。sha256（どのファイルを読んだか）、anchors（本文にそのまま出る語句）と、自分の言葉で書いた分析 | 入れる |
| `raw/` | 原文（HTML・PDF）。照合のためだけに置く | **入れない**（著作物のため） |
| `STATUS.md` | 検査結果の集計。`--write` で生成 | 入れる |

## 取得する

**取得記録（ledger.jsonl・ledger-pending/）は追記だけ。消したり書き換えたりしない**。中身のない殻しか取れなかった・取れなかったときは、消さずに `--skip "理由"` で「読まない」記録を足す（読了ノートは要らない）。

```
node boki2/tools/research-fetch.js --src kentei --coll kouhyou2 --doc 139 --part pdf --url <URL>
node boki2/tools/research-fetch.js --src … --coll … --doc … --skip "取らない理由"
```
台帳にない取得元・規約未確認・自動取得禁止の取得元は取得を拒否し、同じホストへのアクセス間隔（`min_interval_s`）を守る。

## 検査する

```
node boki2/tools/research-check.js            # 検査（エラーがあれば終了コード1）
node boki2/tools/research-check.js --write    # STATUS.md を更新（コミットする）
node boki2/tools/research-check.js --spot 5   # 無作為に5本、anchors が原文のどこに出るかを表示（人の目での抜き打ち）
```

見つけるもの：
- **取りこぼし**：一覧ページに載っているのに、対象にも対象外（理由つき）にも入っていない／対象なのに取得記録がない
- **読んでいない**：取得したのに読了ノートがない
- **タイトルだけ・拾い読み**：anchors が原文に出てこない／一覧やタイトルに出ない固有の語が3つ未満／`read: full` なのに文書の前・中・後ろの全区間から anchors が出ていない
- **別物を読んだ**：ノートの sha256 が取得記録と一致しない
- **転載**：ノート本文に原文と30字以上そのまま一致する箇所がある
- **規約違反**：規約未確認のまま取得／自動取得禁止の取得元を自動で取得／アクセス間隔が短すぎる
- **出典の空振り**：docs の `[[src:coll:doc]]` が存在しないノートを指している
- 不良取得：極端に小さい、ログイン画面を取っている

## 読了ノートの書き方

```
---
src: kentei
coll: kouhyou2
doc: 139
file: 139-02-kouhyou.pdf
sha256: <取得したファイルの sha256>
read: full            # 一部だけなら partial と pages: を書く（嘘の full より正直な partial）
anchors: [本文にそのまま出る語句を5〜8個、半角カンマ区切り（桁区切りのカンマを含むなら JSON の配列で書く）。うち3個以上はその文書に固有の8〜20字の断片。前・中・後ろから]
---
自分の言葉の分析（原文の長い引用はしない）
```
docs で資料に触れるときは `[[kentei:kouhyou2:139]]` の形で出典を付ける。

## 限界（正直に）
- anchors は「その文書を開いて語句を拾った」ことの証拠で、「理解した」ことの証明ではない。だから `--spot` による人の目での抜き打ちと、ノートの中身（分析の具体性）をレビューする
- `raw/` はクラウド環境が作り直されると消える。消えたあとは sha256 と記録だけが残り、照合は「照合不能」として数える（合格扱いにはしない）
- `via: relocate` は、取得済みの原文を正しい置き場所（raw/）へ移した記録（取得ではないのでアクセス間隔の検査から除く）
- `via: backfill` の記録は、取得したときの記録ではなく、後からファイルと作業ログから復元したもの

## 規約で止まらないために（2026-10-22 オーナーの要望で改めた）

- **判定は一度だけ**：サイトごとの規約・robots.txt の確認結果は `site-policy.json` に残り、同じホストは誰も確認し直さない（research-fetch が自動で引く）
- **判定の目安**：規約に自動取得・スクレイピング・bot の**明示的な禁止**がある → `no-automation`。明示がない・規約ページが開けないが robots.txt が許している → `gray` として取得してよい（少数・間隔を守る）
- **禁止でも作業は止めない**：`no-automation` のページは research-fetch が「取らない」記録と `WANTED.md` への追記だけして終了コード3を返す。調べる側は二次資料・別の公式窓口で続け、オーナーに逐一確認しない。オーナーへの依頼は作業の区切りで `WANTED.md` をまとめて渡す

## オーナーが開いた資料

人がブラウザでふつうに閲覧したものは自動取得ではないので取り込んでよい（`via: owner`）。渡し方はどれでもよい：
1. **チャットに貼る**：ページの本文をコピーして貼る（スマホならこれが一番楽）。URL も一緒に
2. **Google ドライブ**：ページを PDF で保存（共有→プリント→PDF、または「PDFとして保存」）して、ドライブの好きなフォルダに入れ、フォルダ名を伝える
3. **ファイル添付**：HTML／PDF をそのまま送る

受け取ったら `node boki2/tools/research-import.js --src … --coll … --doc … --url <元のURL> --file <ファイル>` で登録し（貼られた本文は .txt に保存してから）、通常どおり読了ノートを書く。転載の検査も通常どおり。

## 外部への通信は research-fetch だけ（2026-10-22）

検索は WebSearch か、規約と robots を確かめた検索窓口（国会図書館サーチの API など）を research-fetch で取る。curl・WebFetch・各サイトの API を research-fetch の外で直接呼ばない（取得記録に残らず、規約の判定も通らない）。起きてしまったら research/INCIDENTS.md に書く。


## robots.txt は道具が確かめる（2026-10-22）
research-fetch は取得のたびに、そのホストの robots.txt（1日だけ research/raw/.robots/ に残す）で、パスが User-agent: * に禁じられていないかを確かめる。禁じられていれば取らずに終了コード3で WANTED.md に回す。人が robots.txt を読んで判断しなくてよい（読み落としで IRDB の /search を取った件。INCIDENTS.md）。
