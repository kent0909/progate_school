Micropolis（初代 SimCity の、EA の許諾で公開された C のソース。Don Hopkins が管理する GitHub の micropolis-activity）の `src/sim/s_sim.c`。SimCity の需要（R・C・I の弁）の一次資料（コード）。

需要の計算（自分の言葉で）：
- **住宅の需要**：働き口（商業と工業の人口の和）÷住民（住宅の人口÷8）＝雇用の比。比が1を越えると移り住む人が増え、1を下回ると出ていく。出生は住民の2%。これで「来月の住民の見込み」を出し、今の住民との比を取る。
- **商業の需要**：町の中の市場（住民＋商業＋工業の和÷3.7）× 働き手の比（住民÷働き口、0〜1.3に切る）。
- **工業の需要**：工業の人口 × 働き手の比 × **町の外の市場**（難しさで1.2・1.1・0.98）。
- それぞれ「見込み÷今」の比（上限2）を、(比−1)×600 に**税率と難しさの表**（税が低いほど＋200、高いほど最大−600）を足して、弁の変化の速さにする。弁は住宅±2000・商業と工業±1500で頭打ち。
- **上限の蓋**：住宅は競技場、商業は空港、工業は港がないと、一定の規模以上で弁が0に止まる（コメント「Stad, Prt, Airprt」）。

ゲームへの意味（分析）：
1. SimCity の需要は**互いに頼り合う3つの需要の循環**：住宅が増える→働き手が増える→商業・工業が伸びる→働き口が増える→住宅が伸びる。どれか1つだけ増やすと、他が足りずに比が崩れて止まる。だから「どこを次に伸ばすか」が毎回の判断になり、**最適の手が町の状態で動く**（独立な掛け算の式では起きない性質）。
2. 税は3つ全部に同じ表で効く板挟み（税を上げると財源は増えるが全需要が落ちる）。利用者の声でも税率のジレンマが褒められている（[[web:simgames:r6-sd-applion-simcitybuildit]]）。
3. **規模の蓋＝新しい判断の層の入口**：ある規模で需要が止まり、競技場・空港・港という大きな投資をしないと先へ進めない。成長の段で新しい判断が開く仕組みの最小の形。ラーメンなら「本部」「製麺所」「セントラルキッチン」を作らないと店数・客数が頭打ちになる、という段の作りに写せる。
4. 外の市場（工業）だけは難しさで決まる外からの値で、町の外の景気の役。DESIGN-RAMEN の景気の年の揺れに当たる。
